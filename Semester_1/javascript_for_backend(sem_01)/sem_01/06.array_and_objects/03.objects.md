# Objects in JavaScript
---

Objects are one of the most important concepts in JavaScript.  
Nearly everything in JavaScript is built around objects. Understanding objects helps you store related data together, model real-world things, and work with data coming from APIs or databases.

---

### 1. What Is an Object?

An **object** is a collection of **key–value pairs**.  
Each key is called a **property**, and each value can be:

- Number  
- String  
- Boolean  
- Array  
- Another object  
- Function (called a method)

Objects allow you to group related data and behavior together so you can represent real-world things clearly.

**Simple Example:**

```javascript
const student = {
    name: "Arjun",
    age: 18,
    course: "CSE"
};
```

**Complete Example (covers all value types):**

```javascript
const person = {
    name: "John",                    // String
    age: 25,                         // Number
    isStudent: true,                 // Boolean
    hobbies: ["reading", "coding"],  // Array
    address: {                       // Nested object
        city: "Delhi",
        pincode: 110001
    },
    greet: function() {              // Method (function)
        return "Hello, " + this.name;
    }
};

console.log(person.name);        // John
console.log(person.hobbies[0]);  // reading
console.log(person.address.city);// Delhi
console.log(person.greet());     // Hello, John
```

### 2. Why Do We Need Objects?

Objects help in representing real-world things such as:

- **Students** → `{ name: "Priya", age: 19, course: "CSE" }`  
- **Books** → `{ title: "JavaScript Basics", author: "Alice", pages: 220 }`  
- **Employees** → `{ name: "Rahul", id: 101, department: "IT" }`  
- **Products** → `{ name: "Laptop", price: 55000, inStock: true }`  
- **Cars** → `{ brand: "Honda", model: "City", year: 2022 }`  
- **API data** → Data received from a server is almost always in the form of objects or arrays of objects.

They bundle related information together instead of keeping many separate variables.

**Without objects:**

```javascript
let name = "Michael";
let age = 18;
let marks = 88;
```

**With an object (cleaner and organized):**

```javascript
const student = {
    name: "Michael",
    age: 18,
    marks: 88
};
```

### 3. Creating Objects

There are three common ways to create objects.

#### Method 1: Object Literal (most common and recommended)

```javascript
const student = {
    name: "Alice",
    age: 18,
    marks: 92
};
```

#### Method 2: Using `new Object()`

```javascript
const student = new Object();
student.name = "Rahul";
student.age = 19;
student.marks = 85;
```

#### Method 3: Constructor Function

```javascript
function Student(name, age, marks) {
    this.name = name;
    this.age = age;
    this.marks = marks;
}

const student1 = new Student("Priya", 18, 90);
const student2 = new Student("John", 19, 87);

console.log(student1);
console.log(student2);
```

**Important Points:**  
- Object literal is the simplest and most readable way for one object.  
- `new Object()` is less common today but still works.  
- Constructor functions are useful when you need to create many similar objects.

### 4. Accessing Object Properties

We access properties in two ways. Let’s use this student object:

```javascript
const student = {
    name: "William",
    age: 18,
    "favorite subject": "Mathematics"
};
```

#### 1. Dot notation (simple and preferred when the key is a valid identifier)

```javascript
console.log(student.name);   // William
console.log(student.age);    // 18
```

#### 2. Bracket notation (required when the key has spaces or comes from a variable)

```javascript
console.log(student["age"]);                 // 18
console.log(student["favorite subject"]);    // Mathematics

// When the key comes from a variable
const key = "name";
console.log(student[key]);                   // William
```

### 9. Methods & the `this` Keyword

A function stored inside an object is called a **method**.  
Inside a method, the keyword `this` refers to the current object that owns the method.

```javascript
const student = {
    name: "Kavya",
    marks: 90,
    greet: function() {
        return "Hello, " + this.name;
    },
    getStatus: function() {
        if (this.marks >= 80) {
            return this.name + " is doing great!";
        }
        return this.name + " needs more practice.";
    }
};

console.log(student.greet());      // Hello, Kavya
console.log(student.getStatus());  // Kavya is doing great!
```

**Key Points about `this`:**  
- `this` always points to the object that is calling the method.  
- If you take the method out of the object and call it alone, `this` may no longer point to the original object.

### 10. Looping Through an Object

You can loop through the properties of an object using a `for...in` loop.

```javascript
const student = {
    name: "Karan",
    age: 18,
    course: "CSE"
};

// Using for...in
for (let key in student) {
    console.log(key + ":", student[key]);
}
```

### 11. Nested Objects

Objects can contain other objects. This is very common when modeling real data.

```javascript
const student = {
    name: "Robert",
    address: {
        city: "Mumbai",
        pincode: 400001
    }
};

console.log(student.address.city);   // Mumbai

// Looping through the nested object
for (let key in student.address) {
    console.log(key + ":", student.address[key]);
}
```

### 12. Array of Objects (Very Important)

Arrays of objects are used everywhere: databases, APIs, servers, and front-end applications.

```javascript
const students = [
    { name: "Neha", marks: 85 },
    { name: "Raj", marks: 90 },
    { name: "Amit", marks: 92 }
];

for (let i = 0; i < students.length; i++) {
    console.log(students[i].name, students[i].marks);
}
```

This pattern is the foundation for working with real data from servers.

### 13. Objects vs Arrays

| Feature   | Object                          | Array                          |
|-----------|---------------------------------|--------------------------------|
| Structure | key–value pairs                 | ordered list                   |
| Access    | by key                          | by index                       |
| Best for  | representing **entities**       | storing **lists**              |

**What is an entity?**  
An entity is a single real-world thing that has its own properties (a student, a book, a car, a product).

**What is a list?**  
A list is a collection of multiple items of the same kind (a list of students, a list of products, a list of scores).

Use an **object** when you want to describe one entity.  
Use an **array** when you want to store multiple entities or values.

### 14. Checking Properties & Getting Keys / Values

Sometimes you need to check whether a property exists or get all keys and values of an object.

```javascript
const student = {
    name: "Ananya",
    age: 18,
    course: "CSE"
};

// Check if a property exists
console.log("name" in student);           // true
console.log("marks" in student);          // false

// Get all keys
console.log(Object.keys(student));        // ["name", "age", "course"]

// Get all values
console.log(Object.values(student));      // ["Ananya", 18, "CSE"]

// Get both keys and values as pairs
console.log(Object.entries(student));     
// [["name","Ananya"], ["age",18], ["course","CSE"]]
```

These methods are very useful when you work with data dynamically.

### 16. Common Mistakes Students Make

1. **Using dot notation with a variable**

```javascript
const student = { name: "Rohan" };
const key = "name";

console.log(student.key);   // undefined (wrong)
console.log(student[key]);  // Rohan (correct)
```

2. **Forgetting quotes around string keys that contain spaces**

```javascript
const obj = {
    name: "Lisa",
    "full name": "Lisa Johnson"   // quotes are required
};
```

3. **Relying on the order of properties**

Modern JavaScript engines usually keep the order in which you wrote the properties. However, the language does not guarantee that the order will always stay the same in every situation (especially with older engines or special keys).  

**Simple advice for beginners:**  
Never write logic that depends on properties appearing in a particular order.  

Example of what you should **not** do:

```javascript
const obj = { a: 1, b: 2, c: 3 };
// Do not assume that the first key will always be "a"
```

Instead, always access properties by their exact key name.

4. **Confusing objects with arrays**  
Objects use keys, arrays use numeric indexes.

5. **Forgetting that `this` refers to the object that owns the method**

```javascript
const student = {
    name: "Meera",
    greet: function() {
        return "Hi, I am " + this.name;
    }
};

console.log(student.greet());   // Hi, I am Meera
```
