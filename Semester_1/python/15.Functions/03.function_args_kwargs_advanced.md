# 1. `/` and `*` in Function Parameters

Python lets us control how a caller may pass arguments to a function.

- `/` means parameters before it are **positional-only**.
- `*` means parameters after it are **keyword-only**.
- These symbols are part of the function definition. They do not mean division or multiplication in this context.

## 1.1 Positional-only parameters: `/`

A parameter before `/` must be passed by position. The caller cannot pass it using its parameter name.

```python
def divide(a, b, /):
    return a / b

print(divide(10, 2))  # 5.0
```

This works because `a` and `b` are passed by position.

```python
print(divide(a=10, b=2))
```

This raises a `TypeError`, because `a` and `b` are positional-only.

You can combine positional-only and regular parameters:

```python
def calculate(a, b, /, operation="add"):
    if operation == "add":
        return a + b
    if operation == "multiply":
        return a * b
    return None

print(calculate(3, 4))                 # 7
print(calculate(3, 4, operation="multiply"))  # 12
```

Here, `a` and `b` must be positional. `operation` can be positional or keyword.

## 1.2 Keyword-only parameters: `*`

Parameters written after a bare `*` must be supplied by keyword.

```python
def create_user(name, *, age, city):
    return f"{name}, age {age}, from {city}"

print(create_user("Asha", age=20, city="Pune"))
```

This raises a `TypeError`:

```python
create_user("Asha", 20, "Pune")
```

`age` and `city` are keyword-only, so write their names in the call.

A bare `*` does not collect arguments. It marks the parameters that follow as keyword-only.

## 1.3 Using `/` and `*` together

```python
def book_ticket(source, destination, /, *, passenger, seat="regular"):
    print(source, "to", destination)
    print("Passenger:", passenger)
    print("Seat:", seat)

book_ticket("Pune", "Mumbai", passenger="Asha", seat="window")
book_ticket("Pune", "Mumbai", passenger="Asha")
```

- `source` and `destination` are positional-only.
- `passenger` and `seat` are keyword-only.
- `seat` has a default value, so it is optional.

## 1.4 Parameter order rules

A function definition may contain these kinds of parameters in this order:

1. Positional-only parameters, followed by `/`.
2. Regular parameters.
3. A bare `*` or `*args`.
4. Keyword-only parameters.
5. `**kwargs`, if used.

Example:

```python
def example(pos_only, /, normal, *args, option=True, **kwargs):
    print(pos_only)
    print(normal)
    print(args)
    print(option)
    print(kwargs)

example(1, 2, 3, 4, option=False, color="blue")
```

Output:

```text
1
2
(3, 4)
False
{'color': 'blue'}
```

**Common mistake:** A parameter cannot appear before `/` and also be declared after it. Follow Python's parameter order rules.

# 2. `*args`

`*args` lets a function accept any number of extra positional arguments.

The name `args` is a convention. The `*` is what matters; another valid name could be used.

## 2.1 Basic example

```python
def add(*args):
    print(args)
    print(type(args))

add(10, 20, 30)
```

Output:

```text
(10, 20, 30)
<class 'tuple'>
```

Python gathers the extra positional arguments into a tuple.

## 2.2 Using `*args` in calculations

```python
def add_all(*args):
    total = 0

    for number in args:
        total += number

    return total

print(add_all(10, 20))          # 30
print(add_all(1, 2, 3, 4))      # 10
print(add_all())                # 0
```

An empty `*args` produces an empty tuple, so the function can handle zero extra arguments if its code supports that case.

## 2.3 Regular parameters with `*args`

```python
def introduce(name, *hobbies):
    print("Name:", name)
    print("Hobbies:", hobbies)

introduce("Asha", "reading", "cricket", "music")
```

Output:

```text
Name: Asha
Hobbies: ('reading', 'cricket', 'music')
```

The first positional argument fills `name`. Remaining positional arguments go into `hobbies`.

## 2.4 `*args` is not a list

```python
def show(*args):
    print(args[0])

show("red", "green")  # red
```

`args` is a tuple, not a list. It supports indexing and iteration, but it cannot be modified in place like a list.

```python
def change(*args):
    args[0] = 99  # TypeError: tuple does not support item assignment

change(1, 2)
```

## 2.5 Common `*args` mistake

```python
def show(name, *args):
    print(name, args)

show("Asha", ["reading", "music"])
```

Output:

```text
Asha (['reading', 'music'],)
```

The list is one argument, so `args` contains a one-item tuple holding that list. To pass each list item as a separate positional argument, use unpacking:

```python
hobbies = ["reading", "music"]
show("Asha", *hobbies)
# Asha ('reading', 'music')
```

# 3. `**kwargs`

`**kwargs` lets a function accept any number of extra keyword arguments.

The name `kwargs` is a convention. The double asterisks collect extra named arguments into a dictionary.

## 3.1 Basic example

```python
def show_details(**kwargs):
    print(kwargs)
    print(type(kwargs))

show_details(name="Asha", age=20, city="Pune")
```

Output:

```text
{'name': 'Asha', 'age': 20, 'city': 'Pune'}
<class 'dict'>
```

## 3.2 Reading values from `kwargs`

```python
def show_details(**kwargs):
    for key, value in kwargs.items():
        print(key, "=", value)

show_details(name="Asha", age=20)
```

Output:

```text
name = Asha
age = 20
```

You can also use dictionary methods:

```python
def greet(**kwargs):
    name = kwargs.get("name", "Guest")
    print("Hello,", name)

greet(name="Asha")  # Hello, Asha
greet()             # Hello, Guest
```

Using `.get()` avoids a `KeyError` when the key is missing.

## 3.3 Regular parameters with `**kwargs`

```python
def create_profile(name, **details):
    print("Name:", name)
    print("Other details:", details)

create_profile("Asha", age=20, city="Pune")
```

Output:

```text
Name: Asha
Other details: {'age': 20, 'city': 'Pune'}
```

The named parameter `name` receives its value. Other keyword arguments are gathered in `details`.

## 3.4 Common `**kwargs` mistakes

This call is invalid because `name` is supplied twice:

```python
def greet(name, **kwargs):
    print(name, kwargs)

greet("Asha", name="Ravi")
```

It raises a `TypeError` for multiple values for `name`.

This call is also invalid:

```python
def greet(**kwargs):
    print(kwargs)

greet({"name": "Asha"})
```

The dictionary is passed as one positional argument, but the function accepts only keyword arguments. Use either:

```python
greet(name="Asha")
```

or unpack the dictionary:

```python
details = {"name": "Asha", "age": 20}
greet(**details)
```

# 4. Using `*args` and `**kwargs` Together

A common function signature uses regular parameters, then `*args`, keyword-only parameters, and finally `**kwargs`.

```python
def demo(name, *args, active=True, **kwargs):
    print("Name:", name)
    print("Extra positional:", args)
    print("Active:", active)
    print("Extra keyword:", kwargs)

demo("Asha", 10, 20, active=False, city="Pune", age=20)
```

Output:

```text
Name: Asha
Extra positional: (10, 20)
Active: False
Extra keyword: {'city': 'Pune', 'age': 20}
```

Remember:

- `name` receives the first positional argument.
- `*args` collects remaining positional arguments into a tuple.
- `active` is keyword-only here because it comes after `*args`.
- `**kwargs` collects remaining keyword arguments into a dictionary.

# 5. Argument Unpacking: `*` and `**`

Packing and unpacking are related but different:

- **Packing:** A function gathers many arguments into a tuple or dictionary using `*args` or `**kwargs`.
- **Unpacking:** A caller expands a collection into separate arguments using `*` or `**`.

## 5.1 Unpacking a list or tuple with `*`

```python
def add(a, b, c):
    return a + b + c

numbers = [10, 20, 30]
print(add(*numbers))  # 60
```

`add(*numbers)` is equivalent to:

```python
add(10, 20, 30)
```

The iterable's items are passed as separate positional arguments.

A tuple works too:

```python
values = (2, 3, 4)
print(add(*values))  # 9
```

The number of unpacked items must match the function's accepted positional arguments, unless the function supports a different number.

```python
add(*[10, 20])  # TypeError: missing an argument
add(*[10, 20, 30, 40])  # TypeError: too many arguments
```

## 5.2 Unpacking a dictionary with `**`

Dictionary keys must match parameter names, unless the function accepts extra keywords through `**kwargs`.

```python
def introduce(name, age):
    print(f"{name} is {age} years old.")

person = {"name": "Asha", "age": 20}
introduce(**person)
```

This is equivalent to:

```python
introduce(name="Asha", age=20)
```

A key that does not match a parameter causes a `TypeError` if the function has no `**kwargs` to collect it:

```python
introduce(**{"name": "Asha", "city": "Pune"})
```

This call is missing `age` and includes an unexpected `city` keyword.

## 5.3 Combining positional and dictionary unpacking

```python
def describe(name, age, city):
    print(name, age, city)

person = {"age": 20, "city": "Pune"}
describe("Asha", **person)
```

Output:

```text
Asha 20 Pune
```

## 5.4 Unpacking a list of arguments and a dictionary of options

```python
def display(name, age, city="Unknown"):
    print(name, age, city)

args = ["Asha", 20]
options = {"city": "Pune"}

display(*args, **options)
# Asha 20 Pune
```

Be careful not to provide the same parameter more than once:

```python
display("Asha", 20, **{"age": 21})
```

This raises a `TypeError` because `age` receives two values.

## 5.5 Unpacking inside a list or tuple

The `*` operator can also expand an iterable when creating a list or tuple.

```python
first = [1, 2]
second = [3, 4]

combined = [*first, *second]
print(combined)  # [1, 2, 3, 4]
```

```python
values = (1, 2)
combined = (*values, 3, 4)
print(combined)  # (1, 2, 3, 4)
```

## 5.6 Merging dictionaries with `**`

```python
defaults = {"theme": "light", "language": "en"}
custom = {"theme": "dark"}

settings = {**defaults, **custom}
print(settings)
# {'theme': 'dark', 'language': 'en'}
```

If keys repeat, the value from the later unpacked dictionary wins.

## 5.7 Unpacking strings and other iterables

`*` can unpack any iterable, not just lists and tuples.

```python
def show_letters(a, b, c):
    print(a, b, c)

show_letters(*"cat")  # c a t
```

This works because a string is iterable. But a string with the wrong number of characters will cause an argument-count error.

**Important:** `*` and `**` are context-dependent. In a function definition they collect arguments; in a function call they unpack arguments.

# 6. Docstrings

A **docstring** is a string placed at the start of a module, function, class, or method to explain what it does.

Docstrings are not comments. Python stores them in the object's `__doc__` attribute, and tools can use them to show documentation.

## 6.1 Writing a docstring

```python
def square(number):
    """Return the square of a number."""
    return number * number

print(square(5))       # 25
print(square.__doc__)  # Return the square of a number.
```

Use triple quotes for docstrings. A one-line docstring should briefly describe the purpose.

## 6.2 Multi-line docstrings

```python
def calculate_area(length, width):
    """
    Calculate the area of a rectangle.

    Args:
        length: The rectangle's length.
        width: The rectangle's width.

    Returns:
        The area of the rectangle.
    """
    return length * width
```

The text labels inside this docstring are documentation for people and tools. Python does not automatically validate that the description matches the code.

## 6.3 Docstring vs comment

```python
def multiply(a, b):
    """Return the product of two numbers."""
    # Multiply the two values.
    return a * b
```

- The docstring describes the function and can be accessed through `multiply.__doc__`.
- The comment helps explain the code to someone reading the source.
- Neither one changes how multiplication works.

## 6.4 Viewing help

```python
help(calculate_area)
```

Python displays the function's documentation and signature when available. In an interactive Python shell or notebook, this is useful for learning how a function works.

## 6.5 Docstring best practices

- Start with a short summary of the function's purpose.
- Document parameters, return values, and important exceptions when useful.
- Describe behavior and requirements, not every obvious line of code.
- Keep the docstring accurate when code changes.
- Use consistent formatting across a project.

# 7. Type Hints

Type hints, also called type annotations, indicate the kinds of values expected for parameters and return values.

They help readers, editors, linters, and static type checkers. **Python does not normally enforce type hints at runtime.**

## 7.1 Basic parameter and return hints

```python
def add(a: int, b: int) -> int:
    return a + b

result = add(2, 3)
print(result)  # 5
```

- `a: int` suggests that `a` should be an integer.
- `b: int` suggests that `b` should be an integer.
- `-> int` suggests that the function returns an integer.

These annotations do not automatically stop someone from passing a different type:

```python
print(add("Hello, ", "Python"))
# Hello, Python
```

Python executes this call even though the arguments do not match the hints.

## 7.2 Common type hints

| Type hint | Meaning |
|---|---|
| `int` | Integer |
| `float` | Floating-point number |
| `str` | String |
| `bool` | Boolean |
| `None` | No meaningful return value |
| `list[int]` | List of integers |
| `tuple[str, int]` | A two-item tuple: string, then integer |
| `dict[str, int]` | Dictionary with string keys and integer values |
| `int \| float` | Either an integer or a float |
| `str \| None` | A string or `None` |

Built-in collection annotations such as `list[int]` work in Python 3.9 and later. The union syntax `int | float` works in Python 3.10 and later.

## 7.3 Type hints for collections

```python
def total(numbers: list[int]) -> int:
    return sum(numbers)

print(total([1, 2, 3]))  # 6
```

The hint communicates that the function expects a list of integers. It does not automatically check each list item.

## 7.4 Type hints for `*args` and `**kwargs`

For `*args`, annotate the type of each extra positional value:

```python
def total(*numbers: int) -> int:
    return sum(numbers)

print(total(1, 2, 3))  # 6
```

For `**kwargs`, annotate the type of each keyword value:

```python
def show_scores(**scores: int) -> None:
    print(scores)

show_scores(math=90, science=85)
```

Here, `scores` is a dictionary of string keys and integer values. The annotation does not enforce the types at runtime.

## 7.5 Hinting a function that returns nothing useful

```python
def greet(name: str) -> None:
    print(f"Hello, {name}")

greet("Asha")
```

`-> None` means the function is intended not to return a useful value. A function without an explicit `return` returns `None` automatically.

## 7.6 Optional values

In modern Python, use a union with `None` to show that a value may be absent:

```python
def find_name(user_id: int) -> str | None:
    if user_id == 1:
        return "Asha"
    return None
```

The function returns a string for one ID and `None` otherwise.

For Python versions before 3.10, you can write `Optional[str]` from `typing`:

```python
from typing import Optional

def find_name(user_id: int) -> Optional[str]:
    if user_id == 1:
        return "Asha"
    return None
```

## 7.7 Type hints and runtime inspection

Annotations are available through `__annotations__`:

```python
def add(a: int, b: int) -> int:
    return a + b

print(add.__annotations__)
# {'a': <class 'int'>, 'b': <class 'int'>, 'return': <class 'int'>}
```

Annotations are metadata. They are not automatic runtime validation.

# 8. Common Mistakes and Edge Cases

## Mistake 1: Using positional arguments after keyword arguments

```python
def greet(name, age):
    print(name, age)

# greet(name="Asha", 20)  # SyntaxError
greet("Asha", age=20)     # Correct
```

Once a keyword argument is used in a call, do not place a regular positional argument after it.

## Mistake 2: Passing duplicate values

```python
def greet(name):
    print(name)

# greet("Asha", name="Ravi")  # TypeError
```

`name` receives two values.

## Mistake 3: Assuming hints validate data

```python
def square(number: int) -> int:
    return number * number

print(square(2.5))  # 6.25; Python does not reject it automatically
```

Use explicit validation or a suitable validation library if runtime checks are required.

## Mistake 4: Incorrect dictionary keys during `**` unpacking

```python
def greet(name):
    print(name)

# greet(**{"username": "Asha"})  # TypeError
greet(**{"name": "Asha"})        # Correct
```

The keys must match the function's parameter names unless extra keywords are accepted.

## Mistake 5: Forgetting that `*` unpacks an iterable

```python
def add(a, b):
    return a + b

numbers = [10, 20]
print(add(numbers[0], numbers[1]))  # 30
print(add(*numbers))                # 30
```

`add(numbers)` would pass one list argument, not two numbers.

# 10. Quick Revision

- `/`: parameters before it are positional-only.
- Bare `*`: parameters after it are keyword-only.
- `*args`: gathers extra positional arguments into a tuple.
- `**kwargs`: gathers extra keyword arguments into a dictionary.
- `*values`: expands an iterable into positional arguments in a call.
- `**mapping`: expands a mapping into keyword arguments in a call.
- A docstring documents a module, class, or function and is available through `__doc__`.
- Type hints document expected types and help development tools; Python does not enforce them by default.
