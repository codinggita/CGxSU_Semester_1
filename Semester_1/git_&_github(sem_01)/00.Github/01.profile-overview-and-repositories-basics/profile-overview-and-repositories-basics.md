# GitHub Profile & Repository Guide

This guide covers the GitHub features discussed in class and explains how to set up a professional GitHub profile and repositories.

---

# GitHub Profile

Your GitHub profile acts as your developer portfolio. Recruiters, mentors, and other developers often visit your profile to understand your skills, projects, and contributions.

To update your profile:

1. Click on your profile picture (top-right corner).
2. Select **Your Profile**.
3. Click **Edit Profile**.
4. Update your profile information.

You can add:

- Name
- Bio
- Company (optional)
- Location
- Website/Portfolio
- Social links
- Profile picture

> **Tip:** Use a professional profile photo and write a short bio describing yourself as a developer.

Example:

```
Full Stack Developer | MERN Stack | JavaScript | React | Node.js
```

# Achievements

GitHub provides **Achievements (Trophies)** that are unlocked when you complete certain activities on GitHub.

You can view them from:

```
Profile → Achievements
```

Some common achievements include:

- Pull Shark (Merged Pull Requests)
- Quickdraw
- Galaxy Brain
- YOLO
- Pair Extraordinaire

These achievements are earned automatically after completing eligible activities.

> Note: You cannot manually add achievements.

# Pinned Repositories

Pinned repositories appear at the top of your profile.

They represent your **best projects** and help recruiters quickly understand your work.

You can pin up to **6 repositories**.

## What should you pin?

- Major projects
- Full Stack applications
- Open Source contributions
- College projects
- Personal portfolio
- Best frontend/backend projects

### Good Example

```
Portfolio Website
E-Commerce Application
Hospital Management System
Chat Application
Expense Tracker
Weather Dashboard
```

Keep your pinned repositories updated whenever you complete a better project.

# Contribution Calendar

The contribution calendar displays your GitHub activity over the last year.

It records activities such as:

- Commits
- Pull Requests
- Issues
- Pull Request Reviews
- Repository creation (some activities)

Each square represents one day.

The darker the green color, the more contributions you made on that day.

### Why is it important?

A consistent contribution graph shows that you actively write code and work on projects.

> Try to contribute regularly instead of making hundreds of commits in one day.

# GitHub Profile README

One of GitHub's best features is the **Profile README**.

It allows you to display a custom introduction on your profile.

## How to create it

1. Create a new repository.
2. The repository name **must be exactly the same as your GitHub username**.

Example:

If your username is

```
johnsmith
```

Create a repository named

```
johnsmith
```

3. Make the repository **Public**.
4. Initialize it with a **README.md**.
5. Create the repository.

GitHub will automatically display the README content at the top of your profile.

---

## What can you include in your Profile README?

- Introduction
- About Me
- Skills
- Tech Stack
- Languages
- Frameworks
- Tools
- Featured Projects
- GitHub Statistics
- Contact Information
- Social Links
- Portfolio Website
- Resume Link
- Fun Facts

- Full Stack Developer

## Tech Stack

- HTML

# Repositories

Repositories are where your project's source code, documentation, and version history are stored.

To create a repository:

1. Click **New Repository**.
2. Choose the repository owner.
3. Enter the repository name.
4. Add a short description.
5. Configure the repository settings.
6. Click **Create Repository**.

---

# Repository Configuration

While creating a repository, you will see several options.

## Repository Visibility

### Public

Anyone on GitHub can view your repository.

Suitable for:

- Portfolio projects
- Open Source projects
- Learning projects

### Private

Only invited collaborators can access the repository.

Suitable for:

- Personal work
- Company projects
- Confidential code

---

## Repository Template

A template repository allows you to reuse an existing project structure.

Instead of cloning and deleting unnecessary files every time, you can generate a new repository from the template.

Useful for:

- React starter projects
- Node.js boilerplates
- Company starter templates

---

## Add a README

Always initialize your repository with a **README.md**.

A README explains:

- What the project is
- Why it was built
- How to install it
- How to run it
- Technologies used
- Project screenshots
- Deployment links

A repository without a README is difficult for others to understand.

---

## Add .gitignore

A `.gitignore` file tells Git which files should **not** be tracked.

Examples:

```
node_modules/
.env
dist/
build/
coverage/
```

Never upload:

- node_modules
- Environment variables (.env)
- Build folders
- Temporary files

---

## Choose a License

A license tells others how they are allowed to use your project.

Common licenses include:

### MIT License

- Most popular
- Free to use
- Easy to modify
- Suitable for most projects

### Apache License 2.0

- Similar to MIT
- Includes patent protection

### GPL License

- Requires modified versions to remain open source.

If you're unsure, **MIT License** is a good choice for most personal projects.

# Repository README

Every project should include a detailed README.

# Finding Repositories

The **Repositories** section on GitHub displays all repositories you own or contribute to.

You can:

- Search repositories
- Sort repositories
- Filter repositories
- View Public repositories
- View Private repositories (only your own)
- Find archived repositories
- Find repositories by language

Common filters include:

- All
- Public
- Private
- Sources
- Forks
- Archived

Searching and filtering repositories becomes useful when working with many projects.

# Best Practices

- Use a professional profile picture.
- Write a meaningful bio.
- Keep your profile updated.
- Pin your best repositories.
- Write a detailed README for every project.
- Add a proper `.gitignore`.
- Choose an appropriate license.
- Keep contributing regularly.
- Maintain a healthy contribution calendar.
- Use clear repository names.
- Keep project descriptions concise and informative.
- Showcase your best work through your Profile README.
