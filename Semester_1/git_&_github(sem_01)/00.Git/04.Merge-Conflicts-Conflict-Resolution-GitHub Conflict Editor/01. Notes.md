
# Merge Conflicts • Conflict Resolution • GitHub Conflict Editor • Cleanup

---

## Learning Goals

- Understand what a merge conflict is and when it happens.
- Create a real conflict using two feature branches.
- Resolve a merge conflict on GitHub (browser editor).
- Understand conflict markers (`<<<<<<<`, `=======`, `>>>>>>>`).
- Choose current changes, incoming changes, or write a manual resolution.
- Clean up remote and local feature branches after merging.
- Update local `main` with `git pull`.

---

## 1. What is a Merge Conflict?

A **merge conflict** happens when Git cannot automatically combine changes from two branches because the **same lines** were modified in different ways.

| Situation | Result |
|-----------|--------|
| Two people change **different files** or **different lines** | Usually merges cleanly |
| Two people change the **same lines** in the same file | **Conflict** – Git asks you to decide |

Git stops and asks **you** to choose the final content.

## 2. Hands-on Example – Shopping List Conflict

We practiced with a shared file `list.txt`.

### Step 1: Setup on main

```bash
# Create / open repository: merge-conflict-practise
# Clone it to your local system

# Create list.txt with:
# Shopping List
# 1. Milk
# 2. Bread
# 3. Butter

git add .
git commit -m "added list.txt"
git push origin main
```

### Step 2: Feature Branch A (change Butter → Cheese)

```bash
git checkout -b feature/shopping_list-A

# Edit list.txt → change "Butter" to "Cheese"

git add .
git commit -m "updated a shopping list in list.txt"
git push -u origin feature/shopping_list-A
```

- Open a **Pull Request** on GitHub (do **not** merge yet).  
- Keep it open for review.

### Step 3: Return to main and create Feature Branch B

```bash
git checkout main

git checkout -b feature/shopping_list-B
# (or: git switch -c feature/shopping_list-B)

# Edit list.txt → change "Butter" to "Cream"

git add .
git commit -m "updated a shopping list of list.txt file by replacing Butter with cream"
git push -u origin feature/shopping_list-B
```

- Open a **second Pull Request** on GitHub.  
- Now you have **two open PRs**.

### Step 4: Merge the first PR (no conflict)

- Merge **feature/shopping_list-A** PR successfully.  
- `main` on GitHub now contains **Cheese**.

### Step 5: Merge the second PR → Conflict appears

- Try to merge **feature/shopping_list-B** PR.  
- GitHub shows a **merge conflict** because:
  - `main` has **Cheese**
  - The PR has **Cream**
  - Both changed the same line.

---

## 3. Resolving the Conflict on GitHub (Browser Editor)

1. Click **Resolve conflicts**.
2. GitHub opens the conflict editor. You will see markers like:

```text
<<<<<<< current
3. Cheese
=======
3. Cream
>>>>>>> incoming
```

| Marker | Meaning |
|--------|---------|
| `<<<<<<< current` (or HEAD) | The version already on the target branch (`main`) |
| `=======` | Separator between the two versions |
| `>>>>>>> incoming` | The version coming from the feature branch |

3. **Decide the final content**:
   - Accept current changes, **or**
   - Accept incoming changes, **or**
   - Keep both, **or**
   - Write a manual final version (in class we put **Butter** back).

4. Delete all conflict markers (`<<<<<<<`, `=======`, `>>>>>>>`).
5. Click **Mark as resolved**.
6. Click **Commit merge** (this creates the conflict-resolution commit).
7. Click **Merge pull request** to finish.

---

## 4. Cleanup After Merging

### Delete remote feature branches
- Use the **Delete branch** button on GitHub after merging, **or**

```bash
git push origin --delete feature/shopping_list-A
git push origin --delete feature/shopping_list-B
```

### Delete local feature branches

```bash
git checkout main

git branch -D feature/shopping_list-A
git branch -D feature/shopping_list-B
```

- `-d` = safe delete (checks if merged)  
- `-D` = force delete

### Update local main

```bash
git pull origin main
```

Now your local `main` has the final resolved shopping list.

---

## 5. Complete Flow Summary

```text
1. main → create list.txt (Milk, Bread, Butter) → push
2. feature/shopping_list-A → Butter → Cheese → push → open PR (keep open)
3. main → feature/shopping_list-B → Butter → Cream → push → open 2nd PR
4. Merge first PR (Cheese) successfully
5. Merge second PR → Conflict
6. Resolve conflict on GitHub (choose final text, remove markers, commit)
7. Merge the second PR
8. Delete remote branches
9. Delete local branches
10. git pull origin main
```

---

## 6. Important Rules

- Conflicts are **normal** when two people edit the same lines.
- Always read the full conflict and decide carefully.
- Never leave conflict markers (`<<<<<<<`, `=======`, `>>>>>>>`) in the final file.
- After resolving on GitHub, still run `git pull` on local `main`.
- Delete feature branches (remote + local) after the PR is merged.
- Prefer resolving simple conflicts on GitHub; for complex ones you can also resolve locally.

---

## 7. Quick Revision Cheat Sheet

| Action | Command / Step |
|--------|----------------|
| Create & switch to new branch | `git checkout -b feature/name` or `git switch -c feature/name` |
| Push feature branch | `git push -u origin feature/name` |
| Open Pull Request | GitHub → Compare & pull request |
| Resolve conflict on GitHub | Resolve conflicts → edit → Mark as resolved → Commit merge |
| Delete remote branch | GitHub button or `git push origin --delete feature/name` |
| Delete local branch | `git branch -D feature/name` |
| Update local main | `git pull origin main` |

---

## Key Takeaway

- **Same line changed in two branches = Conflict**
- **Git asks you to decide** (current / incoming / both / manual)
- **Remove all conflict markers** before finishing
- **Merge → Delete remote branch → Delete local branch → git pull**
