# Type Aliases & Interfaces

Once you know how to type functions and objects inline, you can extract reusable names with `type` and `interface`.

## 1. Type Aliases

A type alias creates a reusable name for any type.

```ts
type UserId = number;

type User = {
	id: UserId;
	name: string;
	email: string;
};

type Add = (a: number, b: number) => number;

type Names = string[];

type Address = {
	city: string;
	country: string;
};

type Employee = {
	id: number;
	name: string;
	address: Address;
};

type Category = {
	name: string;
	children?: Category[];
};
```

| Alias      | Describes                             |
| ---------- | ------------------------------------- |
| `UserId`   | Primitive alias                       |
| `User`     | Object alias                          |
| `Add`      | Function alias                        |
| `Names`    | Array alias                           |
| `Employee` | Nested alias — combines other aliases |
| `Category` | Recursive alias — references itself   |

# 2. Interfaces

An interface defines the structure that an object should follow.

One interface can include required, optional, readonly, and method members:

```ts
interface User {
	readonly id: number;
	name: string;
	email?: string;
	greet(): void;
}

interface Employee {
	department: string;
}

interface Admin extends User {
	permissions: string[];
}

interface Manager extends User, Employee {
	teamSize: number;
}
```

Interfaces also support **declaration merging** — multiple declarations with the same name are combined:

```ts
interface User {
	id: number;
}

interface User {
	name: string;
}

// Result: User has both id and name
```

Callable function shapes can be defined with an interface:

```ts
interface Add {
	(a: number, b: number): number;
}
```

# 3. Type vs Interface

Both describe object shapes, but they differ in capability and use case.

```ts
// type — works for primitives, unions, functions, objects, and more
type ID = string | number;
type Status = "active" | "inactive";

type UserType = {
	id: ID;
	status: Status;
};

// interface — focused on object and class contracts
interface UserInterface {
	id: string;
	status: Status;
}
```

| Feature              | `type`                 | `interface`          |
| -------------------- | ---------------------- | -------------------- |
| Object shapes        | Yes                    | Yes                  |
| Primitives & unions  | Yes                    | No                   |
| Extend/inherit       | Via intersection (`&`) | Via `extends`        |
| Declaration merging  | No                     | Yes                  |
| Callable signatures  | Yes                    | Yes                  |
| Classes implementing | Yes                    | Yes (common pattern) |

**When to use `type`**

- Unions, intersections, mapped types, or tuples
- Primitive aliases (`type ID = string`)
- Utility-type-style transformations

**When to use `interface`**

- Public API / object contracts
- Class implementation (`implements`)
- Library augmentation (declaration merging)

**Rule of thumb:** use `interface` for object shapes you expect to extend or merge; use `type` for everything else.
