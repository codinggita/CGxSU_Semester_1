# Type Composition

## 1. Union Types

A union type allows a value to be one of several types, combined with the `|` operator. The example below covers the common union patterns:

```ts
// primitive union — two types
let orderId: string | number;

// multiple unions — more than two types
let metadata: string | number | boolean;

// literal union — restricted to specific values
type OrderStatus = "pending" | "success" | "error";

// union with objects — different object shapes
type Guest = {
	name: string;
};

type Member = {
	name: string;
	membershipId: string;
};

type Customer = Guest | Member;

// union with functions — different callable signatures
type NotifyHandler = ((message: string) => void) | ((code: number) => void);

let status: OrderStatus = "pending";
let customer: Customer = { name: "Satya", membershipId: "M001" };
```

| Part                                   | Kind            | Notes                                        |
| -------------------------------------- | --------------- | -------------------------------------------- |
| `string \| number`                     | Primitive union | Value can be either type                     |
| `string \| number \| boolean`          | Multiple unions | Union of three or more types                 |
| `"pending" \| "success" \| "error"`    | Literal union   | Only these exact values allowed              |
| `Guest \| Member`                      | Object union    | Access shared properties only until narrowed |
| `(string) => void \| (number) => void` | Function union  | Call must be valid for every member          |

TypeScript requires narrowing before using operations or properties that are not valid for every member of the union.

# 2. Intersection Types

An intersection type creates a new type that includes all properties from all combined types. This is done using the `&` operator.

---

## Object Intersections

```ts
type Person = {
	name: string;
};

type Employee = {
	employeeId: number;
};

type EmployeePerson = Person & Employee;
```

The resulting type contains the properties from both types.

---

## Interface Intersections

```ts
interface User {
	id: number;
}

interface Employee {
	department: string;
}

type UserEmployee = User & Employee;
```

The resulting type contains members from both interfaces.

---

## Intersection Conflicts

When two intersected types define the same property with incompatible types, the resulting property can become impossible to satisfy.

```ts
type A = {
	value: string;
};

type B = {
	value: number;
};

type C = A & B;
```

A value of `C` would need `value` to be both a `string` and a `number`, which cannot normally occur.

This can result in a `never` property or an otherwise unusable type.

---

## Combining Types

Union and intersection types can be combined to create more precise type structures.

```ts
type User = {
	id: number;
};

type Admin = {
	permissions: string[];
};

type Account = User &
	(
		| Admin
		| {
				role: "user";
		  }
	);
```

Parentheses can be used to control how unions and intersections are combined.

---

# 3. Literal Types

Literal types represent specific values rather than broad types.

```ts
let status: "success";
```

The variable can contain only the exact string `"success"`.

---

## String Literals

String literal types represent specific string values.

```ts
type Direction = "left" | "right" | "up" | "down";
```

Only the specified strings are allowed.

---

## Number Literals

Number literal types represent specific numeric values.

```ts
type StatusCode = 200 | 201 | 404 | 500;
```

Only the specified numbers are allowed.

---

## Boolean Literals

Boolean literal types represent the exact values `true` or `false`.

```ts
type Enabled = true;
```

A boolean literal type can also be used in unions.

```ts
type Flag = true | false;
```

---

## Const Assertions

A const assertion uses `as const` to preserve literal values and make properties readonly.

```ts
const config = {
	mode: "production",
	debug: false,
} as const;
```

The values are inferred as literal types instead of being widened to `string` and `boolean`.

`as const` also makes object properties readonly and arrays readonly tuples.

---

## Literal Unions

Literal types can be combined into unions.

```ts
type Role = "admin" | "editor" | "user";
```

This is useful when a value should be restricted to a known set of possible values.

---

# 4. Narrowing

Narrowing is the process of reducing a broader type to a more specific type based on runtime checks or control flow.

TypeScript uses control-flow analysis to determine the most specific type that a value can have at a particular point in the program.

Common narrowing techniques include:

- `typeof`
- `instanceof`
- `in`
- Equality checks
- Truthiness checks
- Assignment
- Discriminated unions

---

## Runtime `typeof` Narrowing

The `typeof` operator can narrow primitive types.

```ts
function format(value: string | number) {
	if (typeof value === "string") {
		return value.toUpperCase();
	}

	return value.toFixed(2);
}
```

TypeScript understands the type of `value` in each branch.

---

## `instanceof`

The `instanceof` operator can narrow values based on their class or constructor.

```ts
function process(value: Date | string) {
	if (value instanceof Date) {
		return value.getTime();
	}

	return value.toUpperCase();
}
```

Inside the first branch, TypeScript knows that `value` is a `Date`.

---

## `in`

The `in` operator can narrow object unions based on the presence of a property.

```ts
type Admin = {
	permissions: string[];
};

type User = {
	name: string;
};

function process(account: Admin | User) {
	if ("permissions" in account) {
		account.permissions;
	}
}
```

The presence of `permissions` allows TypeScript to narrow the type to `Admin`.

---

## Equality Narrowing

Equality checks can narrow types.

```ts
function process(value: string | null) {
	if (value !== null) {
		value.toUpperCase();
	}
}
```

TypeScript knows that `value` is a `string` inside the condition.

Equality checks can also narrow multiple values when their types overlap.

---

## Truthiness Narrowing

TypeScript can narrow values using truthiness checks.

```ts
function print(name: string | undefined) {
	if (name) {
		console.log(name.toUpperCase());
	}
}
```

Inside the condition, `name` is treated as a `string`.

Truthiness checks should be used carefully when valid values such as `0`, `false`, or an empty string need to be distinguished from missing values.

---

## Assignment Narrowing

TypeScript can use assignments to determine the current type of a variable.

```ts
let value: string | number;

value = "hello";
```

After the assignment, TypeScript knows that `value` is a `string` at that point.

---

## Control-Flow Analysis

TypeScript analyzes branches, conditions, returns, assignments, and other control-flow structures to determine the current type of a value.

```ts
function process(value: string | number) {
	if (typeof value === "string") {
		return value.toUpperCase();
	}

	return value.toFixed(2);
}
```

The compiler tracks the narrowed type through the control flow.

---

## Discriminated Unions

A discriminated union is a union of object types that share a common property used to identify the specific member.

```ts
type Result =
	| {
			status: "success";
			data: string;
	  }
	| {
			status: "error";
			message: string;
	  };
```

The `status` property is the discriminant.

```ts
function handle(result: Result) {
	if (result.status === "success") {
		result.data;
	} else {
		result.message;
	}
}
```

The discriminant allows TypeScript to narrow the union precisely.

---

## Exhaustiveness Checking

Exhaustiveness checking ensures that all possible members of a union have been handled.

A common pattern uses `never`.

```ts
type Status = "pending" | "success" | "error";

function handle(status: Status) {
	switch (status) {
		case "pending":
			return "Waiting";
		case "success":
			return "Completed";
		case "error":
			return "Failed";
		default: {
			const exhaustive: never = status;
			return exhaustive;
		}
	}
}
```

If a new member is added to the union and not handled, TypeScript can report an error at the `never` assignment.
