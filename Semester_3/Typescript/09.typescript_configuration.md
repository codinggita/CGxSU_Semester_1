# Configuration

## 1. `tsconfig`

### `tsconfig.json`

`tsconfig.json` is the configuration file used by the TypeScript compiler.

It defines how TypeScript should:

- Check TypeScript code
- Resolve modules
- Determine the JavaScript version
- Include source files
- Generate output
- Apply strictness rules

A project can have one or more TypeScript configuration files depending on its structure.

---

### `compilerOptions`

`compilerOptions` contains settings that control TypeScript's type checking and compilation behavior.

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ESNext",
    "strict": true
  }
}
```

Compiler options affect how TypeScript interprets and transforms the source code.

---

### `target`

`target` specifies the JavaScript version that TypeScript should generate.

```json
{
  "compilerOptions": {
    "target": "ES2022"
  }
}
```

The target affects which JavaScript features TypeScript can preserve and which features may need to be transformed.

---

### `module`

`module` specifies the module system used by the generated JavaScript.

Common values include:

- `commonjs`
- `es2015`
- `es2020`
- `es2022`
- `esnext`
- `node16`
- `nodenext`

The appropriate value depends on the runtime and build environment.

---

### `moduleResolution`

`moduleResolution` determines how TypeScript resolves imported modules.

It controls how TypeScript searches for files and packages referenced by `import` statements.

Common modern resolution strategies include:

- `node16`
- `nodenext`
- `bundler`

The resolution strategy should generally match the project's runtime or bundler.

---

### `lib`

`lib` specifies the built-in type definitions available to the TypeScript program.

```json
{
  "compilerOptions": {
    "lib": ["ES2022", "DOM"]
  }
}
```

For example:

- `ES2022` provides types for modern JavaScript features.
- `DOM` provides browser and DOM API types.

---

### `rootDir`

`rootDir` specifies the root directory of the input TypeScript files.

```json
{
  "compilerOptions": {
    "rootDir": "./src"
  }
}
```

It helps TypeScript determine the structure of the generated output.

---

### `outDir`

`outDir` specifies the directory where generated JavaScript and related output files are written.

```json
{
  "compilerOptions": {
    "outDir": "./dist"
  }
}
```

For example:

```text
src/
  app.ts

dist/
  app.js
```

---

### `include`

`include` specifies which files or directories should be included in the TypeScript project.

```json
{
  "include": ["src/**/*.ts"]
}
```

Glob patterns can be used to select files.

---

### `exclude`

`exclude` specifies files or directories that should be excluded from the project.

```json
{
  "exclude": ["node_modules", "dist"]
}
```

The `exclude` option works together with the files selected through the configuration.

---

# 2. Strict Type Checking

Strict type checking enables stronger checks that help detect potential errors.

The `strict` option enables a collection of strict type-checking options.

---

## `strict`

```json
{
  "compilerOptions": {
    "strict": true
  }
}
```

`strict: true` enables a group of strict type-checking options.

It is recommended for most new TypeScript projects.

---

## `noImplicitAny`

When enabled, TypeScript reports an error when a value would otherwise implicitly have the `any` type.

```ts
function greet(name) {
  console.log(name);
}
```

With `noImplicitAny`, the untyped `name` parameter is reported as an error.

---

## `strictNullChecks`

When enabled, `null` and `undefined` are treated as distinct types.

```ts
let name: string = "Satya";

name = null;
```

The assignment is invalid when `strictNullChecks` is enabled.

This option is important for preventing null and undefined related errors.

---

## `strictFunctionTypes`

`strictFunctionTypes` applies stricter checking to function parameter types.

It helps TypeScript detect unsafe assignments involving function types.

```ts
type Handler = (value: string) => void;
```

Function parameter compatibility is checked more strictly when this option is enabled.

---

## `strictBindCallApply`

`strictBindCallApply` enables stricter type checking for the methods:

- `bind`
- `call`
- `apply`

TypeScript checks the arguments passed through these methods against the original function's parameter types.

---

## `strictPropertyInitialization`

`strictPropertyInitialization` checks that class properties are initialized in the constructor when they are not optional or explicitly allowed to remain uninitialized.

```ts
class User {
  name: string;

  constructor() {
    this.name = "Satya";
  }
}
```

This helps prevent class instances from containing unintentionally uninitialized properties.

---

## `noImplicitThis`

`noImplicitThis` reports an error when `this` would implicitly have the type `any`.

It helps ensure that the type of `this` is known in functions and methods.

---

## `useUnknownInCatchVariables`

When enabled, variables in `catch` clauses are typed as `unknown` instead of `any`.

```ts
try {
  // ...
} catch (error) {
  // error: unknown
}
```

This encourages proper checking before using the caught value.

---

# 3. Compiler Options

## `esModuleInterop`

`esModuleInterop` improves interoperability between CommonJS modules and ES module-style imports.

```json
{
  "compilerOptions": {
    "esModuleInterop": true
  }
}
```

It can make default imports from CommonJS packages behave more consistently.

---

## `allowSyntheticDefaultImports`

`allowSyntheticDefaultImports` allows default import syntax from modules that do not provide a real default export.

```ts
import express from "express";
```

This option affects type checking and does not itself change the emitted JavaScript.

`esModuleInterop` also enables this behavior.

---

## `resolveJsonModule`

`resolveJsonModule` allows JSON files to be imported as modules.

```json
{
  "compilerOptions": {
    "resolveJsonModule": true
  }
}
```

A JSON file can then be imported from TypeScript.

```ts
import config from "./config.json";
```

TypeScript can infer the structure of the JSON data.

---

## `isolatedModules`

`isolatedModules` ensures that each source file can be safely transpiled independently.

This is useful with build tools that transform files individually rather than using the TypeScript compiler to emit the complete project.

Some TypeScript patterns that require cross-file type information can be restricted when this option is enabled.

---

## `verbatimModuleSyntax`

`verbatimModuleSyntax` makes TypeScript preserve import and export syntax according to whether it is type-only or runtime code.

```ts
import type { User } from "./types";
import { createUser } from "./user";
```

With this option, type-only imports and exports should be explicitly marked when appropriate.

This provides predictable module output and makes the distinction between types and runtime values clearer.

---

## `skipLibCheck`

`skipLibCheck` skips type checking of declaration files such as `.d.ts` files.

```json
{
  "compilerOptions": {
    "skipLibCheck": true
  }
}
```

This can reduce type-checking time and avoid errors originating from dependency declaration files.

It does not skip type checking of the project's own TypeScript source files.

---

## `noEmit`

`noEmit` prevents TypeScript from generating JavaScript output.

```json
{
  "compilerOptions": {
    "noEmit": true
  }
}
```

TypeScript can still perform type checking.

This is commonly used when another tool, such as a bundler or framework, handles code generation.

---

## `sourceMap`

`sourceMap` generates source map files.

```json
{
  "compilerOptions": {
    "sourceMap": true
  }
}
```

Source maps allow debugging tools to map generated JavaScript back to the original TypeScript source.

---

## `declaration`

`declaration` generates `.d.ts` declaration files from TypeScript source files.

```json
{
  "compilerOptions": {
    "declaration": true
  }
}
```

Declaration files allow other TypeScript projects to consume the types of a library.

---

## `declarationMap`

`declarationMap` generates source maps for declaration files.

```json
{
  "compilerOptions": {
    "declarationMap": true
  }
}
```

These maps allow development tools to navigate from declarations back to the original TypeScript source.
