# Async & Error Handling

## 1. Async

TypeScript provides type support for asynchronous JavaScript code, including promises and asynchronous functions.

---

## Promise Types

A `Promise` represents a value that may become available asynchronously.

TypeScript can specify the type of value that a promise resolves to.

```ts
let promise: Promise<string>;
```

The `Promise<string>` type means the promise resolves to a `string`.

---

## Generic Promises

Promises are generic types.

```ts
const promise: Promise<number> = Promise.resolve(100);
```

The generic type parameter specifies the resolved value.

```text
Promise<T>
```

where `T` represents the resolved value type.

---

## Async Functions

An `async` function always returns a promise.

```ts
async function getUser() {
  return {
    id: 1,
    name: "Satya"
  };
}
```

TypeScript infers the returned promise type from the function's return value.

---

## Async Return Types

An async function can explicitly specify its return type.

```ts
async function getUser(): Promise<User> {
  return {
    id: 1,
    name: "Satya"
  };
}
```

The return type of an async function should be a `Promise`.

---

## `Promise<T>`

`Promise<T>` describes a promise that resolves to a value of type `T`.

```ts
function getName(): Promise<string> {
  return Promise.resolve("Satya");
}
```

Common promise types include:

```text
Promise<string>
Promise<number>
Promise<boolean>
Promise<User>
Promise<User[]>
```

---

## Promise Arrays

An array can contain promises.

```ts
const promises: Promise<number>[] = [
  Promise.resolve(1),
  Promise.resolve(2),
  Promise.resolve(3)
];
```

The array type describes the type of each promise.

The resolved values can be obtained using `Promise.all`.

```ts
const values = await Promise.all(promises);
```

TypeScript infers the resulting array as an array of the resolved value type.

---

## Async Error Handling

Asynchronous operations can fail, so they are commonly handled using `try...catch`.

```ts
async function loadUser() {
  try {
    const user = await getUser();
    return user;
  } catch (error) {
    console.error(error);
  }
}
```

With strict TypeScript settings, the caught error is treated as `unknown`.

The error should be checked before accessing properties specific to a particular error type.

---

# 2. Error Handling

## `Error`

The built-in `Error` class represents runtime errors.

```ts
const error = new Error("Something went wrong");
```

It provides commonly used properties such as:

- `name`
- `message`
- `stack`

Errors can be thrown using `throw`.

```ts
throw new Error("Something went wrong");
```

---

## `unknown` in Catch

With `useUnknownInCatchVariables` enabled, values caught by `catch` are typed as `unknown`.

```ts
try {
  // ...
} catch (error) {
  // error: unknown
}
```

Because any value can be thrown in JavaScript, TypeScript does not assume that the caught value is an `Error`.

The value should be narrowed before being used as a specific error type.

---

## Custom Errors

Custom error classes can extend the built-in `Error` class.

```ts
class ValidationError extends Error {
  constructor(message: string) {
    super(message);
    this.name = "ValidationError";
  }
}
```

Custom errors can represent different categories of application failures.

```ts
throw new ValidationError("Invalid email");
```

---

## Error Type Guards

Type guards can be used to safely identify specific error types.

```ts
function isError(value: unknown): value is Error {
  return value instanceof Error;
}
```

The guard narrows `unknown` to `Error`.

Custom error classes can also be checked using `instanceof`.

```ts
if (error instanceof ValidationError) {
  console.log(error.message);
}
```

---

## Result Types

A result type represents either a successful result or an error result as a union.

```ts
type Result<T> =
  | {
      success: true;
      data: T;
    }
  | {
      success: false;
      error: string;
    };
```

The discriminant property allows TypeScript to narrow the result.

```ts
function handle(result: Result<string>) {
  if (result.success) {
    console.log(result.data);
  } else {
    console.log(result.error);
  }
}
```

Result types are useful when errors are represented as values rather than thrown exceptions.

---

## Error Unions

Errors can be modeled as a union of specific error types.

```ts
type AppError =
  | {
      type: "validation";
      message: string;
    }
  | {
      type: "not-found";
      message: string;
    }
  | {
      type: "unauthorized";
      message: string;
    };
```

A discriminant property can be used to determine which error occurred.

```ts
function handleError(error: AppError) {
  switch (error.type) {
    case "validation":
      return error.message;

    case "not-found":
      return error.message;

    case "unauthorized":
      return error.message;
  }
}
```

Error unions provide a type-safe way to model known application errors.
