## Pattern #3: Slow and Fast Pointer Approach

### Definition

The **Slow and Fast Pointer technique** (also called the **"Tortoise and Hare"** approach) uses **two pointers that move through a data structure — usually a linked list or array — at different speeds**:

- The **slow pointer** moves **one step at a time**.
- The **fast pointer** moves **two steps at a time**.

Because the fast pointer covers ground twice as quickly, the **gap between the two pointers grows in a predictable way**, which can be exploited to detect cycles, find the middle element, or determine the length of a structure — all in a **single pass**, without extra memory.

```
Slow-Fast pointer movement:

  [1] → [2] → [3] → [4] → [5] → [6]
   ↑slow  
   ↑fast

Step 1:
   ↑slow      ↑fast
   (1)         (3)

Step 2:
         ↑slow            ↑fast
         (2)              (5)
```

If the list has a **cycle**, the fast pointer will eventually **lap** the slow pointer and they will meet. If the list is **acyclic**, the fast pointer reaches the **end (null)** first — and at that moment, the slow pointer is sitting at the **middle** of the list.

***

### How to Identify if a Problem Fits the Slow-Fast Pointer Pattern

Ask yourself these questions:

| Signal | Explanation |
| :-- | :-- |
| Is the input a **linked list**? | Slow-fast pointers are most commonly used here since random access isn't possible. |
| Do you need to detect a **cycle/loop**? | Classic slow-fast (Floyd's Cycle Detection) scenario. |
| Do you need to find the **middle node** in one pass? | Fast pointer reaches the end exactly when slow reaches the middle. |
| Do you need to find the **Nth node from the end**? | A fixed-gap variant of fast-slow pointers applies. |
| Is the problem about detecting a **repeating sequence / cycle in a functional graph** (e.g., "Happy Number")? | Floyd's cycle detection generalizes beyond linked lists. |
| Would a brute-force solution need **two full passes** or **extra space** (like a hash set) to track visited nodes? | Slow-fast pointers usually reduce this to one pass, O(1) space. |

If **2 or more** of the above are true, the problem is very likely solvable using the Slow-Fast Pointer pattern.

***

### Step-by-Step Explanation with a Simple Example

**Problem:** Given the **head of a linked list**, determine whether it contains a **cycle**.

```
List:  1 → 2 → 3 → 4 → 5 → (back to 3)
```

**Algorithm:**

1. Place `slow` pointer at the **head** of the list.
2. Place `fast` pointer at the **head** of the list.
3. Move `slow` forward by **1 node**, and `fast` forward by **2 nodes**, in each iteration.
4. Compare `slow` and `fast`:
   - If `fast` becomes `null` (or `fast->next` becomes `null`) → **no cycle**, return false.
   - If `slow == fast` at any point → **cycle exists**, return true.
5. Repeat until one of the above conditions is met.

***

### Visual Execution

```
List: 1 → 2 → 3 → 4 → 5 → (5 points back to 3)

Step 1:
1 → 2 → 3 → 4 → 5 → (cycle to 3)
↑slow
↑fast
slow = 1, fast = 1 → move both


Step 2:
1 → 2 → 3 → 4 → 5 → (cycle to 3)
    ↑slow       ↑fast
slow = 2, fast = 3   → not equal, continue


Step 3:
1 → 2 → 3 → 4 → 5 → (cycle to 3)
        ↑slow            ↑fast (wraps to 5→3, lands on 5)
slow = 3, fast = 5   → not equal, continue


Step 4:
1 → 2 → 3 → 4 → 5 → (cycle to 3)
            ↑slow   ↑fast (wraps again, lands on 4)
slow = 4, fast = 4   → EQUAL ✅ CYCLE DETECTED
```

Total steps taken: **4** (instead of using an extra hash set of size O(n) to track visited nodes) — this is the space efficiency gain of the pattern.

***

### C++ Code

```cpp
#include <iostream>
using namespace std;

// Definition for singly-linked list node
struct ListNode {
    int val;
    ListNode* next;
    ListNode(int x) : val(x), next(nullptr) {}
};

// Returns true if the linked list contains a cycle
bool hasCycle(ListNode* head) {
    ListNode* slow = head;             // Moves 1 step at a time
    ListNode* fast = head;             // Moves 2 steps at a time

    while (fast != nullptr && fast->next != nullptr) {
        slow = slow->next;             // Move slow by 1
        fast = fast->next->next;       // Move fast by 2

        if (slow == fast) {
            cout << "Cycle detected!" << endl;
            return true;                // Pointers met -> cycle exists
        }
    }
    return false;                       // fast reached null -> no cycle
}

int main() {
    // Build list: 1 -> 2 -> 3 -> 4 -> 5 -> (back to 3)
    ListNode* head = new ListNode(1);
    head->next = new ListNode(2);
    head->next->next = new ListNode(3);
    head->next->next->next = new ListNode(4);
    head->next->next->next->next = new ListNode(5);
    head->next->next->next->next->next = head->next->next; // creates cycle

    if (!hasCycle(head)) {
        cout << "No cycle found" << endl;
    }
    return 0;
}
```

**Output:**

```
Cycle detected!
```

***

### Time and Space Complexity

| Metric | Complexity | Explanation |
| :-- | :-- | :-- |
| Time Complexity | $O(n)$ | Fast pointer traverses at most the list twice before meeting slow or hitting null. |
| Space Complexity | $O(1)$ | Only two pointer variables are used — no extra hash set or array. |

**Comparison with Brute Force:**

| Approach | Time Complexity | Space Complexity |
| :-- | :-- | :-- |
| Brute Force (hash set of visited nodes) | $O(n)$ | $O(n)$ |
| Slow-Fast Pointer Approach | $O(n)$ | $O(1)$ |

***

## Common Problems Solved Using Slow-Fast Pointer Pattern

- Detecting a cycle in a linked list (Floyd's Cycle Detection)
- Finding the starting node of a cycle in a linked list
- Finding the middle node of a linked list in one pass
- Finding the Nth node from the end of a linked list
- Checking if a linked list is a palindrome
- Determining if a number is a "Happy Number" (cycle detection on digit-square sums)
- Reordering / rearranging a linked list
- Detecting duplicate numbers in an array using cycle detection (Floyd's on indices)
