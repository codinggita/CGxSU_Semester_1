# Assignment — Expo Local Authentication

#  Secure Vault Pro

Build a production-style **Secure Vault** application using Expo React Native and `expo-local-authentication`.

The goal is not simply to call individual APIs. You must combine the APIs into a complete authentication flow that decides:

---

# 1. Application Scenario

You are building a mobile application that contains highly sensitive information.

The information must remain hidden until the user successfully authenticates with the device's local authentication system.

The application should behave like this:

```text
                  App Starts
                      ↓
              Check Device Status
                      ↓
             ┌────────────────┐
             │ Device Ready?  │
             └────────────────┘
                ↓          ↓
               No          Yes
                ↓           ↓
        Show problem    Show Vault
        + solution      as Locked
                            ↓
                    Unlock Secure Vault
                            ↓
                    Local Authentication
                            ↓
                 ┌──────────┴──────────┐
                 ↓                     ↓
              Success              Failure
                 ↓                     ↓
          Open Secure Vault       Stay Locked
                 ↓
           Show Sensitive Data
```

You do **not necessarily need multiple React Navigation screens**.

You may implement the application using one screen with different UI states.

Your application must support these states:

```text

4. Device Ready
5. Authenticating
6. Authentication Successful
7. Authentication Failed
```

You should decide how these states are represented in your React Native UI.

# 3. Device Capability Check

When the application starts, determine whether biometric/local authentication hardware is available.

Use:

```js
LocalAuthentication.hasHardwareAsync()
```

### Required behavior

If hardware is available:

```text
 Local authentication hardware available
```

If hardware is unavailable:

```text
 Local authentication is not available
```

The application must not behave as if authentication is available when the device does not support it.

---

# 4. Authentication Enrollment Check

If the device has authentication hardware, determine whether the user has enrolled an authentication credential.

Use:

```js
LocalAuthentication.isEnrolledAsync()
```

Display an appropriate state.

Example:

```text
 Authentication credential enrolled
```

or:

```text
 No authentication credential enrolled
```

### Important

A device may have authentication hardware but still have no enrolled credential.

Your application must distinguish between:

```text
Hardware Available
```

and:

```text
Credential Enrolled
```

# 11. Authentication Result

Your application must inspect the returned result.

You must NOT assume:

```js

```

means authentication succeeded.

Handle at least:

```text

Failure
Cancellation
```

### Successful authentication

The application should:

```text

     ↓
Authentication Success
     ↓
Unlocked Vault
     ↓

```

### Failed authentication

The application should:

```text

The vault remains locked.
```

### Cancelled authentication

The application should:

```text
Authentication Cancelled

The vault remains locked.
```

# 14. Android Security Requirement

For Android, configure authentication using:

```js
biometricsSecurityLevel: "strong"
```

Example:

```js
const result =
  await LocalAuthentication.authenticateAsync({
    promptMessage: "Authenticate to open Secure Vault",
    biometricsSecurityLevel: "strong",
  });
```

### Required

Add a code comment explaining why `"strong"` was selected.

You should understand that this option controls the security level accepted for biometric authentication on Android.

# 19. Error Handling

All authentication-related asynchronous operations should be handled safely.

Use:

```js
try {
   // authentication logic
} catch (error) {
   // handle error
}
```

The application must not crash because an authentication operation throws an error.

Display a useful message instead of only showing:

```text

```

Try to make the error understandable to the user.

# 33. Restrictions

Do NOT:

* Hard-code the device status.
* Automatically unlock the vault without authentication.
* Display sensitive information before authentication.
* Assume `authenticateAsync()` always succeeds.
* Treat hardware availability as enrollment.
* Use raw numeric authentication type values in the UI.
* Call Android-only APIs blindly on iOS.
* Ignore authentication errors.
* Start multiple authentication requests simultaneously.
* Store real passwords, bank information, or personal secrets for this assignment.
