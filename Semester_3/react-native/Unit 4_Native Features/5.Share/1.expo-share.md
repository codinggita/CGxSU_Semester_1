# Share API in React Native and Expo

The **Share API** allows a React Native application to send content from your app to other applications installed on the device.

With sharing, an app can share:

- Text
- URLs
- Product details
- Contact details
- Order details
- Referral links
- Local files such as PDFs, images, and videos

React Native and Expo provide different APIs depending on what you want to share.

| API | Main Purpose |
|---|---|
| `Share` from React Native | Share text and URLs |
| `expo-sharing` | Share local files |

---

# Why Do We Need a Share API?

Many applications need a way to send information from the current app to another application.

Examples:

### Social / Content Apps

- Share a post
- Share a quote
- Share an article
- Share a profile

### E-commerce Apps

- Share a product
- Share a product link
- Share an order

### Contact / Communication Apps

- Share contact details
- Share a phone number
- Share an email address

### Other Applications

- Share a referral link
- Share a generated PDF
- Share an image
- Share a video

Instead of implementing WhatsApp, Gmail, Telegram, Messages, etc. individually, we use the operating system's native sharing system.

---

# How Does Sharing Work?

The most important mental model is:

```text
Your React Native App
        ↓
   Share API
        ↓
 Native Android / iOS
        ↓
    Share Sheet
        ↓
 WhatsApp / Gmail / Messages / Telegram / etc.
```

Your React Native application does **not** directly control WhatsApp, Gmail, Telegram, or other destination apps.

React Native asks the operating system to perform a sharing operation.

The operating system decides which sharing destinations are available on the device.

# Chapter 1 - React Native `Share` API

React Native provides a built-in `Share` API.

No package installation is required.

## Import

```js
import { Share } from "react-native";
```

The main method is:

```js
Share.share()
```

```text
User presses Share button

        ↓

handleShare()

        ↓

Share.share()

        ↓

Native Android / iOS Share System

        ↓

Native Share Sheet

        ↓

User selects an application

        ↓

Content is shared
```

# Example 1 - Basic Text Sharing

## Basic Example

```js
import React from "react";
import {
  View,
  Button,
  Share,
} from "react-native";

export default function ShareScreen() {

  const handleShare = async () => {

    await Share.share({
      message: "Hello from my React Native application!",
    });

  };

  return (
    <View>
      <Button
        title="Share Text"
        onPress={handleShare}
      />
    </View>
  );
}
```

When the user presses the button, the native share sheet opens.

---

# What is the Share Sheet?

The **Share Sheet** is the native operating-system UI that allows the user to choose where the content should be shared.

Conceptually:

```text
              Share
                ↓
    ┌────────────────────────┐
    │ WhatsApp               │
    │ Messages               │
    │ Gmail                  │
    │ Telegram               │
    │ Copy                   │
    │ Save to Files          │
    └────────────────────────┘
```

The exact UI depends on:

- Android or iOS
- OS version
- Device manufacturer
- Applications installed on the device

React Native does not create this native Share Sheet.

---

# `Share.share()` Syntax

The general syntax is:

```js
Share.share(content, options);
```

There are two arguments:

```text
Share.share(
    content,
    options
)
     ↓
     ├── What should be shared?
     │
     └── Optional configuration
```

Example:

```js
await Share.share(
  {
    message: "Hello React Native!",
  },
  {
    dialogTitle: "Share this message",
  }
);
```

---

# Understanding `content`

The first argument describes the content.

Common properties are:

```js
{
  message,
  url,
  title
}
```

However, these properties do not behave identically on Android and iOS.

This is because React Native ultimately uses the native sharing system of the operating system.

---

# `message`

`message` contains the main text you want to share.

```js
await Share.share({
  message: "Check out my React Native application!",
});
```

Mental model:

```text
message
   ↓
Main text content
   ↓
Text being shared
```

For basic text sharing, `message` is the most important property.

---

# Dynamic `message`

The message can be generated dynamically.

```js
const userName = "Rajesh";

await Share.share({
  message: `Hello ${userName}, check out this app!`,
});
```

Result:

```text
Hello Rajesh, check out this app!
```

The message can come from:

- API data
- React state
- User input
- Database data
- Product information
- User profile information

# Sharing Text From a `TextInput`

A common real-world use case is allowing the user to enter text and then share it.

```js
import React, { useState } from "react";

import {
  View,
  TextInput,
  Button,
  Share,
} from "react-native";

export default function ShareTextScreen() {

  const [text, setText] = useState("");

  const handleShare = async () => {

    if (!text.trim()) {
      return;
    }

    await Share.share({
      message: text.trim(),
    });

  };

  return (
    <View>

      <TextInput
        placeholder="Enter text to share"
        value={text}
        onChangeText={setText}
      />

      <Button
        title="Share"
        onPress={handleShare}
      />

    </View>
  );
}
```

### Flow

```text
User enters text
      ↓
TextInput
      ↓
React state
      ↓
Share button
      ↓
handleShare()
      ↓
Share.share()
      ↓
Native Share Sheet
```

---

# Why Use `trim()`?

```js
text.trim()
```

removes unnecessary spaces from the beginning and end.

Example:

```js
"   Hello   "
```

becomes:

```js
"Hello"
```

This check:

```js
if (!text.trim()) {
  return;
}
```

prevents the user from sharing an empty value containing only spaces.

You can provide a URL using the `url` property.

```js
await Share.share({
  message: "Check out this website!",
  url: "https://reactnative.dev",

```

However, `url` has platform-specific behavior.

React Native documents:

- `message` as the main text content
- `url` as an iOS content property
- `title` for Android

Therefore, do not assume that `url` behaves exactly the same on Android and iOS.

# Sharing a URL Inside `message`

If you want the URL to explicitly be part of the shared text, put it inside `message`.

```js
await Share.share({
  message: `
Check this website:

https://example.com
`,
});
```

Now the URL is simply part of the text:

```text
Check this website:

https://example.com
```

This is useful when you want the URL to be treated as text consistently across platforms.

# Example 3 - Understanding `title`

Example:

```js
await Share.share({
  title: "React Native Course",
  message: "Check out this course!",
});
```

There are two different concepts:

```text
title
  ↓
Android share operation / share-dialog title

message
  ↓
Main shareable text
```

## Important

Do **not** think of `title` as text that will definitely be sent to WhatsApp, Gmail, Telegram, or another destination.

`title` is documented for Android and provides a title for the share operation/dialog.

However, the native Android Sharesheet and device implementation decide whether and where that title is visibly displayed.

For example:

```js
title: "React Native Course"
```

may be provided to Android, but your particular phone may not visibly display:

```text
React Native Course
```

That does not necessarily mean the code is wrong.

---

# `title` vs `message`

Consider:

```js
await Share.share({
  title: "MY TITLE",
  message: "MY MESSAGE",
});
```

Think about them separately:

```text
title
  ↓
Information provided to the Android share operation/UI

message
  ↓
Main content being shared
```

### Important Rule

> **`message` is the actual shareable text. `title` is not a guaranteed heading that the recipient will receive or that the user will visibly see in the native share UI.**

---

# Android vs iOS

A simplified mental model is:

```text
                 Share.share()
                      |
             ┌────────┴────────┐
             ↓                 ↓
          Android             iOS
             |                 |
           title              url
```

React Native documents:

- `message` as the main content
- `title` for Android
- `url` as an iOS content property

This does not mean Android cannot share URLs.

For example:

```js
await Share.share({
  message: "Check this out: https://example.com",
});
```

Here, the URL is part of the message itself.

---

```js
    dialogTitle: "Share this message",

```

Think:

```text
content
   ↓
What should I share?

options
   ↓
Optional sharing configuration
```

The exact appearance of the native share UI is controlled by the operating system.

# Chapter 2 - Promise and `async/await`

`Share.share()` is asynchronous.

When we call:

```js
Share.share(...)
```

it returns a Promise.

Mental model:

```text
Share.share()
      ↓
   Promise
      ↓
    await
      ↓
   Actual result
```

Therefore, when you need the result, use:

```js
const result = await Share.share({
  message: "Hello!",
});
```

---

# Incorrect Way When Reading the Result

```js
const result = Share.share({
  message: "Hello!",
});

console.log(result);
```

Here:

```text
result
  ↓
Promise
```

It is not the final share result yet.

---

# Correct Way

```js
const result = await Share.share({
  message: "Hello!",
});

console.log(result);
```

Here:

```text
Share.share()
      ↓
Promise
      ↓
await
      ↓
Final result
```

---

# Using `.then()`

You can also use a Promise chain.

```js
Share.share({
  message: "Hello!",
})
  .then((result) => {
    console.log(result);
  })
  .catch((error) => {
    console.log(error);
  });
```

Both approaches work.

For React Native applications, `async/await` with `try/catch` is usually easier to read.

# Chapter 3 - Understanding the Share Result

Example:

```js
const result = await Share.share({
  message: "Hello!",
});

console.log(result);
```

You may see a result like:

```js
{
  action: "sharedAction",
  activityType: null
}
```

The important properties are:

```text
result
  |
  ├── action
  |
  └── activityType
```

---

# `Share.sharedAction`

React Native provides:

```js
Share.sharedAction
```

You can check:

```js
const result = await Share.share({
  message: "Hello!",
});

if (result.action === Share.sharedAction) {
  console.log("Content was shared");
}
```

Mental model:

```text
result.action
      ↓
What happened?
      ↓
sharedAction
      ↓
Share operation completed
```

---

# `Share.dismissedAction`

React Native also provides:

```js
Share.dismissedAction
```

Example:

```js
const result = await Share.share({
  message: "Hello!",
});

if (result.action === Share.dismissedAction) {
  console.log("User dismissed the share dialog");
}
```

Mental model:

```text
Share Sheet
     |
     ├── User completes sharing
     |        ↓
     |   sharedAction
     |
     └── User dismisses dialog
              ↓
        dismissedAction
```

The exact availability and behavior of dismissal information can depend on the platform.

---

# `activityType`

`activityType` is mainly relevant to **iOS**.

It can provide information about the iOS sharing activity/service used for the operation.

Example:

```js
const result = await Share.share({
  message: "Hello React Native!",
});

console.log(result.activityType);
```

Conceptually, an iOS result can contain:

```js
{
  action: Share.sharedAction,
  activityType: "some iOS activity identifier",
}
```

Mental model:

```text
action
  ↓
What happened?
  ↓
sharedAction / dismissedAction

activityType
  ↓
Which iOS sharing activity/service was used?
```

---

# Why is `activityType` `null` on Android?

If you test on Android, you may see:

```js
{
  action: "sharedAction",
  activityType: null,
}
```

This does **not** mean sharing failed.

Instead:

```text
action
  ↓
sharedAction
  ↓
Sharing happened

activityType
  ↓
null
  ↓
No iOS activity information
```

Therefore:

> **`activityType: null` on Android is normal.**

If you want to know whether the share operation completed, check:

```js
result.action
```

not:

```js
result.activityType
```

---

# `action` vs `activityType`

This is one of the most important concepts in the Share API.

```text
result
  |
  ├── action
  |      ↓
  |   What happened?
  |
  |   sharedAction
  |      ↓
  |   Sharing completed
  |
  |   dismissedAction
  |      ↓
  |   Share dialog dismissed
  |
  └── activityType
         ↓
      Mainly iOS
         ↓
      Which sharing activity/service?
```

### Easy way to remember

> **`action` tells you what happened. `activityType` tells you which iOS sharing activity was involved.**

# Using `try/catch`

A production-style implementation should handle errors.

```js
const handleShare = async () => {

  try {

    const result = await Share.share({
      message: "Hello React Native!",
    });

    if (result.action === Share.sharedAction) {
      console.log("Content shared");
    }

    if (result.action === Share.dismissedAction) {
      console.log("Share dialog dismissed");
    }

  } catch (error) {

    console.log(error);

  }

};
```

Flow:

```text
try
 ↓
Share.share()
 ↓
Wait for result
 ↓
Check result.action
 ↓
catch error if operation fails
```

# `Sharing.shareAsync()`

The main method is:

```js
Sharing.shareAsync(
  fileUri,
  options
);
```

The first argument should be a **local file URI**.

Example:

```js
await Sharing.shareAsync(
  fileUri
);
```

---

# What Is a Local File URI?

A local file URI points to a file stored on the device.

Example:

```text
file:///path/to/image.jpg
```

or:

```text
file:///path/to/document.pdf
```

A remote URL is different:

```text
https://example.com/file.pdf
```

The difference:

```text
Remote URL
    ↓
File exists on a server

Local File URI
    ↓
File already exists on the device
```

Typical remote-file flow:

```text
Remote URL
    ↓
Download
    ↓
Local File URI
    ↓
Sharing.shareAsync()
    ↓
Share Sheet
```

# Sharing an Image Selected from the Gallery

`expo-sharing` needs a **real local file URI**.

Instead of manually writing a file path such as:

```js

  "file:///storage/example.jpg";
```

we can use `expo-image-picker` to let the user select an image from the device gallery.

The Image Picker returns information about the selected image, including its local `uri`.

---

## Step 1 - Install Required Packages

```bash
npx expo install expo-image-picker expo-sharing
```

`expo-image-picker` is used to select the image.

`expo-sharing` is used to share the selected image.

---

## Step 2 - Import the Packages

```js
import {
  View,
  Button,
  Alert,
} from "react-native";

import * as ImagePicker
  from "expo-image-picker";

import * as Sharing
  from "expo-sharing";
```

---

## Step 3 - Pick and Share the Image

```js
import {
  View,
  Button,
  Alert,
} from "react-native";

import * as ImagePicker
  from "expo-image-picker";

import * as Sharing
  from "expo-sharing";

export default function ShareScreen() {

  const shareImage = async () => {

    try {

      // 1. Check whether file sharing is available
      const available =
        await Sharing.isAvailableAsync();

      if (!available) {

        Alert.alert(
          "Unavailable",
          "File sharing is not available."
        );

        return;
      }

      // 2. Open the device's image picker
      const result =
        await ImagePicker.launchImageLibraryAsync({
          mediaTypes: ["images"],
          allowsEditing: false,
          quality: 1,
        });

      // 3. Check whether the user cancelled
      if (result.canceled) {
        return;
      }

      // 4. Get the selected image's local URI
      const imageUri =
        result.assets[0].uri;

      console.log(
        "IMAGE URI:",
        imageUri
      );

      // 5. Share the selected image
      await Sharing.shareAsync(
        imageUri,
        {
          mimeType:
            result.assets[0].mimeType ||
            "image/jpeg",

          dialogTitle:
            "Share Image",
        }
      );

    } catch (error) {

      console.log(error);

      Alert.alert(
        "Error",
        "Unable to share image."
      );

    }

  };

  return (

    <View
      style={{
        flex: 1,
        justifyContent: "center",
        alignItems: "center",
      }}
    >

      <Button
        title="Pick & Share Image"
        onPress={shareImage}
      />

    </View>
  );
}
```

---

## How Does This Work?

The complete flow is:

```text
User presses button
        ↓
ImagePicker.launchImageLibraryAsync()
        ↓
Gallery opens
        ↓
User selects an image
        ↓
Picker returns result
        ↓
result.assets[0].uri
        ↓
Local File URI
        ↓
Sharing.shareAsync(imageUri)
        ↓
Native Android / iOS
        ↓
Share Sheet
        ↓
WhatsApp / Gmail / Messages / etc.
```

The important part is:

```js
const imageUri =
  result.assets[0].uri;
```

This gives us the **actual URI of the selected image**.

Then we pass that URI to:

```js
await Sharing.shareAsync(
  imageUri
);
```

So unlike the previous example:

```js
const fileUri =
  "file:///storage/example.pdf";
```

we are not inventing a file path.

The picker gives us a URI that points to the selected image.

---

## Understanding `result`

After selecting an image, the picker returns an object similar to:

```js
{
  canceled: false,

  assets: [
    {
      uri: "file:///.../image.jpg",
      width: 1920,
      height: 1080,
      mimeType: "image/jpeg"
    }
  ]
}
```

We access the selected image using:

```js
result.assets[0]
```

and its URI using:

```js
result.assets[0].uri
```

Therefore:

```text
result
   ↓
assets
   ↓
assets[0]
   ↓
selected image
   ↓
assets[0].uri
   ↓
local file URI
```

---

## Why Do We Check `result.canceled`?

The user might open the gallery and press the back button without selecting anything.

In that case:

```js
result.canceled
```

will be:

```js
true
```

So we stop the function:

```js
if (result.canceled) {
  return;
}
```

Otherwise, we can safely access:

```js
result.assets[0]
```

---

## Important Concept

`expo-image-picker` and `expo-sharing` have **different responsibilities**.

```text
expo-image-picker
        ↓
Select image
        ↓
Return image URI
```

while:

```text
expo-sharing
        ↓
Take local file URI
        ↓
Open native sharing system
```

Together:

```text
Gallery
   ↓
expo-image-picker
   ↓
imageUri
   ↓
expo-sharing
   ↓
Native Share Sheet
```

This is the practical way to share an image selected from the user's device.

# MIME Types

For files, the MIME type describes what kind of file is being shared.

Common examples:

```text
PDF
→ application/pdf

JPEG
→ image/jpeg

PNG
→ image/png

MP4
→ video/mp4
```

Example:

```js
await Sharing.shareAsync(
  imageUri,
  {
    mimeType: "image/jpeg",
  }
);
```

When using a picker, it is better to use the MIME type returned by the selected asset when available:

```js
const mimeType =
  result.assets[0].mimeType;
```

Then:

```js
await Sharing.shareAsync(
  imageUri,
  {
    mimeType:
      mimeType || "image/jpeg",
  }
);
```

# Choosing a File with `expo-document-picker`

For PDFs, documents, ZIP files, and other file types, you can use `expo-document-picker`.

Install:

```bash
npx expo install expo-document-picker expo-sharing
```

Import:

```js
import * as DocumentPicker
  from "expo-document-picker";

import * as Sharing
  from "expo-sharing";
```

Example:

```js
const shareFile = async () => {

  try {

    const available =
      await Sharing.isAvailableAsync();

    if (!available) {
      return;
    }

    const result =
      await DocumentPicker.getDocumentAsync({
        type: "*/*",
        copyToCacheDirectory: true,
      });

    if (result.canceled) {
      return;
    }

    const file =
      result.assets[0];

    console.log(
      "FILE:",
      file
    );

    console.log(
      "FILE URI:",
      file.uri
    );

    await Sharing.shareAsync(
      file.uri,
      {
        mimeType:
          file.mimeType,

        dialogTitle:
          "Share File",
      }
    );

  } catch (error) {

    console.log(error);

  }

};
```

The flow is:

```text
Document Picker
      ↓
User selects PDF / DOCX / ZIP / etc.
      ↓
result.assets[0]
      ↓
file.uri
      ↓
Sharing.shareAsync(file.uri)
      ↓
Native Share Sheet
```

# Complete Combined Example

```js
import React from "react";

import {
  View,
  Text,
  Pressable,
  StyleSheet,
  Share,
  Alert,
} from "react-native";

import * as ImagePicker
  from "expo-image-picker";

import * as Sharing
  from "expo-sharing";

export default function ShareDemo() {

  const shareText = async () => {

    try {

      await Share.share({
        message:
          "Hello from my React Native app!",
      });

    } catch (error) {

      Alert.alert(
        "Error",
        "Unable to share text."
      );

    }

  };

  const shareURL = async () => {

    try {

      await Share.share({
        message:
          "Check this website:\nhttps://example.com",
      });

    } catch (error) {

      Alert.alert(
        "Error",
        "Unable to share URL."
      );

    }

  };

  const shareImage = async () => {

    try {

      const available =
        await Sharing.isAvailableAsync();

      if (!available) {

        Alert.alert(
          "Unavailable",
          "File sharing is not available."
        );

        return;
      }

      const result =
        await ImagePicker.launchImageLibraryAsync({
          mediaTypes: ["images"],
          allowsEditing: false,
          quality: 1,
        });

      if (result.canceled) {
        return;
      }

      const image =
        result.assets[0];

      await Sharing.shareAsync(
        image.uri,
        {
          mimeType:
            image.mimeType ||
            "image/jpeg",

          dialogTitle:
            "Share Image",
        }
      );

    } catch (error) {

      console.log(error);

      Alert.alert(
        "Error",
        "Unable to share image."
      );

    }

  };

  return (

    <View style={styles.container}>

      <Text style={styles.title}>
        Share Demo
      </Text>

      <Pressable
        style={styles.button}
        onPress={shareText}
      >

        <Text style={styles.buttonText}>
          Share Text
        </Text>

      </Pressable>

      <Pressable
        style={styles.button}
        onPress={shareURL}
      >

        <Text style={styles.buttonText}>
          Share URL
        </Text>

      </Pressable>

      <Pressable
        style={styles.button}
        onPress={shareImage}
      >

        <Text style={styles.buttonText}>
          Pick & Share Image
        </Text>

      </Pressable>

    </View>
  );
}

const styles = StyleSheet.create({

  container: {
    flex: 1,
    justifyContent: "center",
    padding: 20,
  },

  title: {
    fontSize: 28,
    fontWeight: "bold",
    textAlign: "center",
    marginBottom: 30,
  },

  button: {
    padding: 16,
    borderRadius: 10,
    alignItems: "center",
    marginBottom: 12,
  },

  buttonText: {
    fontSize: 16,
    fontWeight: "600",
  },

});
```
