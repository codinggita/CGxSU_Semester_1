# Part 1 — Splash Screen Fundamentals

## 1. What Is a Splash Screen?

A **splash screen**, also called a *launch screen*, is the initial screen displayed when a user opens a mobile application.

It appears during the application's startup process, before the main interface becomes available.

A splash screen usually contains:

- **Logo:** Identifies the application.
- **Background color:** Matches the application's branding.
- **Brand illustration:** An optional visual related to the application.
- **Simple design:** Keeps the launch experience clean and recognizable.

### Example: Opening a Shopping App

1. The user taps the application icon.
2. The native splash screen displays the brand logo.
3. The application starts initializing.
4. The home screen appears with products and navigation.

The splash screen provides the initial visual experience while the application prepares to display its interface.

## 2. Why Do We Need a Splash Screen?

A splash screen helps create a consistent and professional startup experience.

**Brand identity:** The logo and background color help users recognize the application.

**Smooth startup:** The native splash screen provides a visual transition while the application starts.

**Resource preparation:** Developers can keep the splash screen visible while essential resources, such as fonts or local settings, are loaded.

**Platform consistency:** Expo provides configuration options for the native launch experience on supported platforms.

**Important:** A splash screen does not automatically fetch API data, load fonts, or restore authentication. Developers must implement that logic when necessary.

## 3. Splash Screen vs. Loading Screen

These two screens may look similar, but they serve different purposes.

| Native splash screen | React Native loading screen |
|---|---|
| Displayed by the operating system during launch. | Rendered by the React Native application. |
| Can appear before JavaScript is ready. | Requires the application interface to start rendering. |
| Configured using Expo's native configuration. | Built using components such as `View` and `ActivityIndicator`. |
| Handles the initial launch experience. | Handles loading work within the application. |

### Example: Educational Application

**Stage 1:** The native splash screen displays the application logo.

**Stage 2:** The application starts and displays a loading indicator while course information is fetched.

**Stage 3:** The course dashboard appears.

Remember: the splash screen handles startup, while a loading screen handles work that continues after the application interface has started.

## 4. How Does a Splash Screen Work?

```text
User opens the application
          |
          v
Native splash screen appears
          |
          v
React Native application starts
          |
          v
Essential resources load (if required)
          |
          v
Splash screen disappears
          |
          v
Application interface appears
```

Expo provides the `expo-splash-screen` package for configuring the native splash screen and controlling when it disappears.

There are two approaches:

- **Automatic:** Expo handles splash screen visibility automatically.
- **Manual:** The developer decides when to hide the splash screen.

For most applications, automatic behavior is sufficient. Manual control is useful when essential resources must be ready before the first screen appears.

# Part 2 — Installation and Project Setup

## 1. Install the Package

Open a terminal in the root directory of your Expo project.

```bash
npx expo install expo-splash-screen
```

Expo selects a version compatible with your project's SDK.

For a project that uses Expo Router, the structure may look like this:

```text
my-app/
├── app/
│   ├── _layout.js
│   └── index.js
├── assets/
│   └── images/
│       ├── splash-icon.png
│       └── splash-icon-dark.png
├── app.json
└── package.json
```

| File | Purpose |
|---|---|
| `app.json` | Stores Expo configuration, including the splash screen plugin. |
| `app/_layout.js` | Defines the root navigation layout and optional startup logic. |
| `app/index.js` | Defines a route in the Expo Router application. |
| `assets/images/` | Stores splash screen artwork. |
| `package.json` | Lists dependencies and project scripts. |

Your project may use `src/app/` instead of `app/`. Adjust file paths accordingly.

Start the development server:

```bash
npx expo start
```

# Part 3 — Configure and Customize the Splash Screen

## 1. Configure `app.json`

Expo recommends configuring the splash screen using its built-in config plugin.

Open `app.json` and add the following configuration under `expo.plugins`.

```json
{
  "expo": {
    "plugins": [
      [
        "expo-splash-screen",
        {
          "backgroundColor": "#2563eb",
          "image": "./assets/images/splash-icon.png",
          "imageWidth": 200,
          "resizeMode": "contain"
        }
      ]
    ]
  }
}
```

If your project already has plugins, add `expo-splash-screen` to the existing array instead of replacing the other plugins.

### Understand the properties

| Property | Purpose |
|---|---|
| `backgroundColor` | Sets the splash screen background color. |
| `image` | Specifies the path to the splash screen image. |
| `imageWidth` | Configures the image width. |
| `resizeMode` | Controls how the image is scaled. |

These properties configure native resources. Changes generally require a new native build to take effect.

## 2. Customize the Background Color

The `backgroundColor` property accepts a hexadecimal color.

**White background**

```json
"backgroundColor": "#ffffff"
```

**Black background**

```json
"backgroundColor": "#000000"
```

**Blue background**

```json
"backgroundColor": "#2563eb"
```

Choose a color that complements the logo and matches the application's branding.

## 3. Configure the Splash Screen Image

The `image` property specifies the image file used for the splash screen.

```json
"image": "./assets/images/splash-icon.png"
```

For this configuration, the file should exist at:

```text
my-app/
├── assets/
│   └── images/
│       └── splash-icon.png
└── app.json
```

If you rename the image, update the path in `app.json`.

### Image preparation tips

- Use a PNG image for the configured splash screen artwork.
- A square image around 1024 × 1024 pixels is a useful starting point for a logo.
- Keep the important artwork centered.
- Leave enough transparent space around the logo when appropriate.
- Choose artwork that remains visible against the background color.

The configured display width, aspect ratio, and platform layout determine how the image appears.

## 4. Control the Image Width

The `imageWidth` property configures the width of the splash screen image.

```json
"imageWidth": 100
```

This configures a relatively small logo.

```json
"imageWidth": 200
```

This configures a medium-sized logo.

```json
"imageWidth": 250
```

This configures a larger logo.

The displayed image height depends on its aspect ratio. The result may differ between platforms, so verify it on your target devices.

**Remember:** Layout units are not necessarily equal to physical screen pixels.

## 5. Understand `resizeMode`

The `resizeMode` property determines how the image is scaled.

| Value | Behavior | Suitable use |
|---|---|---|
| `contain` | Displays the complete image without cropping. | Logos and brand marks. |
| `cover` | Covers the available area; cropping may occur. | Artwork intended to fill an area. |
| `native` | Uses native image resizing behavior. | When native scaling is desired. |

### Recommended starting point

```json
"resizeMode": "contain"
```

For most logo-based splash screens, `contain` is a good starting point because the entire logo remains visible.

## 6. Complete Example — LearnHub

Imagine we are developing an educational application called **LearnHub**.

Requirements:

- Blue background.
- Centered logo.
- Logo width of 220 points.
- No cropping of the logo.

Configuration:

```json
{
  "expo": {
    "plugins": [
      [
        "expo-splash-screen",
        {
          "backgroundColor": "#2563eb",
          "image": "./assets/images/splash-icon.png",
          "imageWidth": 220,
          "resizeMode": "contain"
        }
      ]
    ]
  }
}
```

Expected experience:

1. The user opens LearnHub.
2. The native splash screen displays the blue background and logo.
3. The application starts.
4. The splash screen disappears.
5. The LearnHub interface appears.

No custom JavaScript is needed just to configure this basic splash screen.

# Part 4 — Understand the Splash Screen API

## 1. Import the Library

```jsx
import * as SplashScreen from "expo-splash-screen";
```

This imports the Splash Screen module and makes its methods available through the `SplashScreen` object.

For example:

```jsx
SplashScreen.hide();
```

This calls the method that hides the native splash screen.

## 2. Important Methods

| Method | Purpose |
|---|---|
| `preventAutoHideAsync()` | Prevents automatic hiding so you can control visibility. |
| `hide()` | Hides the native splash screen. |
| `hideAsync()` | Backward-compatible asynchronous hiding method. |
| `setOptions()` | Configures the built-in fade-out animation. |

### Method 1 — `preventAutoHideAsync()`

```jsx
SplashScreen.preventAutoHideAsync().catch(console.warn);
```

This asks Expo to keep the native splash screen visible until the application hides it.

Call it at the module's top level, outside the React component, so the request is made as early as possible.

Use manual control when you need to:

- Load essential fonts.
- Read required local settings.
- Restore authentication state.
- Initialize necessary application services.

Do not delay startup for resources that are not required to display the first screen.

### Method 2 — `hide()`

```jsx
SplashScreen.hide();
```

This hides the native splash screen immediately.

Use it when the application is ready to display its interface.

Hiding it too early can produce a brief blank screen.

### Method 3 — `hideAsync()`

```jsx
await SplashScreen.hideAsync();
```

This is the backward-compatible asynchronous method.

For new code, `hide()` is sufficient when you do not need an asynchronous call.

### Method 4 — `setOptions()`

```jsx
SplashScreen.setOptions({
  duration: 1000,
  fade: true
});
```

This configures the built-in fade-out animation.

| Option | Meaning |
|---|---|
| `duration` | Animation duration in milliseconds. |
| `fade` | Enables the fade-out animation on iOS. |

# Part 5 — Add a Fade Animation

## 1. Configure the Animation

**File:** `app/_layout.js`

```jsx
import { Stack } from "expo-router";
import * as SplashScreen from "expo-splash-screen";

SplashScreen.setOptions({
  duration: 1000,
  fade: true
});

export default function RootLayout() {
  return <Stack />;
}
```

### How does it work?

1. `Stack` provides the application's route layout.
2. `SplashScreen.setOptions()` configures the built-in animation.
3. Expo handles the default splash screen visibility behavior.
4. When the splash screen hides, the configured fade animation is used where supported.

The duration is one second.

**Important:** This does not intentionally delay startup for one second. It specifies the duration of the fade-out animation.

This example does not require `preventAutoHideAsync()` because it does not need to delay the splash screen manually.

# Part 6 — Control the Splash Screen Manually

## 1. When Is Manual Control Needed?

Imagine a student application that must load its initial configuration before showing the dashboard.

The desired flow is:

```text
Application opens
        |
        v
Splash screen stays visible
        |
        v
Essential resources load
        |
        v
isReady becomes true
        |
        v
Splash screen hides
        |
        v
Application interface appears
```

We can implement this with:

- `preventAutoHideAsync()`
- `useState()`
- `useEffect()`
- `hide()`

## 2. Complete Example

**File:** `app/_layout.js`

```jsx
import { Stack } from "expo-router";
import * as SplashScreen from "expo-splash-screen";
import { useEffect, useState } from "react";

// Keep the native splash screen visible during initialization.
SplashScreen.preventAutoHideAsync().catch(console.warn);

export default function RootLayout() {
  const [isReady, setIsReady] = useState(false);

  useEffect(() => {
    async function prepareApp() {
      try {
        // Teaching example: simulate loading essential resources.
        await new Promise((resolve) => {
          setTimeout(resolve, 2000);
        });
      } catch (error) {
        console.warn("Startup error:", error);
      } finally {
        // Allow the application to continue even if initialization fails.
        setIsReady(true);
      }
    }

    prepareApp();
  }, []);

  useEffect(() => {
    if (isReady) {
      SplashScreen.hide();
    }
  }, [isReady]);

  if (!isReady) {
    return null;
  }

  return <Stack />;
}
```

## 3. Understand the Code

**Step 1 — Prevent automatic hiding**

```jsx
SplashScreen.preventAutoHideAsync().catch(console.warn);
```

This requests manual control over the native splash screen.

It is called outside the component to avoid making the request too late.

**Step 2 — Create a readiness state**

```jsx
const [isReady, setIsReady] = useState(false);
```

Initially, `isReady` is `false`, meaning initialization has not finished.

**Step 3 — Start initialization**

```jsx
useEffect(() => {
  async function prepareApp() {
    // Initialization work
  }

  prepareApp();
}, []);
```

The effect starts the asynchronous preparation process when the root layout mounts.

**Step 4 — Simulate an asynchronous operation**

```jsx
await new Promise((resolve) => {
  setTimeout(resolve, 2000);
});
```

This waits approximately two seconds.

The timer is only a teaching example. It does not load real resources.

**Step 5 — Update the state**

```jsx
finally {
  setIsReady(true);
}
```

The `finally` block runs whether the operation succeeds or fails.

This prevents the example from remaining in its loading state indefinitely because of an initialization error.

**Step 6 — Hide the splash screen**

```jsx
useEffect(() => {
  if (isReady) {
    SplashScreen.hide();
  }
}, [isReady]);
```

When `isReady` becomes `true`, the effect hides the native splash screen.

**Step 7 — Render the application interface**

```jsx
if (!isReady) {
  return null;
}
```

This prevents the root layout from rendering its route navigator before initialization completes.

When `isReady` becomes `true`, the `Stack` is rendered.

### Why do we need both methods?

| Method | Responsibility |
|---|---|
| `preventAutoHideAsync()` | Requests that the splash screen remain visible. |
| `hide()` | Hides the splash screen when the application is ready. |

**Production note:** This example teaches the startup flow. A real application should handle initialization failures appropriately and ensure that its first meaningful interface is ready before hiding the splash screen.

# Part 7 — Load Fonts and Essential Startup Data

## 1. Load Custom Fonts Before Hiding

Suppose your application uses a custom font. If the interface appears before the font is ready, the user may briefly see a fallback font.

We can wait for the font to load before hiding the splash screen.

Install the package:

```bash
npx expo install expo-font
```

Example structure:

```text
assets/
└── fonts/
    └── Inter-Regular.ttf
```

### Complete example

**File:** `app/_layout.js`

```jsx
import { Stack } from "expo-router";
import * as SplashScreen from "expo-splash-screen";
import { useEffect } from "react";
import { useFonts } from "expo-font";

SplashScreen.preventAutoHideAsync().catch(console.warn);

export default function RootLayout() {
  const [loaded, error] = useFonts({
    Inter: require("../assets/fonts/Inter-Regular.ttf")
  });

  useEffect(() => {
    if (loaded || error) {
      SplashScreen.hide();
    }
  }, [loaded, error]);

  if (!loaded && !error) {
    return null;
  }

  return <Stack />;
}
```

### Explanation

**Load the font**

```jsx
const [loaded, error] = useFonts({
  Inter: require("../assets/fonts/Inter-Regular.ttf")
});
```

- `loaded` indicates that the font has loaded.
- `error` indicates that font loading failed.

**Wait while the font is loading**

```jsx
if (!loaded && !error) {
  return null;
}
```

The root layout waits until the font is loaded or an error occurs.

**Hide the splash screen**

```jsx
if (loaded || error) {
  SplashScreen.hide();
}
```

The splash screen is hidden when the font loads successfully or when loading fails.

Handling errors is important because a failed font load should not leave the splash screen visible forever.

Replace the example font path with the actual font file in your project.

## 2. Load Essential API Data

Sometimes an application needs a small amount of initial data before its first screen can be displayed.

For example, an application may need to retrieve configuration required to initialize its dashboard.

```jsx
import { Stack } from "expo-router";
import * as SplashScreen from "expo-splash-screen";
import { useEffect, useState } from "react";

SplashScreen.preventAutoHideAsync().catch(console.warn);

export default function RootLayout() {
  const [isReady, setIsReady] = useState(false);

  useEffect(() => {
    async function prepareApp() {
      try {
        const response = await fetch(
          "https://jsonplaceholder.typicode.com/posts/1"
        );

        if (!response.ok) {
          throw new Error("Failed to load startup data");
        }

        const data = await response.json();

        console.log("Startup data:", data);
      } catch (error) {
        console.warn("Could not load startup data:", error);
      } finally {
        setIsReady(true);
      }
    }

    prepareApp();
  }, []);

  useEffect(() => {
    if (isReady) {
      SplashScreen.hide();
    }
  }, [isReady]);

  if (!isReady) {
    return null;
  }

  return <Stack />;
}
```

### Startup sequence

1. Prevent the splash screen from hiding automatically.
2. Request data from the sample API.
3. Check whether the response was successful.
4. Parse the response as JSON.
5. Log any errors.
6. Mark initialization as complete.
7. Hide the splash screen and render the route navigator.

This example demonstrates the startup flow. The returned data is logged, not stored for use by the dashboard.

**Production best practice:** Avoid blocking the entire application while large or optional requests complete. For essential network requests, consider timeouts, cached data, and a fallback experience when the device is offline.

# Part 8 — Dark Mode, Troubleshooting, and Best Practices

## 1. Configure Light and Dark Splash Screens

Some users prefer a light interface, while others use dark mode.

Expo supports different splash screen backgrounds and images for the two device themes.

### Example configuration

**File:** `app.json`

```json
{
  "expo": {
    "plugins": [
      [
        "expo-splash-screen",
        {
          "backgroundColor": "#ffffff",
          "image": "./assets/images/splash-icon.png",
          "imageWidth": 200,
          "resizeMode": "contain",
          "dark": {
            "backgroundColor": "#000000",
            "image": "./assets/images/splash-icon-dark.png"
          }
        }
      ]
    ]
  }
}
```

### How does it work?

**Light appearance:** A white background with the regular logo.

**Dark appearance:** A black background with the dark-mode logo.

Make sure both images exist at their configured paths.

A separate logo is useful when the regular artwork does not contrast well with the dark background.
