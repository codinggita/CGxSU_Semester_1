
# Assignment 1: Storage Inspector Pro

## Overview

Build a **Storage Inspector Pro** application using React Native and Expo's modern `expo-file-system` API.

The application should work like a small local file manager. Users should be able to create, organize, search, inspect, rename, and delete text files stored inside the app's document directory.

Along with file management, the application should display device storage information and help users understand where their app files are stored.

This assignment combines file-system operations, React state management, UI design, validation, and error handling.

---

# Application Requirements

## 1. Dashboard Header

Create a dashboard with the following elements:

- App title: **Storage Inspector Pro**
- A short description explaining that files are stored locally.
- A **Refresh** button.
- A loading indicator while refreshing.

### Expected Behavior

When the user presses Refresh:

1. Load the latest device storage information.
2. Reload the files from the app's workspace.
3. Update the UI with the latest information.
4. Display a friendly error message if something fails.

Prevent repeated refresh actions while a refresh is already in progress.

---

## 2. Device Storage Summary

Display the following information:

- Total internal disk space.
- Available internal disk space.
- Used storage.
- Used storage percentage.

Calculate used storage using:

```js
const usedStorage = totalStorage - availableStorage;
```

Calculate the percentage using:

```js
const usedPercentage =
  totalStorage > 0
    ? (usedStorage / totalStorage) * 100
    : 0;
```

### Requirements

- Convert byte values to GB.
- Format values to two decimal places.
- Display used storage as a percentage.
- Add a progress bar representing used versus available storage.
- Handle unavailable or missing storage information gracefully.

**Important:** Device-wide storage and the size of files created by this app are different values. Display them separately and label them clearly.

---

## 3. App Document Workspace

Use `Paths.document` as the root location for files created by the application.

Create the following directory structure:

```text
document/
└── StorageInspector/
    ├── Notes/
    └── Reports/
```

### Requirements

- Create the workspace directory if it does not exist.
- Create the `Notes` and `Reports` subdirectories if needed.
- Display the workspace URI.
- Display the URI of each subdirectory.
- Show the files inside each directory separately.
- Show an empty-state message if a folder contains no files.

Use the documented `Directory` and `File` APIs.

Do not hard-code Android or iOS physical paths.

## 4. Create a Text File

Create a form that allows users to create a text file.

### Form Fields

- File name
- File content
- Destination folder:
  - Notes
  - Reports

### Example

```text
File Name: React Native Notes
Content: Today we learned about Expo File System.
Destination: Notes
```

The application should create:

```text
Notes/React Native Notes.txt
```

### Validation Requirements

- File name cannot be empty.
- Trim leading and trailing whitespace.
- Add `.txt` automatically if the extension is missing.
- Prevent invalid or unsafe path characters.
- Prevent duplicate file names inside the selected folder.
- Display validation messages near the relevant inputs.

### After Successful Creation

- Clear the form.
- Refresh the file list.
- Display a success message.
- Keep the user on the dashboard.

---

## 5. File List, Search, and Sorting

Display all files inside the `Notes` and `Reports` folders.

For each file, show:

- File name
- File size
- Last modified date, if available
- Folder name
- Actions to view, rename, and delete the file

### Search

Add a search input that allows users to search files by name.

Example:

```text
Search: React
```

The result should display files whose names match the search query.

### Folder Filter

Provide a filter with these options:

- All Files
- Notes
- Reports

### Sorting

Provide the following sorting options:

- Name: A–Z
- Size: Largest first
- Recently modified, if metadata is available

### Additional Requirements

- Display the total number of matching files.
- Add a Clear Filters button.
- Show a message when no files match the search.
- Search and sorting must not modify the actual files.

---

## 6. File Details and Content Viewer

When the user selects a file, open a details screen, modal, or bottom sheet.

Display:

- File name
- Folder name
- File URI
- File size
- Last modified date, if available
- File content

### Required Actions

#### Reload Content

Read the latest content from the file system and update the viewer.

#### Close Details

Return to the dashboard without changing the file.

### Error Handling

If the file cannot be read:

- Display a friendly error message.
- Do not crash the application.
- Allow the user to retry reading the file.

Do not assume that optional metadata fields are always available.

## 7. Rename a File

Allow users to rename an existing file.

### Requirements

- Provide a Rename action.
- Show an input containing the current file name.
- Validate that the new name is not empty.
- Add `.txt` if the extension is missing.
- Prevent duplicate names in the same folder.
- Keep the file in its current folder.
- Refresh the file list after a successful rename.
- Update the selected-file details if the file is currently open.

### Example

Before:

```text
Notes/React Notes.txt
```

After:

```text
Notes/React Native Notes.txt
```

Display a success or error message based on the result.

---

## 8. Delete a File

Allow users to delete a file from the workspace.

### Requirements

- Add a Delete button to each file.
- Ask for confirmation before deleting.
- Delete only the selected file.
- Refresh the file list after successful deletion.
- Close the details view if the deleted file is currently open.
- Handle deletion failures gracefully.

### Example Confirmation

```text
Are you sure you want to delete
"React Native Notes.txt"?
```

Buttons:

- Cancel
- Delete

## 9. Copy File and Folder URIs

Add a Copy URI button for:

- Workspace directory
- Notes directory
- Reports directory
- Individual files

Use the clipboard API if it has been covered in the course.

### Expected Behavior

1. User presses Copy URI.
2. The URI is copied to the clipboard.
3. A success message is displayed.

This feature can be implemented as a bonus if clipboard functionality has not yet been covered.

---

## 10. File Size and Workspace Summary

Display a summary of files stored inside the app's workspace.

Show:

- Total number of files.
- Number of files in Notes.
- Number of files in Reports.
- Combined size of the files in the workspace.

### Important

Keep these values separate:

| Information | Meaning |
|---|---|
| Device used storage | Total device storage minus available storage |
| Workspace file size | Combined size of files managed by this application |

Do not present workspace file size as the device's total used storage.
