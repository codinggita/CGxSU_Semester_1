# Expo Network (`expo-network`) 

---

# What is `expo-network`?

`expo-network` is an Expo SDK library for reading information about the device's network.

It can tell an application things such as:

-   whether an active network connection exists

-   whether internet connectivity is reachable

-   what type of network is active

-   the current IPv4 address

-   whether airplane mode is enabled on supported platforms

-   when network state changes

The main import is:

``` js

import * as Network from "expo-network";

```

The current documented public API surface includes:

``` text

useNetworkState()

getNetworkStateAsync()

getIpAddressAsync()

isAirplaneModeEnabledAsync()

addNetworkStateListener()

NetworkState

NetworkStateEvent

NetworkStateType

```

## Simple meaning

Think of `expo-network` as a ****network information assistant**** inside your application.

Your app can ask questions such as:

``` text

"Is the device connected to a network?"

"Is the internet reachable?"

"Is the user on Wi-Fi or mobile data?"

"What is the current IPv4 address?"

"Did the network connection change?"

"Is airplane mode enabled?"

```

It does ****not**** mean that `expo-network` itself performs your API requests.

For example:

``` js

fetch("https://example.com/api/products");

```

is still responsible for making an HTTP request.

`expo-network` gives your application useful information **about the current network situation**.

---

# Why do we need network information?

Modern mobile applications frequently depend on a network.

Examples:

-   Login

-   Fetching products

-   Loading user profiles

-   Sending messages

-   Uploading images

-   Downloading files

-   Synchronizing data

-   Calling REST APIs

-   Calling GraphQL APIs

-   Loading remote configuration

Suppose your application does:

``` js

fetch("https://example.com/api/products");

```

If the phone is offline, the request may fail.

A better application can first understand the network situation:

``` text

Is there an active connection?

        ↓

Is internet reachable?

        ↓

What type of connection is active?

        ↓

Perform the network-dependent operation

```

This allows us to build:

-   offline banners

-   retry systems

-   network status screens

-   connection indicators

-   Wi-Fi/mobile-data indicators

-   better error messages

-   network debugging tools

-   conditional downloads

-   synchronization systems

-   offline-first experiences

## Real-world example

Imagine a food delivery application.

The user opens the app without internet.

A poor experience might show:

``` text

Something went wrong.

```

The user does not know why.

A better experience can show:

``` text

You are offline.

Please connect to the internet and try again.

```

Even better:

``` text

You're offline.

Your previously loaded restaurants are still available.

We'll sync when you're back online.

```

Network awareness helps create this kind of experience.

# Part 1 - Installation and Setup

## 1.1 Create an Expo project

If you are starting from a new application:

``` bash

npx create-expo-app@latest network-demo

cd network-demo

npx expo start

```

You can then run the application using your normal Expo development

workflow.

---

## 1.2 Install `expo-network`

Install the package using:

``` bash

npx expo install expo-network

```

Other supported package-manager forms include:

``` bash

yarn expo install expo-network

```

``` bash

pnpm expo install expo-network

```

``` bash

bun expo install expo-network

```

### Why prefer `expo install`?

Expo projects contain a particular Expo SDK version.

Using:

``` bash

npx expo install expo-network

```

allows Expo to select a package version compatible with the project's SDK.

Instead of manually guessing:

``` bash

npm install expo-network@some-version

```

prefer the Expo installation command for Expo projects.

---

## 1.3 Import the module

After installation:

``` js

import * as Network from "expo-network";

```

The `* as Network` syntax gives us an object containing the APIs provided by the package.

For example:

``` js

Network.useNetworkState()

Network.getNetworkStateAsync()

Network.getIpAddressAsync()

```

---

## 1.4 Android permissions

Expo documents that Android requires access to network and Wi-Fi state.

The following permissions are added automatically:

``` text

ACCESS_NETWORK_STATE

ACCESS_WIFI_STATE

```

Normally, an Expo application using the package does not need to manually add these permissions.

---

## 1.5 First example

Let's start with the smallest useful example:

``` jsx

import { View, Text, Button } from "react-native";

import * as Network from "expo-network";

export default function App() {

  const checkNetwork = async () => {

    const state = await Network.getNetworkStateAsync();

    console.log(state);

  };

  return (

    <View>

      <Text>Network Demo</Text>

      <Button

        title="Check Network"

        onPress={checkNetwork}

      />

    </View>

  );

}

```

### What happens?

When the user presses the button:

``` text

Button pressed

      ↓

checkNetwork()

      ↓

getNetworkStateAsync()

      ↓

NetworkState returned

      ↓

console.log()

```

The returned object contains network information.

For example, conceptually:

``` js

{

  type: "WIFI",

  isConnected: true,

  isInternetReachable: true

}

```

The exact values depend on the device's current network situation.

# Part 2 - Understanding Network Concepts

Before writing more code, we need to understand what a network actually means.

---

## 2.1 What is a network?

A network allows a device to communicate with another device or service.

A common flow is:

``` text

Phone

  ↓

Wi-Fi Router

  ↓

Internet

  ↓

API Server

```

For example, when a mobile app requests products:

``` text

React Native App

       ↓

     Router

       ↓

    Internet

       ↓

   Backend API

       ↓

    Database

```

The database is usually not directly accessed by the mobile application.

A backend server sits between the app and the database.

---

## 2.2 Network vs Internet

These terms are related, but they are not exactly the same.

### Network

A network is a communication system connecting devices.

For example:

``` text

Phone

  ↓

Wi-Fi Router

```

The phone can be connected to the router.

### Internet

The internet is a huge global network connecting many networks and services.

For example:

``` text

Phone

  ↓

Wi-Fi Router

  ↓

Internet

  ↓

Google / API / Server

```

### Important

A device can be connected to a network without having working internet access.

---

## 2.3 Wi-Fi does not automatically mean internet

Consider this situation:

``` text

Phone

  ↓

Wi-Fi Router

  X

Internet

```

The phone may still display:

``` text

Wi-Fi connected

```

but internet access may not work.

This is one of the most important concepts when learning `expo-network`.

---

## 2.4 `isConnected`

`isConnected` represents whether an active network connection exists.

Conceptually:

``` text

true

↓

An active network connection exists.

false

↓

No active network connection detected.

```

Expo documents that this value is false when the network type is `NONE` or `UNKNOWN`, and true otherwise.

### Example

``` js

const state = await Network.getNetworkStateAsync();

console.log(state.isConnected);

```

Possible result:

``` text

true

```

or:

``` text

false

```

---

## 2.5 `isInternetReachable`

`isInternetReachable` represents whether the internet is reachable through the currently active network connection.

For example:

``` js

{

  isConnected: true,

  isInternetReachable: false

}

```

means conceptually:

``` text

Device

  ↓

Connected to a network 

Internet

  ↓

Not currently reachable 

```

This can happen when a Wi-Fi network is available but the router has lost internet connectivity.

### Android implementation detail

On current Expo documentation, Android considers internet reachability using the active network's internet capability, validated internet access, and a usable connection state. VPN connections also require non-zero downstream bandwidth.

Conceptually:

``` text
Active network
      ↓
Internet capability
      ↓
Internet validated
      ↓
Usable connection
      ↓
isInternetReachable = true
```

This is an implementation detail. In normal application code, use the returned boolean instead of trying to reproduce the platform checks yourself.

---

## 2.6 `type`

`type` represents the current network type.

Examples include:

``` text

WIFI

CELLULAR

ETHERNET

VPN

NONE

UNKNOWN

```

You can read it with:

``` js

const state = await Network.getNetworkStateAsync();

console.log(state.type);

```

---

## 2.7 The three-field mental model

Remember:

``` text

NetworkState

│

├── isConnected

│   └── Does an active network connection exist?

│

├── isInternetReachable

│   └── Is internet connectivity reachable?

│

└── type

    └── What kind of network is active?

```

Whenever students see a `NetworkState` object, they should immediately think:

``` text

CONNECTED?

INTERNET?

TYPE?

```

---

## 2.8 Four common scenarios

### Scenario 1 - Wi-Fi with internet

``` text

type = WIFI

isConnected = true

isInternetReachable = true

```

Meaning:

``` text

Wi-Fi connected

Internet reachable

```

---

### Scenario 2 - Wi-Fi without internet

``` text

type = WIFI

isConnected = true

isInternetReachable = false

```

Meaning:

``` text

Connected to Wi-Fi

But internet is unavailable

```

---

### Scenario 3 - No network

``` text

type = NONE

isConnected = false

```

Meaning:

``` text

No active network connection

```

---

### Scenario 4 - Mobile data

``` text

type = CELLULAR

isConnected = true

```

Meaning:

``` text

Device is connected through cellular/mobile data.

```

The exact value of `isInternetReachable` should be treated according to

the platform and current network conditions.

---

## 2.9 Network status is not API success

This is extremely important.

Even if:

``` js

isConnected === true

```

your API request can still fail.

Possible reasons:

-   server is down

-   DNS fails

-   request times out

-   authentication fails

-   backend returns an error

-   TLS/network problems occur

-   endpoint does not exist

-   request is rejected

-   server returns `500`

-   server returns `401`

-   server returns `403`

Therefore:

``` text

Network state

```

and:

``` text

Request success

```

are different things.

### Example

``` text

isConnected = true

       ↓

fetch("/products")

       ↓

Server returns 500

       ↓

API request failed

```

So:

> Network information is a useful signal, not a guarantee that every API

> request will succeed.

---

## 2.10 Network check vs API check

Think of these as two different questions.

### Network check

``` text

Can the device currently access a network?

```

### API check

``` text

Did my particular request succeed?

```

A good application may use both.

``` text

Network State

     ↓

Should we attempt the request?

     ↓

API Request

     ↓

Did the server respond successfully?

```

# Part 3 - `useNetworkState()`

## 3.1 What is the hook?

`useNetworkState()` is a React hook that returns the current network state.

Expo documents that it initiates a listener for network changes and cleans it up when the component unmounts.

This makes it especially useful for UI.

---

## 3.2 Basic example

``` jsx

import { View, Text } from "react-native";

import * as Network from "expo-network";

export default function App() {

  const state = Network.useNetworkState();

  return (

    <View>

      <Text>Type: {state.type}</Text>

      <Text>

        Connected: {String(state.isConnected)}

      </Text>

      <Text>

        Internet Reachable:

        {String(state.isInternetReachable)}

      </Text>

    </View>

  );

}

```

---

## 3.3 Why is it called a hook?

Because it follows React's hook model.

It can be used inside a React component:

``` js

const state = Network.useNetworkState();

```

The hook gives the component network information.

When the network changes, the hook can provide updated state so React can render the updated UI.

---

## 3.4 Mental model

``` text

Component mounts

      ↓

useNetworkState()

      ↓

Current network state

      ↓

Network changes

      ↓

Hook receives updated state

      ↓

React UI updates

```

This is why the hook is useful for screens that need to **continuously display network status**.

---

## 3.5 Show online/offline UI

``` jsx

const state = Network.useNetworkState();

const online =

  state.isConnected === true &&

  state.isInternetReachable === true;

return (

  <Text>

    {online ? "You are online" : "You are offline"}

  </Text>

);

```

### Why use both?

Because:

``` js

isConnected === true

```

does not necessarily mean:

``` js

isInternetReachable === true

```

---

## 3.6 A more user-friendly status

``` jsx

const state = Network.useNetworkState();

let message = "Checking network...";

if (

  state.isConnected === true &&

  state.isInternetReachable === true

) {

  message = "You are online";

} else if (state.isConnected === true) {

  message = "Connected, but internet may be unavailable";

} else {

  message = "You are offline";

}

return <Text>{message}</Text>;

```

This gives the user more useful information than simply showing `"Offline"`.

---

## 3.7 Show network type

``` jsx

<Text>

  Network Type: {state.type ?? "Unknown"}

</Text>

```

Possible display:

``` text

Network Type: WIFI

```

or:

``` text

Network Type: CELLULAR

```

---

## 3.8 Wi-Fi detection

``` js

if (state.type === "WIFI") {

  console.log("Using Wi-Fi");

}

```

---

## 3.9 Cellular detection

``` js

if (state.type === "CELLULAR") {

  console.log("Using mobile data");

}

```

---

## 3.10 Conditional UI based on network

``` jsx

if (state.type === "CELLULAR") {

  return <Text>You are using mobile data.</Text>;

}

if (state.type === "WIFI") {

  return <Text>You are using Wi-Fi.</Text>;

}

return <Text>Network type is unknown.</Text>;

```

---

## 3.11 When should we use the hook?

Use `useNetworkState()` when the **React UI needs to react to network changes**.

Good use cases:

-   online/offline banner

-   network status screen

-   disabling/enabling UI

-   displaying Wi-Fi/mobile data

-   showing connection state

-   reacting immediately when connectivity changes

# Part 4 - `getNetworkStateAsync()`

## 4.1 What does it do?

It gets the current network connection state.

Return type:

``` text

Promise<NetworkState>

```

Because it is asynchronous, use:

``` js

await

```

inside an async function.

---

## 4.2 Basic example

``` js

const state = await Network.getNetworkStateAsync();

console.log(state);

```

---

## 4.3 Complete example

``` jsx

import { useState } from "react";

import { View, Text, Button } from "react-native";

import * as Network from "expo-network";

export default function App() {

  const [state, setState] = useState(null);

  const checkNetwork = async () => {

    try {

      const result = await Network.getNetworkStateAsync();

      setState(result);

    } catch (error) {

      console.error("Network error:", error);

    }

  };

  return (

    <View>

      <Button

        title="Check Network"

        onPress={checkNetwork}

      />

      {state && (

        <>

          <Text>Type: {state.type}</Text>

          <Text>

            Connected: {String(state.isConnected)}

          </Text>

          <Text>

            Internet Reachable:

            {String(state.isInternetReachable)}

          </Text>

        </>

      )}

    </View>

  );

}

```

---

## 4.4 When should we use it?

Use `getNetworkStateAsync()` when you need a ****current snapshot****.

For example:

``` text

Button pressed

      ↓

Get current network state

      ↓

Make a decision

```

For continuously updating React UI, `useNetworkState()` is often more convenient.

---

## 4.5 Hook vs async function

### `useNetworkState()`

Think:

``` text

"Keep my UI informed about network changes."

```

### `getNetworkStateAsync()`

Think:

``` text

"Tell me the network state right now."

```

# Part 5 - `getIpAddressAsync()`

## 5.1 What is an IP address?

An IP address is a network address associated with a network interface.

Example IPv4:

``` text

192.168.1.20

```

You can think of it as an address used in network communication.

### Important

An IP address is ****not the same thing as your device name****.

For example:

``` text

Device name:

Rajesh's iPhone

IP address:

192.168.1.20

```

These represent different concepts.

---

## 5.2 Basic example

``` js

const ip = await Network.getIpAddressAsync();

console.log(ip);

```

Return type:

``` text

Promise<string>

```

---

## 5.3 Example component

``` jsx

import { useState } from "react";

import { View, Text, Button } from "react-native";

import * as Network from "expo-network";

export default function App() {

  const [ip, setIp] = useState("");

  const loadIp = async () => {

    try {

      const result = await Network.getIpAddressAsync();

      setIp(result);

    } catch (error) {

      console.error(error);

    }

  };

  return (

    <View>

      <Button

        title="Get IP"

        onPress={loadIp}

      />

      <Text>

        IP: {ip || "Not loaded"}

      </Text>

    </View>

  );

}

```

---

## 5.4 Failed retrieval

Expo documents:

``` text

0.0.0.0

```

when the IP address cannot be retrieved.

Therefore, do not assume every returned value represents a useful device address.

For example:

``` js

const ip = await Network.getIpAddressAsync();

if (ip === "0.0.0.0") {

  console.log("Could not retrieve a useful IP address");

}

```

---

## 5.5 Native behavior vs web behavior

On web, Expo documents that this method uses the third-party `ipify` service to obtain the public IP address of the current device.

This is important:

``` text

Native behavior

      ≠

Web behavior

```

A developer should always check platform-specific behavior before

building logic around network information.

---

## 5.6 Is IP address the same as internet?

No.

A device can have an IP address and still have problems reaching a particular internet service.

For example:

``` text

Device has IP

      ↓

Network exists

      ↓

API server unavailable

      ↓

Request fails

```

So:

``` text

IP address

```

does not automatically mean:

``` text

Internet is working perfectly

```

# Part 6 - `isAirplaneModeEnabledAsync()`

## 6.1 What does it do?

It checks whether the device is in airplane mode.

``` js

const enabled =

  await Network.isAirplaneModeEnabledAsync();

```

Return type:

``` text

Promise<boolean>

```

Possible results:

``` text

true

false

```

---

## 6.2 Example

``` jsx

import { useState } from "react";

import { View, Text, Button } from "react-native";

import * as Network from "expo-network";

export default function App() {

  const [enabled, setEnabled] = useState(null);

  const check = async () => {

    const result =

      await Network.isAirplaneModeEnabledAsync();

    setEnabled(result);

  };

  return (

    <View>

      <Button

        title="Check Airplane Mode"

        onPress={check}

      />

      <Text>

        Airplane Mode:

        {enabled === null

          ? "Unknown"

          : String(enabled)}

      </Text>

    </View>

  );

}

```

---

## 6.3 Understanding the boolean

If:

``` js

enabled === true

```

then:

``` text

Airplane mode is enabled.

```

If:

``` js

enabled === false

```

then:

``` text

Airplane mode is not enabled.

```

---

## 6.4 Platform note

The Expo API documentation marks this method as Android-only.

Do not assume it has identical support on all platforms.

### Classroom rule

Whenever an API has platform restrictions, students should check:

``` text

Android

iOS

Web

tvOS

```

before depending on it in production code.

# Part 7 - Network State Listener

## 7.1 What is an event listener?

An event listener waits for something to change.

For network state:

``` text

Network changes

      ↓

Listener receives event

      ↓

Callback executes

```

Instead of repeatedly asking:

``` text

"Did the network change?"

"Did the network change?"

"Did the network change?"

```

we subscribe to changes.

---

## 7.2 `addNetworkStateListener()`

``` js

const subscription =

  Network.addNetworkStateListener((state) => {

    console.log(state);

  });

```

The callback receives updated network information.

---

## 7.3 Read event properties

``` js

const subscription =

  Network.addNetworkStateListener(

    ({ type, isConnected, isInternetReachable }) => {

      console.log("Type:", type);

      console.log("Connected:", isConnected);

      console.log("Internet:", isInternetReachable);

    }

  );

```

---

## 7.4 Subscription cleanup

The returned object has a `remove()` method:

``` js

subscription.remove();

```

This is important because a subscription should not remain active after the component no longer needs it.

---

## 7.5 React `useEffect`

``` jsx

import { useEffect } from "react";

import * as Network from "expo-network";

export default function App() {

  useEffect(() => {

    const subscription =

      Network.addNetworkStateListener((state) => {

        console.log("Network changed:", state);

      });

    return () => {

      subscription.remove();

    };

  }, []);

  return null;

}

```

---

## 7.6 Why cleanup matters

Without cleanup, you can accidentally keep old listeners alive.

Conceptually:

``` text

Listener 1

Listener 2

Listener 3

...

```

One network change could then trigger multiple callbacks.

The correct lifecycle is:

``` text

Mount

  ↓

Subscribe

  ↓

Receive changes

  ↓

Unmount

  ↓

Remove subscription

```

---

## 7.7 Listener vs hook

Both can respond to network changes.

### Hook

``` js

const state = Network.useNetworkState();

```

Best when:

``` text

Network state

     ↓

React UI

```

### Listener

``` js

Network.addNetworkStateListener(...)

```

Useful when:

``` text

Network change

     ↓

Run custom logic

```

For example:

``` text

Network becomes available

        ↓

Start synchronization

```

or:

``` text

Network becomes unavailable

        ↓

Pause upload

```

---

## 7.8 Example: logging network changes

``` jsx

useEffect(() => {

  const subscription =

    Network.addNetworkStateListener((state) => {

      console.log("Network type:", state.type);

      console.log("Connected:", state.isConnected);

      console.log(

        "Internet:",

        state.isInternetReachable

      );

    });

  return () => subscription.remove();

}, []);

```

# Part 8 - `NetworkState`

`NetworkState` is the object representing current network state.

Its documented properties are:

``` text

isConnected

isInternetReachable

type

```

---

## 8.1 `isConnected`

Type:

``` ts

boolean

```

Meaning:

``` text

An active network connection exists.

```

Important:

``` text

connected != guaranteed internet access

```

---

## 8.2 `isInternetReachable`

Type:

``` ts

boolean

```

Meaning:

``` text

Internet is reachable through the currently active connection.

```

Expo documents platform-specific implementation details for this value.

On iOS, Expo documents that this value is always the same as `isConnected`.

---

## 8.3 `type`

Type:

``` ts

NetworkStateType

```

It describes the current network connection type.

Example:

``` js

{

  type: "WIFI",

  isConnected: true,

  isInternetReachable: true

}

```

---

## 8.4 Safe UI handling

Network information can sometimes be unavailable or unknown.

Therefore, UI code should avoid assuming every value is always a perfect string/boolean.

For example:

``` jsx

<Text>

  Type: {state.type ?? "Unknown"}

</Text>

```

For boolean-like values:

``` jsx

<Text>

  Connected: {String(state.isConnected)}

</Text>

```

# Part 9 - `NetworkStateEvent`

`NetworkStateEvent` represents the updated network state supplied when a network-state event occurs.

In the latest Expo documentation, `NetworkStateEvent` is typed as `NetworkState`. It is therefore better to think of it as **the network-state object delivered to a listener when the network changes**, rather than as a completely separate data structure.

It is passed to:

``` js

Network.addNetworkStateListener(...)

```

Example:

``` js

Network.addNetworkStateListener((event) => {

  console.log(event.type);

  console.log(event.isConnected);

  console.log(event.isInternetReachable);

});

```

Think:

``` text

Network change

      ↓

NetworkStateEvent

      ↓

Listener callback

```

---

## 9.1 Why have an event object?

Instead of sending three separate values:

``` text

type

isConnected

isInternetReachable

```

the event gives us a structured object.

That makes it easier to pass around and destructure:

``` js

({ type, isConnected, isInternetReachable }) => {

  // ...

}

```

---

## 9.2 Destructuring example

``` js

Network.addNetworkStateListener(

  ({ type, isConnected }) => {

    console.log(type);

    console.log(isConnected);

  }

);

```

This is simply JavaScript object destructuring.

# Part 11 - Platform Differences

Cross-platform does not mean identical behavior on every platform.

Always consider:

``` text

Android

iOS

tvOS

Web

```

---

## Android

The package supports Android and provides Android-specific network behavior.

Android automatically receives the documented network/Wi-Fi state permissions.

---

## iOS

Network state is supported.

Expo documents an important detail:

``` text

isInternetReachable

```

is always the same as:

``` text

isConnected

```

on iOS.

Therefore, do not build platform-independent assumptions that depend on those two values being meaningfully different on iOS.

---

## tvOS

Network-state APIs are documented as supported where indicated by the Expo platform badges.

---

## Web

Web has additional limitations.

For `getNetworkStateAsync()`, Expo documents:

``` text

active network connection → type = UNKNOWN

no active network connection → type = NONE

```

because:

``` text

navigator.connection.type

```

is not available in browsers in the same way native platforms expose network types.

For `getIpAddressAsync()`, Expo documents use of the third-party `ipify` service to obtain the public IP.

The lesson:

``` text

Cross-platform API

       does not mean

identical native behavior.

```

---

## 11.1 Network type platform availability

The documented platform availability of the network types is useful to remember:

| Network type | Android | iOS | tvOS | Web |
|---|---|---|---|---|
| `BLUETOOTH` | Yes | No | No | No |
| `CELLULAR` | Yes | Yes | No | No |
| `ETHERNET` | Yes | Yes | No | No |
| `NONE` | Yes | Yes | Yes | Yes |
| `OTHER` | Yes | No | No | No |
| `UNKNOWN` | Yes | Yes | Yes | Yes |
| `VPN` | Yes | No | No | No |
| `WIFI` | Yes | Yes | No | No |
| `WIMAX` | Yes | No | No | No |

> The table above describes the platform badges exposed by the current Expo documentation. Treat `UNKNOWN` as a valid result instead of assuming that every platform can identify a detailed network type.

## 11.2 Why platform differences matter

Imagine your code says:

``` js

if (state.type === "WIFI") {

  downloadLargeFile();

}

```

This may work differently across platforms because the available network type information can differ.

Therefore:

> Network-dependent logic should be designed with platform behavior in

> mind.

# Part 12 - Error Codes

Expo documents several error codes associated with network operations. These are especially useful when debugging failures from the native network layer.

## 12.1 Documented error codes

| Error code | Meaning |
|---|---|
| `ERR_NETWORK_IP_ADDRESS` | On Android, there may be an unknown Wi-Fi host while accessing `WifiManager` during `getIpAddressAsync()`. On iOS, no network interfaces could be retrieved. |
| `ERR_NETWORK_UNDEFINED_INTERFACE` | An undefined `interfaceName` was passed to the MAC-address operation referenced by the Expo error documentation. |
| `ERR_NETWORK_SOCKET_EXCEPTION` | An error occurred while creating or accessing the socket for the MAC-address operation referenced by the Expo error documentation. |
| `ERR_NETWORK_INVALID_PERMISSION_INTERNET` | Invalid Android `ACCESS_WIFI_STATE` permission information was encountered by the MAC-address operation referenced by the Expo error documentation. |
| `ERR_NETWORK_NO_ACCESS_NETWORKINFO` | The native network information could not be accessed. |

### 12.2 Handling errors in application code

When calling an asynchronous network API, use `try...catch` when the operation can fail:

``` js
try {
  const ip = await Network.getIpAddressAsync();
  console.log("IP:", ip);
} catch (error) {
  console.error("Network operation failed:", error);
}
```

If you need to diagnose a specific Expo error, inspect the error object and its message/code rather than assuming that every failure means the device is offline.

### 12.3 Important distinction

A native API error and an offline network state are not the same thing:

``` text
Network state
      ↓
Does the device have a network?

Native API error
      ↓
Did the network information operation itself fail?
```

A device may have a network connection and still encounter an error while a particular native network-information operation is being performed.
