# React Native Debugging

## 1. What is Debugging?

Debugging is the process of identifying, analysing, and fixing errors (bugs) in an application.

While developing a React Native application, developers often encounter problems such as:

* Application crashes unexpectedly
* Buttons do not perform the expected actions
* API requests fail
* Variables contain unexpected values
* Components do not render correctly
* Application becomes slow
* Functions return incorrect results

Debugging helps developers understand what went wrong, where the problem occurred, and how to fix it.

Instead of randomly changing code, developers use debugging tools to inspect the application's execution and identify the actual cause of a problem.

---

## 2. Why do we need Debugging?

Every application contains complex logic, components, API requests, and state management.

Even a small mistake in the code can cause unexpected behaviour.

Debugging helps developers:

* Identify syntax and runtime errors
* Find logical mistakes in JavaScript code
* Inspect variable values during execution
* Understand how functions are executed
* Identify problems in API requests
* Understand component rendering issues
* Analyse application performance
* Fix errors without unnecessarily changing working code

Without debugging, developers may spend a lot of time trying to understand why an application is not working correctly.

## 4. Types of Errors in JavaScript

Before learning debugging tools, we should understand the different types of errors that can occur in JavaScript applications.

### 1. Syntax Errors

Syntax errors occur when JavaScript code does not follow the correct syntax rules.

**Example**

```js
const username = "Rajesh";

console.log(username;
```

**Problem:** The closing parenthesis is missing.

**Correct Code**

```js
const username = "Rajesh";

console.log(username);
```

---

### 2. Runtime Errors

Runtime errors occur while the application is executing.

**Example**

```js
const user = null;

console.log(user.name);
```

**Error**

```text
TypeError: Cannot read properties of null
```

**Problem:** We are trying to access a property of a null value.

**Correct Code**

```js
const user = null;

console.log(user?.name);
```

---

### 3. Logical Errors

Logical errors occur when code executes successfully but produces an incorrect result.

**Example**

```js
function calculateTotal(price, quantity) {
  const total = price + quantity;

  return total;
}

console.log(calculateTotal(500, 3));
```

**Actual Output**

```text
503
```

**Expected Output**

```text
1500
```

**Problem:** We used addition instead of multiplication.

**Correct Code**

```js
function calculateTotal(price, quantity) {
  const total = price * quantity;

  return total;
}

console.log(calculateTotal(500, 3));
```

## 6. React Native Dev Menu

### What is React Native Dev Menu?

React Native Dev Menu (Developer Menu) is an in-app menu that provides access to various development and debugging features.

It helps developers perform different development-related tasks without modifying the application code.

Using Dev Menu, developers can:

* Open React Native DevTools
* Reload the application
* Access debugging options
* Open Performance Monitor
* Access other development features

Think of it as a control panel for developers while working on a React Native application.

---

### How to Open Dev Menu?

React Native provides different ways to open the Developer Menu depending on the platform.

### Android Physical Device

Shake your Android device while the application is running.

### Android Emulator

|---|---|
| Windows | `Ctrl + M` |
| Linux | `Ctrl + M` |
| macOS | `Cmd + M` |

The shortcut can vary with emulator and keyboard configuration. If it does not work, use the emulator's **More (⋮) → Shake** action or the ADB method below.

### iOS Simulator

```text
Ctrl + Cmd + Z
```

You can also use the Simulator menu:

```text
Device → Shake
```

### Alternative Method for Android

You can open the Developer Menu using the ADB command:

```bash
adb shell input keyevent 82
```

---

### Important Dev Menu Options

The Developer Menu provides access to several development features.

| Option | Purpose |
|---|---|

| Open DevTools | Opens React Native DevTools |

| Other development options | Depends on the React Native environment |

### Performance Monitor vs Performance Panel

These are two different debugging features. Do not confuse them.

| Performance Monitor | Performance Panel |
|---|---|

| Shows a live performance overlay while the app runs | Records a detailed performance timeline |
| Useful for a quick overview of UI and JavaScript activity | Useful for investigating when and where work takes time |
| Provides a quick, approximate view | Provides more detailed profiling information |

The Performance Monitor is useful for an initial check. When you need to investigate a specific slow interaction or JavaScript operation, use the Performance panel. For complete native/platform performance analysis, use Android Studio Profiler or Xcode Instruments.

## 8. Console Panel

The Console panel allows developers to view and filter messages generated by their JavaScript application.

It is commonly used to:

* Display variable values.
* Check whether a function is executing.
* Identify errors and warnings.
* Inspect JavaScript objects.
* Evaluate JavaScript expressions.
* Understand application execution flow.

---

### Important Console Methods

JavaScript provides different console methods that help developers during debugging.

### 1. `console.log()`

`console.log()` is used to display normal messages and variable values.

**Example**

```js
const name = "Rajesh";
const age = 25;

console.log("Name:", name);
console.log("Age:", age);
```

**Output**

```text
Name: Rajesh
Age: 25
```

### 2. `console.warn()`

`console.warn()` is used to display warning messages.

**Example**

```js
console.warn("Please check your API response.");
```

This generates a warning message.

### 3. `console.error()`

`console.error()` is used to display error messages.

**Example**

```js
console.error("Something went wrong!");
```

This generates an error message.

### 4. `console.table()`

`console.table()` displays array or object data in a tabular format.

**Example**

```js
const students = [
  { id: 1, name: "Amit", marks: 85 },
  { id: 2, name: "Rahul", marks: 90 },
  { id: 3, name: "Neha", marks: 95 },
];

console.table(students);
```

This makes structured data easier to inspect.

### What Did We Learn?

Using console.log(), we can understand:

## 9. Sources Panel – JavaScript Debugging

### What is the Sources Panel?

The Sources panel allows developers to inspect JavaScript source files and debug code execution.

It helps developers understand what is happening internally when their application runs.

Using the Sources panel, developers can:

* View JavaScript source files.
* Add breakpoints.
* Pause JavaScript execution.
* Inspect variable values.
* Understand function execution.
* Navigate through code step by step.
* Inspect Scope and Call Stack.

The Sources panel is one of the most important tools for learning practical debugging.

---

### What is a Breakpoint?

A breakpoint is a marker placed on a specific line of code where JavaScript execution should pause.

When execution reaches that line, the debugger stops running the code temporarily.

This allows developers to inspect variables and understand the current execution state.

### Example

```js
function calculateTotal(price, quantity) {
  const subtotal = price * quantity;

  const tax = subtotal * 0.18;

  const finalAmount = subtotal + tax;

  return finalAmount;
}

const result = calculateTotal(500, 3);

console.log(result);
```

Suppose we want to inspect the value of `subtotal` before calculating tax.

We can add a breakpoint on this line:

```js
const tax = subtotal * 0.18;
```

### How to Add a Breakpoint?

1. Open React Native DevTools.
2. Navigate to the Sources panel.
3. Locate the JavaScript file.
4. Find the line where you want to pause execution.
5. Click the line number.
6. A breakpoint will appear.
7. Execute the function in your application.
8. JavaScript execution will pause when it reaches that line.

### Expected Variable Values

When execution pauses before the tax calculation:

| Variable | Value |
|---|---:|
| price | 500 |
| quantity | 3 |
| subtotal | 1500 |
| tax | Not calculated yet |
| finalAmount | Not calculated yet |

**Why are tax and finalAmount not available yet?**

Because JavaScript has not executed those statements.

This is why breakpoints are useful: they allow us to inspect the program at a particular point during execution.

---

### What is the `debugger` Statement?

The `debugger` statement allows developers to pause JavaScript execution directly from their source code.

Instead of manually adding a breakpoint in DevTools, we can write `debugger` inside a function.

### Syntax

```js
debugger;
```

### Example

```js
function calculateTotal(price, quantity) {
  const subtotal = price * quantity;

  debugger;

  const tax = subtotal * 0.18;

  const finalAmount = subtotal + tax;

  return finalAmount;
}

calculateTotal(500, 3);
```

### How Does It Work?

1. The function starts executing.
2. JavaScript calculates the subtotal.
3. Execution reaches the `debugger` statement.
4. If a compatible debugger is connected, execution pauses.
5. Developers can inspect the current variables.
6. Developers can continue execution using debugger controls.

**Important:** The debugger statement pauses execution only when a compatible debugger is attached. Remove temporary `debugger` statements before committing or releasing your code.

---

### Difference Between Breakpoint and debugger Statement

| Breakpoint | debugger Statement |
|---|---|
| Added manually in DevTools | Written directly in source code |
| Does not require changing application code | Requires adding a statement in code |
| Can be removed from DevTools | Must be removed from source code |
| Useful for debugging existing code | Useful for quickly pausing at a specific location |

---

### How to Remove a Breakpoint?

To remove a breakpoint:

1. Open the Sources panel.
2. Locate the line containing the breakpoint.
3. Click the breakpoint marker again.

The breakpoint will be removed.

---

## 10. Debugger Controls

When JavaScript execution pauses at a breakpoint, DevTools provides controls that allow developers to move through the code.

The three most important controls are:

1. Step Over
2. Step Into
3. Step Out

Let's understand them with an example.

### Example

```js
function calculateTax(amount) {
  const tax = amount * 0.18;

  return tax;
}

function calculateBill(price, quantity) {
  const subtotal = price * quantity;

  const tax = calculateTax(subtotal);

  const total = subtotal + tax;

  return total;
}

const result = calculateBill(500, 3);

console.log(result);
```

---

## 10.1 Step Over

### What is Step Over?

Step Over executes the current line and moves to the next line without entering the internal implementation of a called function.

### Example

Suppose execution is paused at:

```js
const tax = calculateTax(subtotal);
```

When you click Step Over:

* The calculateTax() function executes.
* The returned value is assigned to tax.
* Execution moves to the next line.
* You do not enter the internal statements of calculateTax().

### Execution Flow

```text
Current Line
     |
     ▼
calculateTax(subtotal)
     |
     ▼
Function Executes
     |
     ▼
Next Line
```

**When should we use Step Over?**

Use Step Over when you want to execute a function call without inspecting its internal code.

---

## 10.2 Step Into

### What is Step Into?

Step Into enters the function called on the current line.

It allows developers to inspect what happens inside that function.

### Example

Suppose execution is paused at:

```js
const tax = calculateTax(subtotal);
```

When you click Step Into:

* Execution enters calculateTax().
* You can inspect the amount parameter.
* You can execute the function line by line.
* You can understand how the tax value is calculated.

Inside the function:

```js
function calculateTax(amount) {
  const tax = amount * 0.18;

  return tax;
}
```

You can inspect:

```text
amount = 1500
tax = 270
```

### Execution Flow

```text
Current Line
     |
     ▼
calculateTax(subtotal)
     |
     ▼
Enter calculateTax()
     |
     ▼
Execute Function Line by Line
```

**When should we use Step Into?**

Use Step Into when you want to understand the internal implementation of a function.

---

## 10.3 Step Out

### What is Step Out?

Step Out continues execution until the current function returns, then pauses in the calling function (when a suitable pause location is available).

### Example

Suppose execution is paused inside:

```js
function calculateTax(amount) {
  const tax = amount * 0.18;

  return tax;
}
```

When you click Step Out:

* The remaining function code executes.
* The function returns its result.
* Execution returns to calculateBill().
* You can continue debugging the calling function.

### Execution Flow

```text
Inside calculateTax()
        |
        ▼
     Step Out
        |
        ▼
Function Completes
        |
        ▼
Return to calculateBill()
```

**When should we use Step Out?**

Use Step Out when you have finished inspecting the current function and want to return to its caller.

---

### Difference Between Step Over, Step Into and Step Out

| Feature | Purpose |
|---|---|
| Step Over | Executes the current line without entering a called function |
| Step Into | Enters the called function |
| Step Out | Finishes the current function and returns to its caller |

---

### Practical Exercise

Use the following code:

```js
function add(a, b) {
  const result = a + b;

  return result;
}

function calculateTotal(price, quantity) {
  const subtotal = price * quantity;

  const total = add(subtotal, 100);

  return total;
}

const result = calculateTotal(500, 3);

console.log(result);
```

### Tasks

1. Add a breakpoint inside calculateTotal().
2. Execute the code.
3. Use Step Over to execute the subtotal calculation.
4. Use Step Into on the add() function call.
5. Inspect the values of a and b.
6. Use Step Out to return to calculateTotal().
7. Inspect the final total.

**Expected Output**

```text
1600
```

---

### Important Note

The debugger controls work only when JavaScript execution is paused.

You can also resume execution using the Resume control after inspecting the code.

## 11. Scope in JavaScript Debugging

### What is Scope?

Scope defines where variables can be accessed in JavaScript.

When debugging an application, developers often need to inspect variable values to understand why the code is producing unexpected results.

The Scope section in React Native DevTools helps developers inspect variables available at the current execution point.

It allows us to understand:

* Which variables are available in the current function.
* What values are stored in those variables.
* Which variables belong to outer functions.
* Which variables are accessible from the global environment.

### Types of Scope

Some important scopes that developers may encounter while debugging are:

1. Local Scope
2. Closure Scope
3. Global Scope

---

## 11.1 Local Scope

### What is Local Scope?

Local Scope contains variables and parameters that are available inside the current function execution.

These variables are generally created when a function executes.

### Example

```js
function calculateTotal(price, quantity) {
  const subtotal = price * quantity;

  debugger;

  const tax = subtotal * 0.18;

  const finalAmount = subtotal + tax;

  return finalAmount;
}

calculateTotal(500, 3);
```

### What Happens?

1. The function starts executing.
2. `price` receives 500.
3. `quantity` receives 3.
4. The subtotal is calculated.
5. Execution pauses at `debugger`.

Now open the Scope section in React Native DevTools.

### Expected Values

```text
Local:
    price: 500
    quantity: 3
    subtotal: 1500
```

The variables `tax` and `finalAmount` have not been initialized yet because their statements have not executed.

### Why is Local Scope Important?

It helps developers:

* Inspect function parameters.
* Check calculated values.
* Identify incorrect variable values.
* Understand what is happening inside a function.

---

## 11.2 Closure Scope

### What is Closure Scope?

A closure allows an inner function to access variables from its outer function, even after the outer function has completed execution.

These retained variables can be inspected while debugging the inner function.

### Example

```js
function createCounter() {
  let count = 0;

  return function increment() {
    count++;

    debugger;

    return count;
  };
}

const counter = createCounter();

counter();
counter();
```

### What Happens?

1. `createCounter()` executes.
2. A variable named `count` is created with value 0.
3. The inner function `increment()` is returned.
4. The outer function completes.
5. The inner function is executed.
6. The value of `count` increases.
7. Execution pauses at `debugger`.

### Expected Values

First execution:

```text
Closure:
    count: 1
```

Second execution:

```text
Closure:
    count: 2
```

### Why is Closure Scope Important?

It helps developers understand:

* How inner functions access outer variables.
* Why variables retain their values.
* How closures work internally.
* How state is maintained between function calls.

---

## 11.3 Global Scope

### What is Global Scope?

Global Scope contains properties and variables available through the JavaScript global environment.

In React Native, a variable declared at the top level of a JavaScript module with `const` or `let` is not automatically a global variable. For a clear global example, we will attach a property to `globalThis`.

### Example

```js
globalThis.appName = "My Shopping App";

function showAppName() {
  debugger;

  console.log(globalThis.appName);
}

showAppName();
```

### What Happens?

1. The `appName` variable is declared.
2. The `showAppName()` function executes.
3. Execution pauses at `debugger`.
4. You can inspect the accessible outer and global variables.

### Why is Global Scope Important?

It helps developers understand:

* Variables declared outside functions.
* How different functions access shared variables.
* Where a particular variable comes from.

---

### Difference Between Local, Closure and Global Scope

| Scope | Description |
|---|---|
| Local | Contains variables and parameters of the current function |
| Closure | Contains variables retained from outer lexical scopes |
| Global | Contains variables available in the global execution environment |

**Important:** The exact variables displayed in the Scope panel depend on the current execution position and JavaScript environment. These are JavaScript concepts, not React Native-specific features.

## 12. Call Stack

### What is a Call Stack?

A Call Stack is a mechanism that keeps track of active function calls during JavaScript execution.

It helps developers understand which function called another function and how execution reached the current location.

The Call Stack follows the **LIFO (Last In, First Out)** principle.

This means the last function added to the stack is the first function to finish execution.

---

### Example

```js
function first() {
  second();
}

function second() {
  third();
}

function third() {
  debugger;
}

first();
```

### How Does It Work?

Let's understand the execution flow.

```text
first()
   |
   ▼
second()
   |
   ▼
third()
   |
   ▼
debugger
```

When `third()` executes, it pauses at the debugger statement.

The Call Stack conceptually looks like:

```text
third()
second()
first()
Global
```

The currently executing function appears at the top of the stack.

### Understanding Function Execution

1. JavaScript executes `first()`.
2. `first()` calls `second()`.
3. `second()` calls `third()`.
4. `third()` reaches the debugger statement.
5. Execution pauses.
6. The Call Stack displays the active function calling sequence.

---

### Why Do We Need Call Stack?

Suppose an error occurs inside a function, but you do not know which function called it.

The Call Stack helps developers:

* Trace function execution.
* Understand function calling relationships.
* Identify the source of an error.
* Understand nested function execution.
* Debug complex JavaScript applications.

### Practical Exercise

Use the following code:

```js
function login() {
  validateUser();
}

function validateUser() {
  checkCredentials();
}

function checkCredentials() {
  debugger;
}

login();
```

**Tasks:**

1. Run the code.
2. Open the Sources panel.
3. Inspect the Call Stack.
4. Identify which function executed first.
5. Identify which function is currently executing.

## 13. Watch Expressions

### What are Watch Expressions?

Watch Expressions allow developers to continuously monitor the values of specific JavaScript expressions while debugging.

Instead of repeatedly checking variables manually, developers can add expressions to the Watch section.

Whenever execution pauses, the debugger evaluates these expressions in the current execution context.

### Example

```js
function calculateTotal(price, quantity) {
  const subtotal = price * quantity;

  const tax = subtotal * 0.18;

  const finalAmount = subtotal + tax;

  debugger;

  return finalAmount;
}

calculateTotal(500, 3);
```

Suppose we want to monitor:

* `price`
* `quantity`
* `subtotal`
* `tax`
* `finalAmount`

We can add these expressions to the Watch section.

### Example Watch Expressions

```js
price
quantity
subtotal
tax
finalAmount
subtotal + tax
```

### Expected Values

```text
price: 500
quantity: 3
subtotal: 1500
tax: 270
finalAmount: 1770
subtotal + tax: 1770
```

### Why Do We Need Watch Expressions?

* Monitor important variables.
* Observe calculated values.
* Check complex expressions.
* Avoid repeatedly typing the same expressions.
* Understand how values change during execution.

**Note:** Expressions are evaluated in the current paused execution context. A variable that has not yet been initialized or is outside the current accessible scope may show an unavailable value or error.

## 14. Network Panel – API Debugging

### What is the Network Panel?

The Network panel helps developers inspect network requests made by their React Native application.

Whenever an application communicates with a backend server, it sends network requests.

For example:

* Login API
* Registration API
* Fetch Users API
* Product Listing API
* Payment API
* Upload Image API

The Network panel helps developers understand what happens during these requests.

---

### Why Do We Need the Network Panel?

Suppose a login button is clicked, but the user cannot log in.

Possible reasons include:

* Incorrect API URL.
* Server is not running.
* Incorrect request method.
* Invalid request body.
* Authentication failure.
* Server-side error.
* Network connection problem.

The Network panel helps investigate these issues.

---

### Example: Fetch API

Let's create a simple function that fetches users from an API.

```js
const fetchUsers = async () => {
  try {
    const response = await fetch(
      "https://jsonplaceholder.typicode.com/users"
    );

    const data = await response.json();

    console.log(data);

  } catch (error) {
    console.error("API Error:", error);
  }
};

fetchUsers();
```

### What Happens?

1. The function executes.
2. A GET request is sent to the API.
3. The server processes the request.
4. The server returns a response.
5. The response is converted into JSON.
6. The user data is displayed in the console.

---

### How to Inspect API Requests?

### Steps

1. Open React Native DevTools.
2. Navigate to the Network panel.
3. Keep DevTools open.
4. Execute the API request in your application.
5. Find the request in the Network panel.
6. Select the request.
7. Inspect its details.

Network requests are recorded automatically while DevTools is open.


## 15. Performance Panel

### What is the Performance Panel?

The Performance panel helps developers understand how their JavaScript application is executing over time.

It provides a performance timeline that allows developers to record and analyse application activity.

It helps identify operations that take too much time and may affect application responsiveness.

---

### Why Do We Need Performance Debugging?

Suppose you have a React Native application containing a large product list.

When users scroll through the list, the application becomes slow.

Possible reasons include:

* Expensive JavaScript calculations.
* Unnecessary component rendering.
* Too many updates.
* Slow event handlers.
* Large amounts of work happening during interactions.

The Performance panel helps developers investigate these problems.

---

### What Can We Inspect?

The Performance panel provides different timeline tracks, including:

* JavaScript execution.
* React performance activity.
* Network events.
* Custom User Timings.

These tracks help developers understand what happened during a recorded session.

---

### Practical Example

Consider this function:

```js
function calculateSum() {
  let total = 0;

  for (let i = 0; i < 1000000; i++) {
    total += i;
  }

  return total;
}
```

This function performs a large number of calculations.

If an expensive operation runs during an interaction, it may delay other JavaScript work.

### Practical Steps

1. Open React Native DevTools.
2. Navigate to Performance.
3. Start recording.
4. Perform an interaction in your application.
5. Stop recording.
6. Inspect the performance timeline.
7. Identify time-consuming operations.

### Why is Performance Debugging Important?

It helps developers:

* Identify expensive JavaScript operations.
* Understand React rendering activity.
* Investigate slow interactions.
* Inspect network activity during performance recording.
* Understand application responsiveness.

**Important:** React Native DevTools Performance is available starting from React Native 0.83.

Do not confuse this panel with the Performance Monitor available from the Developer Menu:

* **Performance Monitor:** Provides a quick, live performance overlay while the application is running.
* **Performance panel:** Records and analyses a detailed timeline of JavaScript and React activity, along with supported network and timing events.

For platform-level and native performance measurements, use Android Studio Profiler or Xcode Instruments as well.

## 16. Memory Panel

### What is the Memory Panel?

The Memory panel helps developers inspect the memory used by JavaScript objects in their application.

It provides tools to capture heap snapshots and analyse memory usage.

A heap is an area of memory where JavaScript objects and other dynamically allocated data are stored.

---

### Why Do We Need Memory Debugging?

Suppose an application becomes slower after running for a long time.

One possible reason is that the application is retaining objects that are no longer needed.

This may lead to increased memory usage.

Memory debugging helps developers investigate such problems.

### Common Memory Problems

* Unnecessary objects remaining in memory.
* Event listeners not being removed.
* Uncleaned subscriptions.
* Objects being retained unintentionally.
* Memory usage increasing over time.

---

### What is a Heap Snapshot?

A Heap Snapshot is a record of objects and their memory usage at a particular point in time.

Developers can use heap snapshots to inspect which objects are occupying JavaScript memory.

### Example Scenario

Suppose a screen creates many objects whenever the user opens it.

If those objects remain reachable even after leaving the screen, memory usage may increase.

By taking heap snapshots at different points, developers can investigate whether objects are being retained.

---

### How to Use the Memory Panel?

1. Open React Native DevTools.
2. Navigate to Memory.
3. Capture a heap snapshot.
4. Perform some application operations.
5. Capture another snapshot.
6. Compare the retained objects and memory usage.
7. Investigate unexpected object retention.

### Why is Memory Debugging Important?

* Helps investigate memory leaks.
* Helps inspect JavaScript objects.
* Helps understand memory usage.
* Helps identify unnecessary object retention.
* Helps improve application stability.

**Important:** The Memory panel focuses on JavaScript heap memory. It does not show the complete memory footprint of the native app and does not replace native memory profiling tools.

## 18. React Profiler

### What is React Profiler?

React Profiler is a tool that helps developers analyse the rendering performance of React components.

It allows developers to record component rendering activity and understand how much time React spends rendering and committing updates.

---

### Why Do We Need React Profiler?

Suppose a button updates one component, but many other components also re-render.

Unnecessary rendering may affect application performance.

React Profiler helps developers investigate:

* Which components rendered.
* When components rendered.
* How much time rendering took.
* Which React commits occurred.
* How components behave during updates.

---

### Example

```jsx
import React, { useState } from "react";

import {
  View,
  Text,
  Button,
} from "react-native";

function Counter() {
  const [count, setCount] = useState(0);

  return (
    <View>
      <Text>Count: {count}</Text>

      <Button
        title="Increase"
        onPress={() => setCount(count + 1)}
      />
    </View>
  );
}

export default function App() {
  return (
    <View>
      <Counter />
    </View>
  );
}
```

### What Happens?

1. The application renders.
2. The Counter component displays count = 0.
3. The user presses the Increase button.
4. State changes from 0 to 1.
5. React renders the updated component.
6. The Profiler can record this rendering activity.

---

### How to Use React Profiler?

1. Open React Native DevTools.
2. Navigate to the Profiler panel.
3. Start recording.
4. Interact with your application.
5. Stop recording.
6. Inspect the recorded React commits.
7. Analyse the rendering time and component activity.

### What is a React Commit?

A React commit is a phase in which React applies the updates from a completed render to the host environment.

In React Native, this involves applying the relevant updates to the native UI.

The Profiler helps developers inspect the timing of these commits.

---

### Difference Between Performance and Profiler

| Performance Panel | React Profiler |
|---|---|
| Analyses broader application activity | Focuses on React rendering |
| Shows JavaScript execution and other timeline tracks | Shows React component rendering and commits |
| Helps investigate slow operations | Helps investigate rendering performance |
| Provides a broader performance timeline | Provides React-specific profiling information |

## 20. JavaScript Debugging vs Native Debugging

React Native applications contain JavaScript code as well as native Android and iOS code.

React Native DevTools is designed primarily for debugging JavaScript and React application concerns.

It does not replace native debugging tools.

### JavaScript Debugging

Use React Native DevTools when you need to investigate:

* JavaScript errors.
* Incorrect variable values.
* Function execution.
* React component behaviour.
* API requests supported by the DevTools Network panel.
* JavaScript performance and memory.

### Native Debugging

Use Android Studio or Xcode when you need to investigate:

* Native Android crashes.
* Native iOS crashes.
* Native module errors.
* Java/Kotlin issues.
* Swift/Objective-C issues.
* Platform-level native logs.

### Important Native Debugging Commands

**Android**

```bash
npx react-native log-android
```

**iOS**

```bash
npx react-native log-ios
```

For Android, you can also inspect device logs using:

```bash
adb logcat
```

These commands are intended for React Native CLI projects and may not be available in every Expo workflow. In Expo projects, use the logs shown by the Expo/Metro terminal and the platform tools (Android Studio, `adb logcat`, or Xcode) when native logs are needed.

These tools help developers investigate issues that cannot be fully diagnosed through JavaScript debugging.

### Practical Examples: Which Tool Should You Use?

| Problem | Recommended Tool |
|---|---|
| A JavaScript variable contains an incorrect value | React Native DevTools – Sources and Console |
| A function is not executing as expected | React Native DevTools – Breakpoints and Call Stack |
| An API request returns an unexpected response | React Native DevTools – Network panel, Console, and backend logs |
| A native Android application crash occurs | Android Studio and Logcat (`adb logcat`) |
| A native iOS application crash occurs | Xcode debugger and device logs |
| A native module written in Java/Kotlin fails | Android Studio |
| A native module written in Swift/Objective-C fails | Xcode |
| The application has a slow JavaScript interaction | React Native DevTools – Performance panel |
| Native CPU or memory usage is unusually high | Android Studio Profiler or Xcode Instruments |

### Important Note for Expo Developers

The exact native debugging workflow depends on the Expo workflow and whether you are using Expo Go or a development build.

* In **Expo Go**, you cannot directly modify or debug the native source code bundled inside Expo Go.
* In a **development build**, you can work with your app's native project and use Android Studio or Xcode for native-level debugging.
* For JavaScript errors, use React Native DevTools and the Expo/Metro terminal logs.
* For Android native logs, use Android Studio or `adb logcat`.
* For iOS native logs, use Xcode and its device logs.

## 22. LogBox

### What is LogBox?

LogBox is React Native's in-app system for displaying warnings and errors during development.

It helps developers notice problems without having to keep the terminal or DevTools visible all the time.

LogBox can display different kinds of messages, including:

* Warnings generated by the application or libraries.
* JavaScript errors.
* Error details and stack traces.
* Fatal errors that prevent the application from continuing normally.

### Why Do We Need LogBox?

Suppose a component uses an incorrect property or a JavaScript operation throws an error.

LogBox can display an error or warning notification in the running application. Developers can open the notification to inspect the message and relevant stack trace, then use React Native DevTools to investigate the source.

### Example: Generating a Warning and an Error

```js
import { View, Button } from "react-native";

export default function App() {
  const showMessages = () => {
    console.warn("This is a warning message.");
    console.error("This is an error message.");
  };

  return (
    <View>
      <Button title="Show Messages" onPress={showMessages} />
    </View>
  );
}
```

When the button is pressed, the warning and error messages can be displayed through the development logging tools, including LogBox where applicable.

### Ignoring LogBox Messages

React Native provides the `LogBox` API to ignore selected warning messages during development.

#### 1. Ignore Specific Warning Messages

```js
import { LogBox } from "react-native";

LogBox.ignoreLogs([
  "Warning: Some warning message",
]);
```

This is useful when a known warning is noisy during development and cannot immediately be resolved.

#### 2. Ignore All LogBox Notifications

```js
import { LogBox } from "react-native";

LogBox.ignoreAllLogs();
```

You can also pass `true` or `false` to control whether LogBox notifications are ignored:

```js
LogBox.ignoreAllLogs(true);  // Ignore LogBox notifications
LogBox.ignoreAllLogs(false); // Show LogBox notifications again
```

### Important Things to Remember

* LogBox is a development aid for displaying warnings and errors.
* Ignoring a warning does not fix the underlying problem.
* Avoid ignoring all messages as a permanent solution.
* Read the warning or error and investigate its root cause.
* Remove temporary debugging workarounds when they are no longer needed.

### LogBox vs Console vs React Native DevTools

| Tool | Main Purpose |
|---|---|
| LogBox | Displays warnings and errors in the running app during development |
| Console | Displays messages written using methods such as `console.log()`, `console.warn()`, and `console.error()` |
| React Native DevTools | Provides a complete environment for inspecting and debugging JavaScript and React behaviour |

**Remember:** LogBox helps you notice an issue, while React Native DevTools helps you investigate the issue in more detail.
