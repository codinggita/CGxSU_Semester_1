# 12. Database Integration with MongoDB & Mongoose

MongoDB is a NoSQL document database. **Mongoose** is an ODM (Object Data Modeling) library that provides schemas, validation, and models for working with MongoDB in a Node.js application.

In a Next.js application, database operations must run on the server. Client Components should communicate with the server through Route Handlers or Server Actions instead of connecting directly to MongoDB.

## 1. Install Mongoose and Configure MongoDB

Install Mongoose:

```bash
npm install mongoose
```

Add the MongoDB connection string to `.env.local`:

```env
MONGODB_URI="mongodb://127.0.0.1:27017/ecommerce"
```

For MongoDB Atlas, use the connection string provided by your cluster:

```env
MONGODB_URI="mongodb+srv://<username>:<password>@<cluster-url>/ecommerce"
```

Keep the connection string private. Do not expose it in Client Components or commit `.env.local` to Git.

## 2. Create a Reusable Database Connection

Create `lib/mongodb.ts`:

```ts
import mongoose from "mongoose";

const MONGODB_URI = process.env.MONGODB_URI;

if (!MONGODB_URI) {
	throw new Error("Please define the MONGODB_URI environment variable");
}

type MongooseCache = {
	conn: typeof mongoose | null;
	promise: Promise<typeof mongoose> | null;
};

declare global {
	// eslint-disable-next-line no-var
	var mongooseCache: MongooseCache | undefined;
}

const cached = global.mongooseCache ?? {
	conn: null,
	promise: null,
};

global.mongooseCache = cached;

export async function connectToDatabase() {
	if (cached.conn) {
		return cached.conn;
	}

	if (!cached.promise) {
		cached.promise = mongoose.connect(MONGODB_URI, {
			bufferCommands: false,
		});
	}

	try {
		cached.conn = await cached.promise;
	} catch (error) {
		cached.promise = null;
		throw error;
	}

	return cached.conn;
}
```

### Why cache the connection?

Next.js may reload server modules during development, and multiple requests may reach the application at the same time. Caching the connection and connection promise helps reuse an existing connection instead of opening a new connection for every request.

Call `connectToDatabase()` before performing database operations.

## 3. Create a Mongoose Schema and Model

A **Schema** defines the structure, data types, and validation rules of documents in a MongoDB collection. A **Model** is created from a schema and provides methods to interact with that collection.

Create `models/Product.ts`:

```ts
import mongoose, { Schema } from "mongoose";

const productSchema = new Schema(
	{
		name: {
			type: String,
			required: true,
			trim: true,
		},
		description: {
			type: String,
			trim: true,
		},
		price: {
			type: Number,
			required: true,
			min: 0,
		},
		stock: {
			type: Number,
			required: true,
			default: 0,
			min: 0,
		},
	},
	{
		timestamps: true,
	},
);

const Product =
	mongoose.models.Product || mongoose.model("Product", productSchema);

export default Product;
```

- `required` makes a field mandatory.
- `trim` removes whitespace from the beginning and end of a string.
- `min` defines the minimum allowed numeric value.
- `default` sets a value when one is not provided.
- `timestamps` automatically adds `createdAt` and `updatedAt` fields.
- `mongoose.models.Product || mongoose.model(...)` prevents model recompilation errors during development.

Mongoose creates or uses the `products` collection for the `Product` model.

## 4. Use Mongoose in a Route Handler

Route Handlers expose HTTP endpoints that can be called by the browser or other clients. They run on the server, so they can safely use Mongoose models.

Create `app/api/products/route.ts`:

```ts
import { connectToDatabase } from "@/lib/mongodb";
import Product from "@/models/Product";

export async function GET() {
	await connectToDatabase();

	const products = await Product.find().sort({ createdAt: -1 });

	return Response.json({ products });
}

export async function POST(request: Request) {
	await connectToDatabase();

	const body = await request.json();

	const product = await Product.create({
		name: body.name,
		description: body.description,
		price: body.price,
		stock: body.stock,
	});

	return Response.json({ product }, { status: 201 });
}
```

- `GET` retrieves products from MongoDB.
- `POST` reads the request body and creates a product.
- `Product.find()` retrieves matching documents.
- `Product.create()` creates and saves a new document.
- `Response.json()` sends a JSON response.

The example demonstrates the database interaction. Production endpoints should also validate incoming request data and handle database errors before returning a response.

A Client Component can call the endpoint using `fetch()`:

```ts
const response = await fetch("/api/products");
const data = await response.json();
```

## 5. Use Mongoose in a Server Action

Server Actions allow server-side functions to be called from Client Components or Server Components. They are useful for handling form submissions and data mutations.

Create `app/products/actions.ts`:

```ts
"use server";

import { revalidatePath } from "next/cache";
import { connectToDatabase } from "@/lib/mongodb";
import Product from "@/models/Product";

export async function createProduct(formData: FormData) {
	await connectToDatabase();

	const name = String(formData.get("name") ?? "");
	const description = String(formData.get("description") ?? "");
	const price = Number(formData.get("price"));
	const stock = Number(formData.get("stock"));

	await Product.create({
		name,
		description,
		price,
		stock,
	});

	revalidatePath("/products");
}
```

A form can use the Server Action directly:

```tsx
import { createProduct } from "@/app/products/actions";

export function CreateProductForm() {
	return (
		<form action={createProduct}>
			<input name='name' placeholder='Product name' required />
			<textarea name='description' placeholder='Description' />
			<input name='price' type='number' min='0' required />
			<input name='stock' type='number' min='0' required />
			<button type='submit'>Create Product</button>
		</form>
	);
}
```

`revalidatePath("/products")` tells Next.js to revalidate the products page after a product is created.

Server Actions are server-side entry points, but they must still validate submitted data. Client-side form constraints such as `required` and `min` are not a replacement for server-side validation.
