# 11. Backend & API Routes Handlers

## 1. What Is a Backend API in Next.js?

Next.js can expose the same kind of REST endpoints you've built in Express — the syntax changes, the concepts don't. The two real differences are **how routes are registered** and **what Request/Response objects you get**.

```text
app/
└── api/
    └── products/
        └── route.ts
```

This file defines the collection endpoint `/api/products`.

---

## 2. App Route Handling

In the App Router, backend endpoints live in `route.ts`. A `route.ts` file is **not** a React component — it handles HTTP requests and returns HTTP responses.

```text
page.tsx   →  UI / Page
route.ts   →  HTTP API
```

### Named exports per HTTP method — the main paradigm shift

This is the biggest structural difference from Express:

```text
Express:  one file, branch on req.method (or register .get() / .post() separately)
Next.js:  one file, one named export per method — GET, POST, PUT, PATCH, DELETE
```

```ts
// app/api/products/route.ts
export async function GET() {
	/* ... */
}
export async function POST(request: Request) {
	/* ... */
}
export async function PUT(request: Request) {
	/* ... */
}
```

### Web `Request` / `Response` vs Express `req` / `res`

Route Handlers use the **Web Platform** APIs — not Express-specific objects. Your Express muscle memory will fight you here:

| What you need    | Express (Pages Router is similar) | App Router Route Handler                            |
| ---------------- | --------------------------------- | --------------------------------------------------- |
| Auth header      | `req.headers.authorization`       | `request.headers.get("authorization")`              |
| Query params     | `req.query.category`              | `new URL(request.url).searchParams.get("category")` |
| JSON body        | `req.body` (already parsed)       | `await request.json()`                              |
| JSON response    | `res.status(201).json(data)`      | `Response.json(data, { status: 201 })`              |
| No body (DELETE) | `res.status(204).end()`           | `new Response(null, { status: 204 })`               |

```text
Express req/res          →  Next.js wraps Node for Pages Router API routes
Web Request/Response     →  App Router Route Handlers use these directly
```

### File structure

```text
app/
└── api/
    └── products/
        ├── route.ts          ← GET /api/products, POST /api/products
        └── [id]/
            └── route.ts      ← GET/PUT/PATCH/DELETE /api/products/123
```

### `context.params` is a Promise

No Express equivalent. In App Router dynamic Route Handlers, route params arrive as a **Promise** you must await:

```ts
type RouteContext = {
	params: Promise<{ id: string }>;
};

export async function GET(_request: Request, context: RouteContext) {
	const { id } = await context.params; // not context.params.id directly
	// ...
}
```

### Collection — `app/api/products/route.ts`

```ts
// app/api/products/route.ts

import { z } from "zod";

let products = [
	{ id: 1, name: "Laptop", price: 80000, category: "electronics" },
	{ id: 2, name: "Keyboard", price: 3000, category: "electronics" },
];

const productSchema = z.object({
	name: z.string().min(1),
	price: z.number().positive(),
	category: z.string().min(1),
});

function requireAuth(request: Request) {
	return request.headers.get("authorization");
}

// GET /api/products?category=electronics&page=1
export async function GET(request: Request) {
	try {
		if (!requireAuth(request)) {
			return Response.json({ error: "Unauthorized" }, { status: 401 });
		}

		const { searchParams } = new URL(request.url);
		const category = searchParams.get("category");
		const page = searchParams.get("page") ?? "1";

		let result = products;
		if (category) {
			result = result.filter((p) => p.category === category);
		}

		return Response.json(
			{ products: result, page: Number(page) },
			{ status: 200, headers: { "X-App-Version": "1.0.0" } },
		);
	} catch {
		return Response.json(
			{ error: "Failed to fetch products" },
			{ status: 500 },
		);
	}
}

// POST /api/products
export async function POST(request: Request) {
	try {
		if (!requireAuth(request)) {
			return Response.json({ error: "Unauthorized" }, { status: 401 });
		}

		const body = await request.json();
		const result = productSchema.safeParse(body);

		if (!result.success) {
			return Response.json(
				{
					error: "Invalid request body",
					details: result.error.flatten(),
				},
				{ status: 400 },
			);
		}

		const product = { id: Date.now(), ...result.data };
		products.push(product);
		return Response.json(product, { status: 201 });
	} catch {
		return Response.json(
			{ error: "Failed to create product" },
			{ status: 500 },
		);
	}
}
```

### Individual product — `app/api/products/[id]/route.ts`

```ts
// app/api/products/[id]/route.ts

import { z } from "zod";

type RouteContext = {
	params: Promise<{ id: string }>;
};

let products = [
	{ id: 1, name: "Laptop", price: 80000, category: "electronics" },
	{ id: 2, name: "Keyboard", price: 3000, category: "electronics" },
];

const patchSchema = z.object({
	name: z.string().min(1).optional(),
	price: z.number().positive().optional(),
	category: z.string().min(1).optional(),
});

function requireAuth(request: Request) {
	return request.headers.get("authorization");
}

function findProduct(id: string) {
	return products.find((p) => p.id === Number(id));
}

// GET /api/products/123
export async function GET(request: Request, context: RouteContext) {
	if (!requireAuth(request)) {
		return Response.json({ error: "Unauthorized" }, { status: 401 });
	}

	const { id } = await context.params;
	const product = findProduct(id);

	if (!product) {
		return Response.json({ error: "Product not found" }, { status: 404 });
	}

	return Response.json(product, { status: 200 });
}

// PUT /api/products/123
export async function PUT(request: Request, context: RouteContext) {
	if (!requireAuth(request)) {
		return Response.json({ error: "Unauthorized" }, { status: 401 });
	}

	const { id } = await context.params;
	const body = await request.json();

	if (!findProduct(id)) {
		return Response.json({ error: "Product not found" }, { status: 404 });
	}

	const updated = { id: Number(id), ...body };
	products = products.map((p) => (p.id === Number(id) ? updated : p));
	return Response.json(updated, { status: 200 });
}

// PATCH /api/products/123?notify=true
export async function PATCH(request: Request, context: RouteContext) {
	if (!requireAuth(request)) {
		return Response.json({ error: "Unauthorized" }, { status: 401 });
	}

	const { id } = await context.params;
	const notify = new URL(request.url).searchParams.get("notify");
	const body = await request.json();
	const result = patchSchema.safeParse(body);

	if (!result.success) {
		return Response.json(
			{ error: "Invalid request body" },
			{ status: 400 },
		);
	}

	const product = findProduct(id);
	if (!product) {
		return Response.json({ error: "Product not found" }, { status: 404 });
	}

	Object.assign(product, result.data);
	return Response.json({ product, notify }, { status: 200 });
}

// DELETE /api/products/123
export async function DELETE(request: Request, context: RouteContext) {
	if (!requireAuth(request)) {
		return Response.json({ error: "Unauthorized" }, { status: 401 });
	}

	const { id } = await context.params;

	if (!findProduct(id)) {
		return Response.json({ error: "Product not found" }, { status: 404 });
	}

	products = products.filter((p) => p.id !== Number(id));
	return new Response(null, { status: 204 });
}
```

## 3. Page Route Handling

The Pages Router API route pattern mirrors Express: one default export, branch on `req.method`. Pages Router API routes use `NextApiRequest` / `NextApiResponse`, which behave much closer to Express `req` / `res` than App Router's Web APIs.

```ts
// pages/api/products.ts
import type { NextApiRequest, NextApiResponse } from "next";

export default function handler(req: NextApiRequest, res: NextApiResponse) {
	if (req.method === "GET") {
		return res.status(200).json({ products: [] });
	}

	if (req.method === "POST") {
		return res.status(201).json({ id: 1, ...req.body });
	}

	return res.status(405).json({ error: "Method not allowed" });
}
```

Dynamic segments use file names like `pages/api/products/[id].ts` — the param is on `req.query.id`, same idea as Express route params.

### App Router vs Pages Router

| Topic        | App Router                          | Pages Router                    |
| ------------ | ----------------------------------- | ------------------------------- |
| File         | `route.ts`                          | `pages/api/*.ts`                |
| HTTP methods | Named exports (`GET`, `POST`, …)    | `req.method` + `if` / `switch`  |
| Request      | Web `Request`                       | `NextApiRequest` (Express-like) |
| Response     | `Response.json()`                   | `res.status().json()`           |
| Query params | `new URL(request.url).searchParams` | `req.query`                     |
| Route params | `await context.params`              | `req.query` (on `[id]` file)    |
| Body         | `await request.json()`              | `req.body` (already parsed)     |
| Headers      | `request.headers.get()`             | `req.headers`                   |

## 4. Server Actions vs Route Handlers

Server Actions and Route Handlers can both perform server-side operations, but they are designed for different use cases. **There is no Express equivalent for Server Actions** — not every mutation should be an API route.

Both should call the same **service layer** — do not reuse the same function name with incompatible signatures:

```ts
// lib/services/product.service.ts
export async function createProductService(data: { name: string }) {
	return db.product.create({ data });
}
```

### Server Actions

Server Actions are server-side functions invoked from your Next.js UI — especially form mutations.

```ts
"use server";

import { createProductService } from "@/lib/services/product.service";

export async function createProduct(formData: FormData) {
	const name = formData.get("name");
	return createProductService({ name: String(name) });
}
```

Typical flow:

```text
Next.js Form
     ↓
Server Action
     ↓
Product Service
     ↓
Database
```

### Route Handlers

Route Handlers expose public HTTP endpoints for any client — browser, mobile app, third-party service.

```text
POST /api/products
```

```ts
// app/api/products/route.ts
import { createProductService } from "@/lib/services/product.service";

export async function POST(request: Request) {
	const body = await request.json();
	const product = await createProductService(body);
	return Response.json(product, { status: 201 });
}
```

Typical flow:

```text
Browser / Mobile App / External Client
                ↓
       POST /api/products
                ↓
          Route Handler
                ↓
          Product Service
                ↓
             Database
```

## 5. Server Actions vs Route Handlers — When to Use Which?

| Requirement                                 | Server Actions          | Route Handlers / API Routes |
| ------------------------------------------- | ----------------------- | --------------------------- |
| Form submission from Next.js UI             | ✅                      | ✅                          |
| UI-triggered server mutation                | ✅                      | ✅                          |
| Public HTTP API                             | ❌                      | ✅                          |
| Mobile app consuming API                    | ❌                      | ✅                          |
| Third-party service calling endpoint        | ❌                      | ✅                          |
| REST API                                    | ❌                      | ✅                          |
| Explicit HTTP methods                       | ❌                      | ✅                          |
| JSON API                                    | Not the primary purpose | ✅                          |
| Direct server-side function from Next.js UI | ✅                      | ❌                          |

### Example

If only your Next.js application needs to submit a product form:

```text
Product Form
     ↓
Server Action
     ↓
Database
```

If a mobile application also needs to create products:

```text
Mobile App
     ↓
POST /api/products
     ↓
Route Handler / API Route
     ↓
Database
```

## 6. Recommended Backend Structure

Inline Route Handler examples keep logic in the handler for clarity; here's how to structure it once the app grows. Same separation you already do with Express controllers/services — the file locations just move:

```text
lib/services/      ←  controllers/
lib/validations/   ←  validation schemas alongside services
```

```text
app/api/products/route.ts   ←  thin route layer only

lib/
├── db.ts
├── services/
│   └── product.service.ts
└── validations/
    └── product.schema.ts
```

---

## 7. Key Takeaways

- **App Router** → `route.ts` with named exports per HTTP method; **Pages Router** → `pages/api/*.ts` with `req.method` branching (Express-like).
- The biggest shift from Express: **one named export per method** + **Web** `Request`**/**`Response` instead of `req`/`res`.
- `await context.params` in dynamic Route Handlers — params is a Promise, not a plain object.
- **Server Actions** have no Express equivalent — use for Next.js UI mutations; **Route Handlers** for public HTTP/REST APIs.
- Share business logic via `lib/services/` — both Server Actions and Route Handlers call the same service functions.
- Do not expose internal errors in API responses.

### Final mental model

```text
                         NEXT.JS BACKEND
                                │
                 ┌──────────────┴──────────────┐
                 │                             │
             App Router                  Pages Router
                 │                             │
     named exports (GET, POST…)         req.method branching
     Web Request / Response            NextApiRequest / Response
                 │                             │
                 └──────────────┬──────────────┘
                                │
                    lib/services/ (shared with Server Actions)
                                │
                         Database / External API
```
