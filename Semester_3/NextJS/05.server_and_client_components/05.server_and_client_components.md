# 05. Server & Client Components

Next.js App Router uses **Server Components by default**.

Client Components are used when a component needs **browser-side interactivity or browser APIs**.

### Two Different Concepts

```text
Server / Client Components
        ↓
Where does the component code run?

Rendering
        ↓
How and when is the UI generated?
```

> **Server/Client Components and rendering strategies are different concepts.**

---

## 1. Server Components

In the App Router, components are **Server Components by default**.

Example:

```tsx
export default async function ProductsPage() {
	const products = await getProducts();

	return (
		<div>
			{products.map((product) => (
				<div key={product.id}>{product.name}</div>
			))}
		</div>
	);
}
```

Server Components are useful when you need to:

- Fetch data
- Access server-side resources
- Work with databases
- Use server-only logic
- Render content that does not need browser interaction

### Server Component Restrictions

Server Components cannot use features that require the browser.

For example:

```text
useState
useEffect
onClick
onChange
window
document
localStorage
```

If a component needs these features, make it a Client Component.

---

## 2. Client Components

A Client Component is used when a component needs **client-side JavaScript or browser features**.

Add:

```tsx
"use client";
```

Example:

```tsx
"use client";

import { useState } from "react";

export default function Counter() {
	const [count, setCount] = useState(0);

	return <button onClick={() => setCount(count + 1)}>Count: {count}</button>;
}
```

Client Components are useful for:

- `useState`
- `useEffect`
- Event handlers
- Browser APIs
- Interactive UI

---

## 3. `"use client"`

The `"use client"` directive creates a **Client Component boundary**.

Example:

```tsx
"use client";

export default function Button() {
	return <button onClick={() => alert("Hello")}>Click Me</button>;
}
```

Do not add `"use client"` to every component.

Start with Server Components and add `"use client"` only when client-side features are required.

---

## 4. `"use server"`

`"use server"` is different from `"use client"`.

```text
"use client"
→ Client Component boundary

"use server"
→ Server Function / Server Action
```

Example:

```tsx
"use server";

export async function createProduct(formData: FormData) {
	const name = formData.get("name");

	// Server-side validation
	// Database mutation
}
```

`"use server"` can be used for functions that need to run on the server, such as:

- Database mutations
- Server-side validation
- Other server-only operations

> **Important:**
> `"use client"` is used for components.
> `"use server"` is used for server functions.

---

## 5. Server and Client Components Together

A Server Component can render a Client Component.

For example, a product page may fetch product data on the server while using a Client Component for an interactive button.

### Server Component

```tsx
export default async function ProductPage() {
	const product = await getProduct();

	return (
		<div>
			<h1>{product.name}</h1>

			<AddToCartButton productId={product.id} />
		</div>
	);
}
```

### Client Component

```tsx
"use client";

export default function AddToCartButton({ productId }: { productId: string }) {
	return <button onClick={() => addToCart(productId)}>Add to Cart</button>;
}
```

The structure becomes:

```text
Product Page
    │
    ├── Product Information
    │       → Server Component
    │
    └── Add to Cart
            → Client Component
```

The entire page does **not** need to become a Client Component.

---

## 6. Passing Data to Client Components

A Server Component can pass data to a Client Component through props.

```text
Server Component
       ↓
      Props
       ↓
Client Component
```

Example:

```tsx
// Server Component

<ProductCard name={product.name} price={product.price} />
```

The Client Component can then use those props for interactive UI.

---

## 7. Using `children`

A Client Component can also receive server-rendered content through `children`.

### Client Component

```tsx
"use client";

export default function InteractivePanel({
	children,
}: {
	children: React.ReactNode;
}) {
	return (
		<div>
			<button>Toggle</button>

			{children}
		</div>
	);
}
```

A Server Component can use it:

```tsx
<InteractivePanel>
	<ProductDetails />
</InteractivePanel>
```

This allows server-rendered content to be combined with client-side interaction.

---

## 8. Server vs Client Components

| Requirement                      | Component |
| -------------------------------- | --------- |
| Needs `useState`                 | Client    |
| Needs `useEffect`                | Client    |
| Needs event handlers             | Client    |
| Needs browser APIs               | Client    |
| Mainly fetches data              | Server    |
| Mainly displays data             | Server    |
| Needs database access            | Server    |
| Needs server-only resources      | Server    |
| Needs private server credentials | Server    |

### Simple Decision

```text
Does it need state?
        ↓
       Yes → Client

Does it need event handlers?
        ↓
       Yes → Client

Does it need browser APIs?
        ↓
       Yes → Client

Does it mainly fetch/display data?
        ↓
       Yes → Server

Does it need server-only resources?
        ↓
       Yes → Server
```

---

## 9. Best Practices

### Keep Client Components Small

Instead of making an entire page a Client Component, isolate the interactive part.

```text
Product Page
    ↓
Server Component
    │
    ├── Product Information
    ├── Product Description
    │
    └── Add to Cart
            ↓
       Client Component
```

### Start with Server Components

By default:

```text
Component
    ↓
Server Component
```

Only use `"use client"` when the component actually needs client-side features.

### Keep Secrets on the Server

Never expose:

- Database passwords
- Private API keys
- Secret tokens
- Server credentials

in Client Components.

Use server-side code for operations that require secrets.

---

## Summary

- App Router components are **Server Components by default**.
- Server Components are useful for data fetching and server-side resources.
- Client Components are used for interactivity and browser APIs.
- `"use client"` creates a Client Component boundary.
- `"use server"` marks a Server Function.
- Server Components can render Client Components.
- Server Components can pass data to Client Components through props.
- Client Components can receive server-rendered content through `children`.
- Keep Client Components as small as practical.
- Do not add `"use client"` to every component.
- Keep secrets and server-only resources on the server.
- Start with Server Components and move only interactive parts to Client Components.
