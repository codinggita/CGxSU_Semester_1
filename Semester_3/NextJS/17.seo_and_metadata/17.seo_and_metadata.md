# 20. SEO & Metadata

SEO helps search engines understand, discover, and display public pages. Next.js App Router provides tools for generating page metadata, server-rendering public content, and exposing URLs to crawlers.

> Server rendering alone does not guarantee good SEO. Public pages also need useful content, descriptive metadata, discoverable URLs, and correct crawl settings.

## 1. Public Pages vs. Private Pages

| Page type                     | SEO priority | Typical approach                                               |
| ----------------------------- | ------------ | -------------------------------------------------------------- |
| Home, products, blog, pricing | High         | Server-render content, metadata, sitemap                       |
| Dashboard, account, admin     | Low          | Authentication and authorization; usually exclude from sitemap |

SEO work mainly applies to public, indexable pages. Private pages should be protected, not made public for search engines.

## 2. Metadata API

In the App Router, metadata is defined by exporting either:

- `metadata` — for metadata that does not depend on route data.
- `generateMetadata` — for metadata that depends on dynamic data, such as a product.

Metadata exports must be defined in Server Components. They cannot be exported from a Client Component.

### 2.1 Static Metadata

Use `metadata` for pages with fixed titles and descriptions.

```tsx
import type { Metadata } from "next";

export const metadata: Metadata = {
	title: "Products",
	description: "Browse our latest products.",
};

export default function ProductsPage() {
	return (
		<main>
			<h1>Products</h1>
		</main>
	);
}
```

### 2.2 Metadata in Layouts and Inheritance

Layouts can define shared metadata for their child routes. A page can override inherited values.

```tsx
// app/layout.tsx
import type { Metadata } from "next";

export const metadata: Metadata = {
	metadataBase: new URL("https://example.com"),
	title: {
		default: "Example Store",
		template: "%s | Example Store",
	},
	description: "Shop technology products at Example Store.",
};
```

```tsx
// app/products/page.tsx
import type { Metadata } from "next";

export const metadata: Metadata = {
	title: "Products", // Products | Example Store
};
```

`metadataBase` provides the base URL for metadata URLs that are relative. The title template allows child pages to use a consistent site name.

### 2.3 Dynamic Metadata

Use `generateMetadata` when the title, description, or other metadata depends on route data.

```tsx
import type { Metadata } from "next";

type Props = {
	params: Promise<{ id: string }>;
};

export async function generateMetadata({ params }: Props): Promise<Metadata> {
	const { id } = await params;
	const product = await getProduct(id);

	return {
		title: product.name,
		description: product.description,
	};
}

export default async function ProductPage({ params }: Props) {
	const { id } = await params;
	const product = await getProduct(id);
	return (
		<main>
			<h1>{product.name}</h1>
		</main>
	);
}
```

For example, each product can have its own title and description generated from its database record.

Metadata is generated on the server. Fetch SEO-critical content on the server rather than relying only on client-side `useEffect` fetching.

### 2.4 Metadata and Client Components

Keep metadata on the Server Component page/layout; import Client Components for interactivity:

```tsx
import type { Metadata } from "next";
import ProductFilters from "./ProductFilters"; // "use client"

export const metadata: Metadata = { title: "Products" };

export default function ProductsPage() {
	return (
		<main>
			<h1>Products</h1>
			<ProductFilters />
		</main>
	);
}
```

## 3. Open Graph and Twitter Metadata

Open Graph and Twitter metadata control how a page is represented when its link is shared on social platforms or messaging apps. They can provide a title, description, and preview image.

```tsx
export const metadata: Metadata = {
	title: "MacBook Pro",
	description: "Powerful laptop for professionals.",
	openGraph: {
		title: "MacBook Pro",
		description: "Powerful laptop for professionals.",
		images: ["/images/macbook-pro-preview.jpg"],
		type: "website",
	},
	twitter: {
		card: "summary_large_image",
		title: "MacBook Pro",
		description: "Powerful laptop for professionals.",
		images: ["/images/macbook-pro-preview.jpg"],
	},
};
```

### 3.2 Dynamic

For dynamic pages, return these fields from `generateMetadata` using the relevant product data.

```tsx
export async function generateMetadata({ params }: Props): Promise<Metadata> {
	const { id } = await params;
	const product = await getProduct(id);

	return {
		title: product.name,
		description: product.description,
		openGraph: {
			title: product.name,
			description: product.description,
			images: [
				{
					url: product.image,
					width: 1200,
					height: 630,
					alt: product.name,
				},
			],
		},
		twitter: {
			card: "summary_large_image",
			title: product.name,
			description: product.description,
			images: [product.image],
		},
	};
}
```

## 4. Canonical URLs

A page may be reachable through multiple URLs—for example, with sorting, filtering, or tracking query parameters.

A canonical URL tells search engines which URL should be treated as the preferred version of that page.

```tsx
export const metadata: Metadata = {
	alternates: {
		canonical: "https://example.com/products/123",
	},
};
```

For dynamic pages, generate the canonical URL from the route data:

```tsx
return {
	alternates: {
		canonical: `https://example.com/products/${id}`,
	},
};
```

Use the canonical URL that represents the preferred page, not an arbitrary query-string variation.

## 5. Sitemap

A sitemap lists the important URLs of a website to help search engines discover them.

Create `app/sitemap.ts`:

```tsx
import type { MetadataRoute } from "next";

export default async function sitemap(): Promise<MetadataRoute.Sitemap> {
	const products = await getProducts();

	return [
		{
			url: "https://example.com",
			lastModified: new Date(),
		},
		{
			url: "https://example.com/products",
			lastModified: new Date(),
		},
		...products.map((product) => ({
			url: `https://example.com/products/${product.id}`,
			lastModified: product.updatedAt,
		})),
	];
}
```

Next.js generates `/sitemap.xml` from this file.

Include public, useful, indexable pages. Do not include private account, dashboard, or admin pages.

## 6. Robots

Create `app/robots.ts` to control crawler access through the generated `robots.txt`.

```tsx
import type { MetadataRoute } from "next";

export default function robots(): MetadataRoute.Robots {
	return {
		rules: {
			userAgent: "*",
			allow: "/",
			disallow: ["/admin/", "/dashboard/"],
		},
		sitemap: "https://example.com/sitemap.xml",
	};
}
```

| File         | Purpose                                                |
| ------------ | ------------------------------------------------------ |
| `sitemap.ts` | Lists URLs that crawlers can discover                  |
| `robots.ts`  | Gives crawlers instructions about which paths to crawl |

**Robots is not security.** Disallow rules are crawler instructions, not access control. Protect private pages and APIs with authentication and authorization.

## 7. Semantic HTML

Use semantic HTML to describe the structure and meaning of page content.

- Use `<main>` for the primary page content.
- Use `<article>` for self-contained content such as a product or blog article where appropriate.
- Use headings in a logical hierarchy (`h1`, `h2`, `h3`).
- Use descriptive link text and Next.js `<Link>` for internal navigation.

Semantic structure helps crawlers and other tools interpret content. Do not choose heading levels just to get a particular font size; style headings with CSS.

## 8. Structured Data (JSON-LD)

Structured data provides search engines with additional information about the content of a page using a recognized schema, such as Schema.org.

For a product page, Product structured data may describe its name, image, price, currency, and availability. The data must be accurate and match the visible page content.

```tsx
const productSchema = {
	"@context": "https://schema.org",
	"@type": "Product",
	name: product.name,
	description: product.description,
	image: product.image,
	offers: {
		"@type": "Offer",
		price: product.price,
		priceCurrency: "USD",
		availability: "https://schema.org/InStock",
	},
};

return (
	<script
		type='application/ld+json'
		dangerouslySetInnerHTML={{
			__html: JSON.stringify(productSchema).replace(/</g, "\\u003c"),
		}}
	/>
);
```

Only include fields that are supported by the actual product data. Do not add fake ratings, prices, availability, or other information.

## 9. Metadata and Client Components

Metadata exports cannot be placed in Client Components. Keep the page or layout as a Server Component and render interactive Client Components inside it when needed.

```tsx
import type { Metadata } from "next";
import ProductFilters from "./ProductFilters"; // Client Component

export const metadata: Metadata = {
	title: "Products",
	description: "Browse our latest products.",
};

export default function ProductsPage() {
	return (
		<main>
			<h1>Products</h1>
			<ProductFilters />
		</main>
	);
}
```

This allows the page to provide server-generated metadata while still supporting client-side interactivity.

## 10. Common SEO Mistakes

- Using the same title and description across every page.
- Leaving public product content to load only after client-side rendering.
- Creating duplicate indexable URLs without an appropriate canonical.
- Forgetting to include important public pages in the sitemap.
- Accidentally disallowing important public pages in `robots.ts`.
- Treating `robots.txt` as a security mechanism.
- Adding structured data that is inaccurate or does not match visible content.
- Using non-semantic HTML or an incorrect heading hierarchy.

## 11. SEO Checklist

For each important public page, check:

- [ ] Meaningful URL
- [ ] Unique title and description
- [ ] Server-rendered page content
- [ ] Appropriate canonical URL
- [ ] Open Graph and Twitter metadata where relevant
- [ ] Semantic HTML and heading hierarchy
- [ ] Accurate JSON-LD where appropriate
- [ ] Included in sitemap if indexable
- [ ] Not unintentionally blocked by robots rules

## Key Takeaways

- Use `metadata` for static page metadata.
- Use `generateMetadata()` when metadata depends on dynamic route data.
- Define shared metadata in layouts and override it in child pages as needed.
- Open Graph and Twitter metadata improve link previews.
- Canonical URLs identify the preferred URL for duplicate or parameterized pages.
- `sitemap.ts` helps crawlers discover public pages.
- `robots.ts` provides crawl instructions; it does not secure routes.
- JSON-LD describes page content in a structured format.
- SEO matters most for public, indexable content—not authenticated dashboards.
