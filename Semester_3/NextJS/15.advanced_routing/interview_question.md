# Advanced Routing — Interview Questions

1. What are Parallel Routes in the Next.js App Router?

2. How are Parallel Routes different from normal nested routes?

3. What is a named slot, and how is it created in the folder structure?

4. Does a folder such as `@analytics` create a URL segment? Explain.

5. How does a layout receive and render Parallel Route slots?

6. What is the purpose of `default.tsx` inside a Parallel Route slot?

7. How can loading and error UI be handled independently for Parallel Route slots?

8. What is the purpose of an `error.tsx` file, and what component type must it use?

9. What are Intercepting Routes, and what are some common use cases?

10. What is the difference between how an intercepted route appears during client-side navigation and when its URL is opened directly?

11. What do the `(.)`, `(..)`, and `(...)` conventions represent in Intercepting Routes?

12. Do route groups and Parallel Route slot folders count as URL route segments when determining an Intercepting Route convention?

13. What is Modal Routing, and how does it use Parallel Routes and Intercepting Routes together?

14. How is a route-based modal different from a modal controlled with `useState`?

15. How does browser Back navigation behave when a user opens a route-based modal?

16. What happens when a user refreshes or directly opens the URL of a route-based modal?

17. In the product quick-view example, how does Next.js show the product as a modal during client navigation but as a full page on direct access?

18. When should you use a normal React component or `useState` instead of Parallel Routes or route-based modals?

19. Why should Parallel Routes not be used simply to organize ordinary components such as headers, sidebars, or buttons?

20. Are Parallel Routes and Intercepting Routes supported by the Next.js Pages Router?
