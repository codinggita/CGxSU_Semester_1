# 19. Advanced Routing

Parallel Routes, Intercepting Routes, and Modal Routing in the Next.js App Router — features with no direct equivalent in React Router or Express. Requires familiarity with file-based routing, dynamic routes, catch-all routes, route groups, nested layouts, and layout persistence. Parallel Routes and Intercepting Routes are **App Router only**; the Pages Router does not support them.

---

## 1. Parallel Routes

Parallel Routes render **multiple route segments simultaneously** inside the same layout, using **named slots** — folders prefixed with `@`.

The layout receives each slot as a prop alongside `children`. Next.js passes slots automatically. The layout shell persists; each slot is an independently routed segment — an extension of nested layouts covered in **Layouts**.

### 1.1 Parallel vs Nested Routes

Normal nested routing shows one child at a time. Parallel routing renders multiple segments at once within the same layout.

Use parallel routes when sections need **independent routing state**, not just separate React components.

### 1.2 Slots Are Not URL Segments

`@analytics` does **not** create `/dashboard/analytics`. The `@` prefix marks a slot rendered through the parent layout, not a URL path.

### 1.3 Default Files (`default.tsx`)

When no active page matches a slot, add a `default.tsx` inside the slot folder as a fallback.

### 1.4 Independent Loading and Error UI

Each slot can have its own `loading.tsx` and `error.tsx`. One slot can load or error independently while others render normally.

### 1.5 Example: Admin Dashboard

An admin dashboard with main content, analytics sidebar, and a notifications panel — all rendered at `/dashboard` simultaneously.

**UI layout:**

```text
┌──────────────────────────────────────────────┐
│                  Dashboard                   │
├──────────────────────┬───────────────────────┤
│                      │                       │
│     Main Content     │      Analytics        │
│     (children)       │     (@analytics)      │
│                      │                       │
├──────────────────────┴───────────────────────┤
│              Notifications (@notifications)  │
└──────────────────────────────────────────────┘
```

**Folder structure:**

```text
app/dashboard/
├── layout.tsx
├── page.tsx                        → /dashboard
├── settings/
│   └── page.tsx                    → /dashboard/settings (nested route still works)
├── @analytics/
│   ├── page.tsx
│   ├── loading.tsx
│   └── default.tsx
└── @notifications/
    ├── page.tsx
    └── loading.tsx
```

**`layout.tsx`** — receives slots as props:

```tsx
export default function DashboardLayout({
  children,
  analytics,
  notifications,
}: {
  children: React.ReactNode;
  analytics: React.ReactNode;
  notifications: React.ReactNode;
}) {
  return (
    <div className="dashboard">
      <main>{children}</main>
      <aside>{analytics}</aside>
      <section>{notifications}</section>
    </div>
  );
}
```

**`page.tsx`** — main content slot (`children`):

```tsx
export default function DashboardPage() {
  return <h1>Dashboard Overview</h1>;
}
```

**`@analytics/page.tsx`**:

```tsx
export default async function AnalyticsPanel() {
  const data = await fetchAnalytics(); // slow fetch
  return <div>Analytics: {data.totalUsers} users</div>;
}
```

**`@analytics/loading.tsx`** — shown while analytics loads; notifications can already be visible:

```tsx
export default function AnalyticsLoading() {
  return <p>Loading analytics...</p>;
}
```

**`@analytics/default.tsx`** — fallback when no analytics page is active:

```tsx
export default function AnalyticsDefault() {
  return <p>No analytics view selected.</p>;
}
```

**`@notifications/page.tsx`**:

```tsx
export default function NotificationsPanel() {
  return <ul><li>New order #1042</li><li>User signed up</li></ul>;
}
```

**URLs:**

```text
/dashboard            → main + analytics + notifications (all three slots)
/dashboard/settings   → settings page + analytics + notifications
```

`@analytics` and `@notifications` do **not** add `/analytics` or `/notifications` to the URL.

## 2. Intercepting Routes

Intercepting Routes render a route **within the current layout context** while navigating to a different URL.

Use cases: modals, photo previews, login dialogs, detail overlays, side panels.

> **The URL represents a full page; client navigation can display it as an overlay.**

On **client navigation**, the route renders as an overlay (e.g. a modal over the current page). On **direct URL access or refresh**, the same URL renders as a full page.

### 2.1 Intercepting Route Conventions

| Convention | Meaning         |
| ---------- | --------------- |
| `(.)`      | Same level      |
| `(..)`     | One level above |
| `(...)`    | Root app level  |

These are filesystem conventions, not URL segments. The exact folder name depends on the route hierarchy.

## 3. Modal Routing

Modal Routing combines Parallel Routes and Intercepting Routes for URL-driven modals.

### 3.1 URL-Based Modals vs `useState`

| Approach    | State lives in   | Deep link | Back button | Shareable URL |
| ----------- | ---------------- | --------- | ----------- | ------------- |
| `useState`  | Component memory | No        | No          | No            |
| Route modal | URL              | Yes       | Yes         | Yes           |

Use route-based modals when the modal represents **meaningful navigation state** — a detail view, login prompt, or quick-view that users should bookmark or share. `useState` is fine for simple temporary UI.

### 3.2 Back Button Behavior

Browser history controls the UI naturally — navigating Back closes a route-based modal without extra state management.

### 3.3 Refresh and Direct Navigation

Opening a modal URL directly (or refreshing) has no prior page in navigation history. The app renders the **full page** instead of the modal overlay.

Same URL, different UI depending on **how the user arrived** — the core value of intercepting routes.

### 3.4 Example: Product Quick-View Modal

A product list at `/products`. Clicking a product opens `/products/123` as a modal overlay. Opening `/products/123` directly shows the full product page.

**Folder structure:**

```text
app/
├── layout.tsx
├── @modal/
│   ├── default.tsx
│   └── (.)products/[id]/page.tsx    ← intercepting route (modal)
└── products/
    ├── page.tsx                     → /products
    └── [id]/page.tsx                → /products/123 (full page)
```

**`layout.tsx`** — renders page content and modal slot:

```tsx
export default function RootLayout({
  children,
  modal,
}: {
  children: React.ReactNode;
  modal: React.ReactNode;
}) {
  return (
    <html>
      <body>
        {children}
        {modal}
      </body>
    </html>
  );
}
```

**`@modal/default.tsx`** — nothing shown when modal is closed:

```tsx
export default function Default() {
  return null;
}
```

**`products/page.tsx`** — list with links (client navigation triggers intercept):

```tsx
import Link from "next/link";

export default function ProductsPage() {
  return (
    <ul>
      <li><Link href="/products/123">Product 123</Link></li>
    </ul>
  );
}
```

**`@modal/(.)products/[id]/page.tsx`** — modal overlay (shown on client navigation):

```tsx
import Link from "next/link";

export default function ProductModal({ params }: { params: { id: string } }) {
  return (
    <div className="modal-overlay">
      <div className="modal">
        <h2>Product {params.id}</h2>
        <Link href="/products">Close</Link>
      </div>
    </div>
  );
}
```

**`products/[id]/page.tsx`** — full page (shown on direct URL / refresh):

```tsx
export default function ProductPage({ params }: { params: { id: string } }) {
  return <h1>Product {params.id} — Full Page</h1>;
}
```

**Behavior:**

```text
/products → click Product 123 → /products/123 → modal overlay (intercepted)
/products/123 (direct URL or refresh)          → full product page
Back button from modal                          → /products (modal closes)
```

## 4. Common Mistakes

### 4.1 Using Parallel Routes for Normal Components

Do not create `@header`, `@sidebar`, or `@button` for ordinary UI components. Parallel Routes are for **independently routed** segments.

### 4.2 Confusing `@folder` with URL Segments

`@analytics` creates a slot, not `/analytics`.

### 4.3 Confusing Route Groups with Routes

`(auth)` organizes routes — it does not create `/auth`.

### 4.4 Using Intercepting Routes Too Early

Intercepting routes change behavior based on **how the user navigated**. Understand layouts, dynamic routes, route groups, and parallel routes first.

### 4.5 Building Modals Only with React State

`useState` is fine for simple temporary UI. Use route-based modals when navigation state matters.

### 4.6 Making Every Page a Separate Layout

Layouts represent shared UI boundaries. Avoid unnecessary layout layers.

---

**Key takeaways:**

> **Parallel Routes** render multiple route slots simultaneously inside one layout.

> **Intercepting Routes** show a route as an overlay during client navigation.

> **Modal Routing** combines both for URL-driven modals with back-button and deep-link support.

> **Pages Router** does not provide Parallel Routes or Intercepting Routes.

Use advanced routing only when routing is part of the UI requirement. For ordinary composition, use normal React components.
