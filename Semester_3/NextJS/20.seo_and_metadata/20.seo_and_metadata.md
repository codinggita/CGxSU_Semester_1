# 20. SEO & Metadata

Next.js Metadata API, `generateMetadata`, Open Graph/Twitter, canonical URLs, `sitemap.ts`, `robots.ts`, and JSON-LD. Examples use the **App Router**; Pages Router patterns are in **Pages Router vs App Router**.

---

## 1. SEO in Next.js

In a CRA/MERN SPA, crawlers often receive an empty HTML shell. Next.js renders on the server so the initial response can include content, metadata, and structured data.

> **Server rendering alone does not make a site SEO-friendly** — you still need metadata, canonical URLs, sitemaps, and server-fetched content on public pages.

| Page type | SEO concern | Typical approach |
| --------- | ----------- | ---------------- |
| Product, blog, marketing | High | Server render + `generateMetadata` + sitemap |
| Dashboard, admin | Low | Client fetch OK; block in `robots.ts` |

---

## 2. Metadata API

In the App Router, export `metadata` (static) or `generateMetadata` (dynamic) from a Server Component, layout, or page. Metadata is **server-only** — never export it from `"use client"` components.

### 2.1 Static Metadata

```tsx
import type { Metadata } from "next";

export const metadata: Metadata = {
  title: "Products",
  description: "Browse our latest products.",
};

export default function ProductsPage() {
  return (
    <main>
      <h1>Products</h1>
    </main>
  );
}
```

### 2.2 Metadata in Layouts & Inheritance

Define shared metadata in a layout; child routes override or extend it.

```tsx
// app/layout.tsx
export const metadata: Metadata = {
  title: {
    default: "Example Store",
    template: "%s | Example Store",
  },
  description: "Online store for technology products.",
};
```

```tsx
// app/products/page.tsx
export const metadata: Metadata = {
  title: "Products", // → "Products | Example Store"
};
```

### 2.3 Dynamic Metadata

Use `generateMetadata` when metadata depends on route data:

```tsx
import type { Metadata } from "next";

type Props = { params: Promise<{ id: string }> };

export async function generateMetadata({ params }: Props): Promise<Metadata> {
  const { id } = await params;
  const product = await getProduct(id); // or fetch from your Node.js API

  return {
    title: product.name,
    description: product.description,
  };
}

export default async function ProductPage({ params }: Props) {
  const { id } = await params;
  const product = await getProduct(id);
  return <main><h1>{product.name}</h1></main>;
}
```

> Metadata generation runs on the server — including fetches to a separate backend.

### 2.4 Metadata and Client Components

Keep metadata on the Server Component page/layout; import Client Components for interactivity:

```tsx
import type { Metadata } from "next";
import ProductFilters from "./ProductFilters"; // "use client"

export const metadata: Metadata = { title: "Products" };

export default function ProductsPage() {
  return (
    <main>
      <h1>Products</h1>
      <ProductFilters />
    </main>
  );
}
```

## 3. Open Graph & Twitter

Set social preview metadata via the same `metadata` / `generateMetadata` export. Configure **both** `openGraph` and `twitter` — they are separate systems but use the same API surface.

### 3.1 Static

```tsx
export const metadata: Metadata = {
  title: "MacBook Pro",
  description: "Powerful laptop for professionals.",
  openGraph: {
    title: "MacBook Pro",
    description: "Powerful laptop for professionals.",
    url: "https://example.com/products/macbook-pro",
    siteName: "Example Store",
    images: [{ url: "https://example.com/images/macbook-pro.jpg", width: 1200, height: 630, alt: "MacBook Pro" }],
    type: "website",
  },
  twitter: {
    card: "summary_large_image",
    title: "MacBook Pro",
    description: "Powerful laptop for professionals.",
    images: ["https://example.com/macbook-pro.jpg"],
  },
};
```

### 3.2 Dynamic

```tsx
export async function generateMetadata({ params }: Props): Promise<Metadata> {
  const { id } = await params;
  const product = await getProduct(id);

  return {
    title: product.name,
    description: product.description,
    openGraph: {
      title: product.name,
      description: product.description,
      images: [{ url: product.image, width: 1200, height: 630, alt: product.name }],
    },
    twitter: {
      card: "summary_large_image",
      title: product.name,
      description: product.description,
      images: [product.image],
    },
  };
}
```

## 4. Canonical URLs

When the same page is reachable via multiple URLs (`?utm_source=`, `?sort=`, etc.), set a canonical URL:

```tsx
export const metadata: Metadata = {
  alternates: { canonical: "https://example.com/products/123" },
};
```

Dynamic:

```tsx
export async function generateMetadata({ params }: Props): Promise<Metadata> {
  const { id } = await params;
  return {
    alternates: { canonical: `https://example.com/products/${id}` },
  };
}
```

## 5. Sitemap

Create `app/sitemap.ts`:

```tsx
import type { MetadataRoute } from "next";

export default function sitemap(): MetadataRoute.Sitemap {
  return [
    { url: "https://example.com", lastModified: new Date() },
    { url: "https://example.com/products", lastModified: new Date() },
  ];
}
```

Dynamic (database-driven):

```tsx
export default async function sitemap(): Promise<MetadataRoute.Sitemap> {
  const products = await getProducts();
  return [
    { url: "https://example.com", lastModified: new Date() },
    ...products.map((p) => ({
      url: `https://example.com/products/${p.id}`,
      lastModified: p.updatedAt,
    })),
  ];
}
```

For very large sites, split into multiple sitemap files (`/sitemap-products.xml`, etc.).

## 6. Robots

Create `app/robots.ts`:

```tsx
import type { MetadataRoute } from "next";

export default function robots(): MetadataRoute.Robots {
  return {
    rules: {
      userAgent: "*",
      allow: "/",
      disallow: ["/admin/", "/dashboard/"],
    },
    sitemap: "https://example.com/sitemap.xml",
  };
}
```

| File | Purpose |
| ---- | ------- |
| `sitemap.ts` | Tell crawlers which URLs exist |
| `robots.ts` | Tell crawlers what to crawl or skip |

### 6.1 Important: `robots.txt` Is Not Security

`Disallow: /admin` is a **crawler hint**, not access control. Protect admin routes with authentication and authorization — not `robots.ts`.

## 7. Semantic HTML

Use semantic HTML — `<main>`, `<article>`, `<h1>`–`<h3>`, and `<Link>` for navigation. Style heading size with CSS, not by picking the wrong heading level.

## 8. Structured Data (JSON-LD)

Render Schema.org JSON-LD in a `<script type="application/ld+json">` tag. Data must match visible page content.

```tsx
export default async function ProductPage({ params }: Props) {
  const { id } = await params;
  const product = await getProduct(id);

  const productSchema = {
    "@context": "https://schema.org",
    "@type": "Product",
    name: product.name,
    description: product.description,
    image: product.image,
    offers: {
      "@type": "Offer",
      price: product.price,
      priceCurrency: "USD",
      availability: "https://schema.org/InStock",
    },
  };

  return (
    <main>
      <h1>{product.name}</h1>
      <script
        type="application/ld+json"
        dangerouslySetInnerHTML={{ __html: JSON.stringify(productSchema) }}
      />
    </main>
  );
}
```

## 9. Architecture Notes

**Separate Node.js backend:** SEO lives in Next.js (HTML, metadata, sitemap, robots, JSON-LD). Your Express API handles business logic and data — `generateMetadata` fetches from it server-side.

**Public vs private pages:**

| Public (SEO-sensitive) | Private (SEO not a priority) |
| ---------------------- | ---------------------------- |
| Home, products, blog, pricing | Dashboard, account, admin |
| Server render + metadata + sitemap | Client fetch OK; auth required |

**Client-side fetch and SEO:** A `"use client"` page that loads content via `useEffect` sends empty HTML to crawlers. For indexable pages, fetch on the server in the page or `generateMetadata`.

## 10. Pages Router vs App Router

| Feature | App Router | Pages Router |
| ------- | ---------- | ------------ |
| Static Metadata | `metadata` | `next/head` |
| Dynamic Metadata | `generateMetadata` | `next/head` + page data |
| Open Graph / Twitter | Metadata API | `next/head` |
| Canonical | `alternates.canonical` | `<link rel="canonical">` in `next/head` |
| Sitemap | `sitemap.ts` | Custom / static |
| robots.txt | `robots.ts` | Static / custom |

Pages Router example:

```tsx
import Head from "next/head";

export default function ProductsPage() {
  return (
    <>
      <Head>
        <title>Products | Example Store</title>
        <meta name="description" content="Browse our latest products." />
        <link rel="canonical" href="https://example.com/products" />
      </Head>
      <main><h1>Products</h1></main>
    </>
  );
}
```

## 11. Complete Product Page Example

```tsx
import type { Metadata } from "next";

type Props = { params: Promise<{ id: string }> };

async function getProduct(id: string) {
  const res = await fetch(`https://api.example.com/products/${id}`);
  if (!res.ok) throw new Error("Failed to fetch product");
  return res.json();
}

export async function generateMetadata({ params }: Props): Promise<Metadata> {
  const { id } = await params;
  const product = await getProduct(id);

  return {
    title: `${product.name} | Example Store`,
    description: product.description,
    alternates: { canonical: `https://example.com/products/${id}` },
    openGraph: {
      title: product.name,
      description: product.description,
      images: [{ url: product.image, width: 1200, height: 630, alt: product.name }],
    },
    twitter: {
      card: "summary_large_image",
      title: product.name,
      description: product.description,
      images: [product.image],
    },
  };
}

export default async function ProductPage({ params }: Props) {
  const { id } = await params;
  const product = await getProduct(id);

  const productSchema = {
    "@context": "https://schema.org",
    "@type": "Product",
    name: product.name,
    description: product.description,
    image: product.image,
    offers: {
      "@type": "Offer",
      price: product.price,
      priceCurrency: "USD",
      availability: "https://schema.org/InStock",
    },
  };

  return (
    <main>
      <article>
        <header><h1>{product.name}</h1></header>
        <img src={product.image} alt={product.name} />
        <p>{product.description}</p>
        <p>${product.price}</p>
      </article>
      <script
        type="application/ld+json"
        dangerouslySetInnerHTML={{ __html: JSON.stringify(productSchema) }}
      />
    </main>
  );
}
```

## 12. SEO Checklist

```text
□ Meaningful URL
□ Unique <title> and meta description per page
□ Canonical URL (especially with query params)
□ Open Graph + Twitter metadata
□ Semantic HTML + heading hierarchy
□ JSON-LD where appropriate (accurate to page content)
□ URL in sitemap.ts
□ Not blocked by robots.ts
□ Server-rendered content on public pages
```

---

## 13. Common SEO Mistakes

### 13.1 Same Title on Every Page

Use title templates or per-page titles — not `"Example Store"` everywhere.

### 13.2 Duplicate URLs Without Canonical

Watch for `?sort=`, `?filter=`, `?utm_source=` creating duplicate indexable URLs.

### 13.3 Client-Only Fetch on Public Pages

Do not load SEO-critical content only via `useEffect` when it should be in the initial HTML.

### 13.4 Using `robots.txt` as Security

Never. Use authentication and authorization.

### 13.5 Fake Structured Data

Only mark up content that actually exists on the page.

## 14. Mental Model

```text
Static data  →  metadata
Dynamic data →  generateMetadata()
Social       →  openGraph / twitter
Preferred URL→  alternates.canonical
Discovery    →  sitemap.ts
Crawl rules  →  robots.ts
Rich results →  JSON-LD in page
```

> **App Router:** Metadata API + file conventions. **Pages Router:** `next/head`.

Use advanced SEO tooling on **public, indexable pages**. Dashboards and authenticated routes need auth — not sitemap entries.
