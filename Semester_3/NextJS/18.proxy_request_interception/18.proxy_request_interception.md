# 22. Proxy & Request Interception

Next.js Proxy allows you to inspect incoming requests and apply request-level logic before the request reaches its destination. It can continue the request, redirect, rewrite, or apply lightweight routing rules.

In modern Next.js, the file convention is `proxy.ts`. Older Next.js versions use `middleware.ts` for a similar purpose. Use the convention supported by your installed version.

## 1. What Is Proxy?

Proxy runs before the requested page or Route Handler and can inspect details such as the URL, headers, and cookies.

```text
Browser
   ↓
Incoming Request
   ↓
proxy.ts
   ↓
Page / Route Handler
   ↓
Response
```

Proxy can decide whether a request should:

- Continue normally
- Redirect to another URL
- Rewrite to a different internal destination

## 2. Why Use Proxy?

Proxy is useful when a request-level rule needs to apply to multiple routes without repeating the same logic in each page.

Common use cases include:

- Redirecting unauthenticated visitors from protected sections
- Redirecting logged-in users away from the login page
- Request-dependent redirects or rewrites
- Inspecting cookies, headers, or URL information
- Locale-based routing

For fixed redirects that do not depend on the incoming request, use `next.config.ts` redirects instead of Proxy.

## 3. Proxy vs Route Handler

These serve different purposes.

| Proxy                                           | Route Handler                                                    |
| ----------------------------------------------- | ---------------------------------------------------------------- |
| Runs before the request reaches its destination | Handles the request and returns a response                       |
| Inspects or changes request routing             | Implements API behavior                                          |
| Can continue, redirect, or rewrite              | Reads data, performs operations, returns JSON or other responses |
| Not a replacement for API endpoints             | Defines HTTP endpoints such as `GET`, `POST`, `DELETE`           |

Example request flow:

```text
GET /api/products
        ↓
      Proxy
        ↓
 Route Handler
        ↓
  JSON Response
```

## 4. Redirect vs Rewrite

Both can route a request to another destination, but their browser behavior differs.

### Redirect

A redirect tells the browser to navigate to a different URL. The browser's address bar changes.

```tsx
import { NextResponse } from "next/server";

export function proxy(request) {
	if (request.nextUrl.pathname === "/old-products") {
		return NextResponse.redirect(new URL("/products", request.url));
	}

	return NextResponse.next();
}
```

Visiting `/old-products` sends the browser to `/products`.

### Rewrite

A rewrite internally maps the request to another destination while keeping the URL shown in the browser unchanged.

```tsx
import { NextResponse } from "next/server";

export function proxy(request) {
	if (request.nextUrl.pathname === "/catalog") {
		return NextResponse.rewrite(new URL("/products", request.url));
	}

	return NextResponse.next();
}
```

Visiting `/catalog` serves the content from `/products`, but the browser continues to show `/catalog`.

| Redirect                                   | Rewrite                                          |
| ------------------------------------------ | ------------------------------------------------ |
| Browser navigates to a new URL             | Internal destination is changed                  |
| Address bar URL changes                    | Address bar URL stays the same                   |
| Browser makes a new request to destination | Next.js internally serves the mapped destination |

## 5. Creating `proxy.ts`

Create `proxy.ts` at the project root, alongside the `app` directory. If your project uses a `src` directory, place it according to that project structure.

```text
my-next-app/
├── app/
│   ├── page.tsx
│   └── products/
│       └── page.tsx
├── proxy.ts
├── next.config.ts
└── package.json
```

A basic Proxy:

```tsx
import { NextResponse } from "next/server";

export function proxy() {
	return NextResponse.next();
}
```

`NextResponse.next()` allows the request to continue to its intended destination.

## 6. Simple Authentication-Related Redirect

For example, suppose your application stores a session cookie after login. Proxy can check whether a cookie is present and redirect visitors from `/dashboard` to `/login` when it is missing.

```tsx
import { NextRequest, NextResponse } from "next/server";

export function proxy(request: NextRequest) {
	const session = request.cookies.get("session");

	if (request.nextUrl.pathname.startsWith("/dashboard") && !session) {
		return NextResponse.redirect(new URL("/login", request.url));
	}

	return NextResponse.next();
}
```

This example checks only whether a cookie exists. It does **not** validate that the session is genuine, unexpired, or belongs to an authorized user.

Proxy can provide a convenient routing check, but protected pages, Route Handlers, and Server Actions must perform their own authentication and authorization checks where sensitive operations are performed. Do not rely on Proxy as the only security layer.

## 7. Matcher

Proxy can be limited to specific paths using `matcher`. This prevents it from running on routes that do not need request-level logic.

```tsx
export const config = {
	matcher: ["/dashboard/:path*", "/admin/:path*"],
};
```

With this matcher, Proxy runs for dashboard and admin paths, including their nested routes.

A matcher can be used to target specific routes instead of applying Proxy across the entire application.

## 8. Keep Proxy Lightweight

Proxy should handle request-level decisions, not application business logic.

| Appropriate in Proxy               | Not appropriate in Proxy                          |
| ---------------------------------- | ------------------------------------------------- |
| Redirects                          | Payment processing                                |
| Rewrites                           | Complex business rules                            |
| Lightweight request checks         | Database workflows                                |
| Inspecting request headers/cookies | Large data transformations                        |
| Route-level access filtering       | Replacing authorization in APIs or Server Actions |

Keep business logic in the application's service layer and data access in the appropriate database layer.

## Key Takeaways

- `proxy.ts` is a request interception entry point in modern Next.js.
- Older Next.js versions used the `middleware.ts` convention.
- Proxy runs before the request reaches the page or Route Handler.
- `NextResponse.next()` continues the request.
- `NextResponse.redirect()` navigates the browser to a new URL.
- `NextResponse.rewrite()` maps to another internal destination while preserving the browser URL.
- Use `matcher` to limit the routes Proxy handles.
- Proxy is not a replacement for Route Handlers, Server Actions, business logic, or proper authentication and authorization.
